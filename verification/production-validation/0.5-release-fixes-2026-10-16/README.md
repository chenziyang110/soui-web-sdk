# 0.5 发布修复的实际验证

两架构各 19 项 UIA 回归、NVDA 文本观察和原生表单/键盘流程通过；新回归也在原安装库上复现拒绝。实际进程与监督器均自然退出，Job 清空。填写、选择各提交一次；Windows 额外请求的焦点另计。秘密字段隐藏、删除后的调用拒绝、授权、重入、队列上限和关闭保护分别验证。

测试以已安装 Source28 SDK 加上精确 provider 源码覆盖构建，最终公开构建与交付包仍须验收。源代码、消费者、原始输出和逐文件散列保存在本目录；没有将覆盖构建冒充正式发布包。

保留焦点原错、只修焦点后的填写失败、UIAutomationCore 撤销返回值差异、一次键盘字符不符和 NVDA 配置缩进改写导致的失败。最后一项配置逐行去除缩进后完全相同，最终实际运行使用 NVDA 自己的规范缩进，输入/输出散列一致。字符不符的原因未确定，后续相同操作成功不将该次失败改为通过。

读屏证据为 NVDA 的 Speaking 文本日志，合成器设置 silence；没有音频或人工听觉验证。键盘采用实际 SendInput，不能代替物理输入资格。高刷能力遵照维护者要求，不等待额外设备；物理高刷仍未实测。

x64 有限资源运行的 114 个采样均完整且在事先确定的 1 GiB 观察预算内；不是八小时资格。为避免在即将替换的源码上重复长流程，x86 有限运行安排在整合后的候选上，并在八小时运行前完成。

12 个当前 Web 工程实际 npm audit 均为零告警，锁文件未改变。打包、中文清单、长路径和依赖原始脚本归档的既有针对性验证索引一并保存；最终统一入口仍单独验证。生产结论保持 releaseReady=false。
