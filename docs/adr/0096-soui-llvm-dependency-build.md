# ADR 0096：SOUI 依赖构建的 LLVM 档位

状态：已实现并完成组件重建与独立消费者回归；完整 SDK 候选验收进行中。

## 背景

实际 MSVC143 SOUI 重建生成了五个 DLL，源码未变且根进程返回 0，但原
两秒收尾预算结束时仍有 mspdbsrv 与 vctip。整个自有进程组失败（监督器
124），不能由编译成功推导依赖验收成功。SDK 和 Miniblink 已有显式
LLVM22/MSVC142 档位，SOUI 公共重建入口尚不支持此档位。

外部隔离 LLVM 诊断已完成 utilities 编译，在 NotifyCenter 发现 C++ 模板
静态成员的特化定义晚于实例化。该错误是源码兼容问题，不能通过删除编译
错误检查或冒充其他编译器解决。

## 决定

- 保留默认 MSVC143 入口及原失败证据，扩展显式 LLVM 档位的依赖重建。
- 使用独立 `tools/Build-SouiLlvm.ps1` 入口显式选择该档位；现有 Miniblink
  入口和正在运行的捕获输入保持稳定。两组件以各自真实构建记录汇总。
- 固定编译器、链接器、MSVC/ATL 与 SDK 输入；只在全新隔离源码目录构建，
  保留原源树。产物、真实调用、源文件与整个进程组收尾分别验证。
- 在单件类型首次可能实例化前声明已有五项静态成员特化，继续使用原
  cpp 中的唯一存储定义，不改变单件数据布局、导出或运行行为。
  实际 PE 比对发现仅前置声明会使 SApplication、SNotifyCenter 的原有
  数据符号不再自动导出；这两项声明显式保留 SOUI_EXP，消费者继续导入
  同一符号。其余三个原本未导出的存储不扩大可见性。
  MSVC 实测对此显式属性报 C2370；前置特化声明仅用于 Clang。MSVC 沿用
  原有的类实例化及自动导出规则，两种编译器分别验证消费者与原有导出。
- ActiveX 的两项 COM 查询改为直接初始化，避免复制初始化中的两次隐式
  用户转换；仍调用原 QueryInterface 构造函数，借用与引用计数不变。
- 对象工厂的局部临时对象改为具名局部变量，再传递给已有非常量引用
  接口；注册函数仍克隆工厂，局部对象在函数返回时销毁，接口不变。
- 布局尺寸格式化显式向变参接口传入字符串指针，避免把非平凡字符串
  对象传入 `%s`；不关闭编译器的运行时中止诊断。
- 树控件命中测试使用原坐标的具名副本，满足可变引用接口并保留后续
  事件处理使用的原坐标；不改变命中测试算法。
- 图像尺寸在转换为有符号 GDI 坐标前拒绝零或超出 LONG 范围的值，再
  明确转换；不以关闭窄化检查代替边界验证。
- 保存可重放的第三方补丁与来源。两个架构必须实际重编、检查导出/依赖
  并在真实应用中验证；仅外部诊断不能标记公共入口或发布已完成。

## 替代方案与迁移

不延长收尾期限、不结束构建工具后宣称自然完成，也不依赖用户机器上的
其他版本预编译 DLL。默认档位不静默改变；使用 LLVM 须显式指定固定输入。
发布收集仍须区分各组件的实际构建记录，不能伪造一个未执行的 All 记录。

LLVM 的依赖验收显式选择两份组件构建报告及各自的 Owned 捕获，不从目录
修改时间猜测输入。读取器重验原始进程记录、实际入口参数、工具与源码
快照、产物散列和 PE 架构。先要求当前已接受的 SDK 应用载荷使用这六个
重建 DLL，再在原桌面租约内执行现有三个 45 秒 smoke 场景；复用现有
监督器和关闭断言。汇总工具读取该选择记录并重新验证，保留 MSVC 原入口。
该证据是组件来源与实际运行验证，不冒充独立的工具链或生产资格审核。

内核的两个 V8 静态库分别超过 512 MiB。文件散列以固定 1 MiB 缓冲完整
读取，并检查同一文件句柄及路径的大小、身份和时间戳在读取前后一致；
不得截断内容或将大型静态库排除。JSON 与原始进程日志继续使用各自的
解析大小上限，避免将二进制散列的读取方式扩散到结构化输入解析。

## 验证

先保留现有 MSVC 收尾失败及 LLVM 编译错误。验证修正后的两种编译器、两
架构行为，公共参数边界、完整原生调用和 DLL 运行。当前验收仍在进行。

公共入口已在 x86/x64 分别完成五个库的真实编译链接，源码保持一致，根
进程和监督器均返回 0，整个自有进程组自然清空。原有导出全部保留；真实
消费者验证两个数据导入、尺寸格式化及工厂对象释放。MSVC 两架构也完成
编译且生成库通过消费者测试，但其编译服务收尾失败仍保留，未追认为自然
关闭。详见[组件证据](../../verification/production-validation/0.5-soui-rebuild-2026-10-15/README.md)。

已导入两架构五个运行库及原交付的两个导入库，完整 SDK 重建、桌面、长期
负载、目标系统和二进制授权门槛另行验证；该局部记录不关闭发布验收。
