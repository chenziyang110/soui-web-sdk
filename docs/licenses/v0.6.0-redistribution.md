## 对应源码与重建

本次默认MiniBlink内核须从本次完整源码树重新构建，替换旧默认预编译内核；最终二进制与源码身份以本次发布的实际散列和构建记录为准。与二进制在同一发布下载位置提供完整源码归档及校验清单；紧凑source SDK是开发子集，不能替代完整MiniBlink对应源码。完整归档保留 `third_party/sources/miniblink/` 的库源码、接口、生成源码、项目文件、原许可、`LOCAL-CHANGES.patch`，以及 `third_party/patches/miniblink/`、`tools/` 和 `cmake/` 中的修改与编译/安装脚本。

对应源码采用随附/同址下载方式（LGPL 2.1 §4、§6(a)/(d)）；本说明不另行创建三年书面offer。静态纳入DLL的库需可重建/重链接，不能只凭“DLL是共享库”声称满足全部义务。公开源还包括SDK及所附消费者/模板源码。使用[构建入口](../../tools/Build-Dependencies.ps1)的 `-Component Miniblink -NativeToolchain LLVM22MSVC142`，选择x86或x64及新的外部输出目录，并显式提供自己安装的工具路径。该入口重建静态依赖及主DLL；配置要求LLVM 22.1.3、MSVC 14.29.30133兼容、Windows SDK 10.0.19041.0、Release和GPU关闭。完整profile/平台资格仍按实际记录声明，不承诺不同环境产生逐字节相同的DLL。

DevTools消费者固定内核和前端身份，直接替换已固定的DLL会被拒绝。修改库后，按[公开配对流程](../devtools.md)合成/准备自己的组件、选择自己的可信kernel/frontend/approval pin，并重新编译原生消费者。这保留安全校验及每次原生授权要求，同时提供修改后重建/重链接的源码路径；技术配对文档不是第三方法律批准。

本次候选已将旧复制目录 `third_party/sources/miniblink/vc6/` 和 `third_party/sources/miniblink/third_party/GDIPlus/` 移出公开源码工作树。它们包含Microsoft版权的旧SDK/CRT头，不能由MiniBlink根许可证重新授权。新构建改用用户自行安装的Windows SDK 10.0.19041.0系统头与GDIPlus系统库，不把安装目录中的头、编译器或Windows系统文件复制进公开源码。目录移除和include选择本身不是新构建成功证据；本次构建记录须记录实际所用SDK输入。旧来源和历史清单继续作为历史保存，不据此扩大再分发授权。
