# ADR 0115：显式保留依赖构建时的原始脚本输入

状态：实施中；两架构原组件配对已验证，最终公开入口另验。

## 背景

安装包统一 LF 后，两份身份脚本的当前字节与早先 SOUI 构建记录的 CRLF 输入不同。
原编译器、组件源码和 DLL 没有变化，但只读取原路径的验证无法再消费该构建记录。

## 决定

v1/v2 选择器保持原行为。v3 在每个组件中显式添加 inputArchive：绝对 JSON 路径或 null。
PowerShell 入口增加 KernelInputArchive、SouiInputArchive；只在显式指定时构造 v3。
归档格式为 `soui.dependency-input-archive/v1`，包含 producerRoot 和 files。
每项包含 original（原绝对 path、bytes、sha256）及 file（归档目录内的相对文件路径）。

只接受原 producerRoot/tools 下已被原输入固定的脚本/配置。拒绝未知、重复、路径逃逸、重解析链接及编译器/SDK 工具输入替换。
归档字节必须符合原始长度和 SHA-256，不执行规范化。结果固定归档清单和文件身份，复读时完整重新验证。
完整源码、原入口命令、原进程退出、编译工具与 SDK 输入、六个 DLL 及应用载荷保持严格校验。
原报告不变，归档不是重新编译或运行的证明。两份历史脚本可由 LF 展开为 CRLF 后恢复；
只有所得字节与已有 SHA-256 完全一致才可留存，恢复记录必须说明操作。

## 备选方案、兼容性与验证

不改写历史散列，不临时改回交付脚本，也不因脚本迁移替换已验证 DLL。
省略归档时仍要求所有原物理输入相同；v1/v2 无需迁移。
回归覆盖字段、来源、工具替换、字节变动、重复和逃逸；两架构实际组件配对包含原编译及进程记录。
最终发布仍需当前公共入口的真实桌面验证。
