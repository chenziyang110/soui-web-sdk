# ADR-0019：现代后端的控制请求容量隔离

- 日期：2026-10-08
- 状态：实施；0.5 首批可靠性切片，真实长会话验收待执行
- 范围：可选 WebView2 适配器与其本地 preload；不修改公共 Bridge 消息格式、业务授权或默认后端

## 背景

现代后端的页面等待表、原生请求表与回送队列均共享 128 个槽。即使 Web SDK 已独立接纳续期/清理请求，满载业务仍会在下层拒绝这些请求；仅扩请求队列不能解决回送被业务响应或事件占满的问题。

## 决定

1. 页面与原生分别保留 128 个普通槽、128 个清理槽和 1 个续期槽。清理仅包括 `task.cancel` 与 `task.unsubscribe`；续期仅包括 `bridge.session.renew`。清理容量沿用公共客户端的默认订阅上限。总量有限，不扩大普通业务容量。
2. 两端均从实际方法、凭据字段与单字段参数形态分类。续期要求合法有界 `operationId`；清理要求有界 `taskId` 或 `subscriptionId`。未知、畸形或只有网页自报 `control`/`priority` 的消息属于普通通道。原生从自己解析的 JSON 重新分类，绝不采信页面传递的类别。分类只决定调度；实际会话、令牌、能力、资源归属和参数授权仍由 Bridge 在执行时独立校验。看起来合法但未授权的控制请求仍可能占用一个有界槽，不能因此执行未授权业务。
3. 原生请求槽通过私有 RAII 租约覆盖排队、执行和待回送阶段。重复 requestId 在同一文档代际跨通道拒绝。响应发送前、丢弃响应、清空队列和关闭都会释放；旧代际租约不能释放新代际槽。
4. 续期先于尚未执行的普通/清理请求。清理最多连续优先四项，然后给已经排队的普通请求一次机会。此策略同样用于回送；普通事件或拒绝回应不能占据控制回送槽。每个回送通道同时限制项数与字节，总上限为普通 8 MiB、清理 8 MiB、续期 64 KiB。拒绝回应和事件使用普通回送预算。
5. 导航先清空旧文档请求/回送，再设置原生会话撤销屏障；屏障必须在新文档请求之前执行。关闭清空所有租约；源 URL 和原生文档身份检查保持不变。页面 pagehide/beforeunload 清理全部计时器和等待，并拒绝之后的发送。同步 post 异常与超时分别释放对应页面槽。
6. 排队超时在原生调度时返回 `E_TIMEOUT`，不执行处理器。正在执行的处理器不可抢占，其租约直到处理器返回并完成/丢弃回送才释放；页面超时不等于任务取消或业务回滚。优先级不能抢占长模态操作或违反有界处理器契约的代码。

## 备选、兼容与迁移

拒绝只提高统一上限、只隔离页面等待表、允许页面声明优先级，或用第二条并行业务执行线程绕过既有串行会话/关闭顺序。采用私有策略和预算实现，不新增公共 ABI；普通请求上限、原生权限、可信资源策略和任务协作取消契约保持不变。控制请求总容量增加为有界的 129 项，需按本版重新记录载荷与构建身份。

## 验证

页面使用真实 preload 的隔离 VM 夹具验证：128 普通请求满载下续期/清理接纳、各通道超量与跨通道重复、伪造分类和畸形参数、完成/超时/同步发送异常释放、旧文档回应、导航/关闭拒绝与计时器清理。

无窗口 C++ 策略测试验证：独立分类与预算、满载/重复、租约回收、旧代际释放隔离、续期优先/清理公平性及独立回送字节预算。正式验证还需当前源码的 x86/x64 构建、真实 WebView2 满载、重载/关闭与超过 30 分钟、8 小时任务/订阅跨续期保留。VM、策略测试和短启动不能将这些长时或目标平台门槛标为通过。
