# ADR-0108：长期负载中的 TaskStore 请求字节限额

- 状态：实现已整合；独立解析与集成回归通过，最终候选的真实八小时验证待执行
- 日期：2026-10-16

## 问题

ADR 0101 已将 TaskStore 私有分配请求额度固定为 128 MiB。Acceptance App 无论采集哪种负载都会输出实际额度、pool epoch、当前和峰值请求字节、拒绝次数及原生调用身份。但原额度读取器只接受 reload 的单窗口顺序，无法核对八小时 mixed 的槽位复用和 session 的常驻 anchor。因此现有长期分析没有消费这条实际额度通道。

## 决定

保留原 reload binding/v1、32 MiB/8192 行上限和全部旧生命周期约束。独立的 long binding/1 使用冻结的 mixed/session 配置、128 MiB 额度及完整 source/payload/EXE/Owned/context/raw log 绑定。其原始日志仍必须是严格 UTF-8/LF，无重复 JSON 字段；256 MiB/1000000 行只是解析上限，与实际工作负载及内存预算无关。

同一窗口寿命保持原生 HWND、线程、频率、pool epoch 和诊断 owner epoch；下一次使用同一槽位必须是新 pool。每个存活样本与关闭后的 owner 样本都检查配置、峰值和退款关系；跨观察的累计峰值/拒绝次数不能倒退。QPC 不能重放或回退。窗口 roster、cycle 和原关闭样本必须完整，session anchor 不能被重新创建。busy、unavailable 和缺记录不当作零或通过；已知违反优先失败。

长期策略使用新修订 v3，将 `taskStoreQuota` 加入必需子门。分析保留逐点结果，capture 的一致性检查从保存的原解析记录重新计算，拒绝被改写的子结果或无数据的 passed 字段。历史 v2 策略字节及原始报告保持历史含义；不得拿旧报告冒充本修订的实际执行。

## 范围

本门只判断 TaskStore 私有分配请求额度。关闭样本采自 Host 关闭后、C++ owner 析构前，历史条目仍可按契约保留；不要求此时请求字节为零，也不宣称观察到了最终析构。公共拷贝、allocator 开销、外部借用以及 Blink/V8/Skia 的完整 heap 仍不在本额度范围。`cacheBudget` 继续独立，不能因本子门通过而变成绿色；原八小时真实时钟、资源趋势、任务续期、自然退出和全部其他子门不变。

## 验证

独立 proposal 的 28 项额度解析用例、71 项长期聚合用例、12 项缓存观察用例、43 项资源读取用例与原 reload 的 106 项回归已通过。新增 cycle 缺样、错 cycle 关闭及替换 EXE/Owned/context 绑定用例先复现误判，再修复并通过。额度绑定必须等于原始私有存储的完整输入绑定，原执行入口独立复验该绑定及完整解析记录，不能只依靠额度结果自己携带的散列。以上为纯数据/源码回归，不能代表实际 Native 或八小时运行；真实两种长负载须使用新策略重新执行。
