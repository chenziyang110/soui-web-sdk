# ADR 0105：发布验证的独立工具归属

状态：实施中；完整候选发布验证尚未完成。

## 背景

LLVM 候选的应用与 SDK 构建记录绑定了实际验证工具的目录、准备记录和文件散列。原发布入口固定在候选目录准备历史 MSVC 工具，再在另一个目录准备 LLVM 工具。这会覆盖此前候选使用的 LLVM 验证工具，使当前应用构建记录失效。汇总入口还遗漏了向安装/回退报告读取器传递已明确选择的编译档位，导致 LLVM 报告被按 MSVC 默认值读取。

## 决定

- `Verify-Release.ps1` 增加可选 `-LegacyDevkitRoot`，仅与显式 LLVM 档位共同使用。未指定时保留旧行为。
- 显式指定历史工具目录时使用 `soui.release-requested-profile/v2`。LLVM 和 MSVC 目录仍须物理独立；在任何工具构建前拒绝同一目录、链接路径、无效目录及不安全路径。
- 基线和回退阶段使用所选历史 MSVC 工具；新建、升级、再次升级和搬移阶段使用所选 LLVM 工具。候选目录可以继续持有其既有 LLVM 工具，旧版应用源码及工具链保持原有契约。
- 已有 v1 记录继续要求 MSVC 工具归属于原候选目录，不追认成 v2。实际编译、请求、工具准备、进程关闭和原始文件核验保持不变。
- 汇总将显式编译档位传入安装/回退报告读取器；不从结果推断或自动切换档位。

## 兼容性与验证

这是发布工具的可选参数扩展，不改变 SDK 的公共 C++/TypeScript API 或默认构建档位。新的工具目录必须实际准备并验证；目录选择本身不构成运行或发布通过。

回归覆盖六阶段路由、v1 兼容、同目录与链接别名拒绝、缺失/不安全输入，以及汇总调用的档位传递。还需用最终候选执行双架构完整的新建、升级、回退、搬移和安装消费者流程，保留所有失败原件。
