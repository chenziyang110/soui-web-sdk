# ADR 0143：生成应用的可见启动失败与便携诊断

## 背景

生成应用只把 initialize 失败写到 stderr 后退出。Finder/Explorer 双击可能没有可见反馈，
但无窗口不证明是某个特定 SDK/系统错误。临时脚本不是持久交付契约。

## 决定

只增强新生成项目，不增加 Desktop/Bridge 公共 API、不修改旧生成项目。
正常启动失败先输出去敏错误，再尝试平台原生错误框；成功路径不弹框。
运行中首个 error 回调立即输出去敏 stderr，避免等用户关闭窗口才有诊断；
只缓存首错避免洪泛，原生提示在事件循环退出且应用释放后进行。
显示服务或原生提示不可用时保留 stderr，不循环初始化应用、不强制修改系统策略。
原生提示是一次用户关闭的模态提示，不重新启动应用事件循环。

新增应用参数 `--diagnose`：不安装业务回调、不弹框、不打开业务窗口、不运行应用事件循环；
解析资源并以 visible=false 初始化 SDK，随后关闭并输出一条 JSON，失败非零。
它可能创建隐藏原生窗口、WebView 与临时 loopback listener，不是纯静态检查；
不执行业务 invoke、剪贴板、选择器或全局快捷键。成功仅表示有限初始化，
不代表页面完成加载、Bridge 可用或 nativeRuntimeVerified。
其他参数拒绝，不猜测用户意图。普通启动的诊断也不自动写文件或上传。

报告使用固定 schema、固定阶段与白名单错误 code，未知 code 归为 unclassified_error，
不输出任意 result.message。只有已知资源监听器固定消息格式允许提取有界原生数字错误，
不输出资源 URL、能力令牌、用户路径或异常 what()。格式化与原生展示分离，供无 GUI 测试。

## 平台与限制

Windows 使用 MessageBox，macOS 使用 AppKit NSAlert，Linux 使用 GTK；不新增第三方依赖。
本进程尚未加载（缺动态库、OS 拒绝执行等）时无法报告，继续使用交付目录的 doctor。
不能保证系统不允许 UI 时弹框成功，也不能把诊断增强描述成已修复 Finder 启动根因。
已安装 SDK 自动携带模板来源；应用需重新生成或显式迁移这些源文件/CMake 接线。

## 验证与替代

只做纯格式化边界、生成文件传播、可用平台语法与 fake 模板入口验证，不唤醒用户操作Mac。
原生提示实际显示仍需目标环境后续验收。相比默认保存完整日志或自动回退 file://，
本方案减少敏感信息持久化，不改变原资源协议、权限及同源边界。
