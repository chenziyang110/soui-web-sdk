# ADR 0063: bounded authorization scope owners

状态：实现已采纳，2026-10-10 常规四配置集成回归通过，实际边界见文末。此切片沿用已采纳的标量诊断与 Engine V2 诊断 POD，没有修改 Engine 准入或调度；长期资源、目标系统和正式发布仍待验收。

Each permission store admits at most 128 stored scope owners plus pending issuance reservations. Expired grants remain stored until explicit revoke or issuer destruction. A module-local budget permits at most 512 outstanding scope slots: pending reservations, live stored owners, and revoked or issuer-dead owners still retained by an external shared pointer. A slot is refunded only on reservation rollback or actual final scope-owner destruction. Revocation is admission invalidation, not proof of final external-owner death.

The module ledger contains only an atomic count and the fixed limit. The budget belongs to this linked SDK module instance; independently loaded SDK copies do not form a cross-module or cross-process quota. Scope slots hold a shared reference to that budget state, never a store, issuer, native binding, callback or authority. A borrowed scope cannot keep the issuer alive. Native local bindings retain the existing weak issuer identity and their irreversible close semantics.

Permission issuance reserves under the store mutex before its token entropy, scope correlation-ID allocation or grant construction. Existing caller envelope and local-policy validation remain before that boundary. The initial bearer consumes one pending alias credit. Store, initial alias and module credits are refunded on every exception. Scope and return-owner allocation occurs outside the store mutex; final insertion rechecks token collision. A throwing insertion refunds the reservations, while the following stored/pending count commit and return moves cannot throw. Concurrent pending reservations count against the same bound as committed grants.

Committed bearer aliases are bounded at 256 per store. A same-scope renewal may insert one new alias to a transient maximum of 257 before retiring the prior alias. It never acquires another scope slot. Authorization, binding/method checks, expiry, operation idempotence, early-renewal and generation errors precede capacity checks. Expiry remains E_SESSION_EXPIRED. No clock-driven sweep, TTL erase, grant recreation or automatic retry is introduced.

Native issue and issue_local signal capacity refusal through scope_capacity_error with code E_LIMIT_SCOPE_CAPACITY and a native enum identifying store, module or alias exhaustion. Renewal returns the same code in the existing permission_lease failure shape. json_bridge bootstrap catches only that typed exception and produces the existing error envelope. A local endpoint preserves its current failed-native-issuance close boundary; this slice adds no local wire grant or capacity protocol.

Revoke_scope, revoke_session and issuer destruction first invalidate actual scopes and remove aliases under the store mutex, then destroy extracted map nodes outside it. Fixed node holders require no cleanup allocation. All scope-state changes retain Store-to-Scope lock order. Ledger accounting is atomic and has no reverse lock or callback. A scope's budget lease is the last state member retired, after its actual owned fields. Store destruction still requires callers to stop accessing the store; this change is not a concurrent-destruction API.

Scalar permission diagnostics distinguish store stored/pending scope counts and reserved aliases from module-wide outstanding slots. Limits and rejection counts are native observations, not authority or heap totals. Module counts include other stores and pending construction. Default-disabled getters remain entirely zero, including limits and module data. Enabled getters use the existing try-lock/busy semantics and a non-atomic module count sampled during that store observation.

The public native exception, permission_store layout and diagnostics POD change require the SDK and consumers to be rebuilt together. No old binary ABI compatibility is claimed. Public action/wire authorization, generation, nativeAdmission and the default 30-minute lease/5-minute renewal window remain unchanged.

Planned normal-SDK tests exercise store128/129, module512/513 across stores, revoked/external-owner retention and final refund, issuer death without authority retention, twenty same-scope renewal rounds and alias bounds, real nth-allocation/entropy/collision rollback, pending concurrent admission and disabled-zero diagnostics. A held actual clock call makes 128 reservations observable before it throws; the test joins every thread and requires all three credits refunded. A second two-thread schedule makes both preparations pass the first collision check, then requires exactly one commit and one collision refund. They link one normal SDK and use existing native clock/entropy seams only; no copied SDK TU or business permission substitute. The original eleven metrics case IDs and Engine V2 queue-field assertions remain.

Normal-SDK compilation and 29 CTest cases passed on x86/x64 Debug/Release, including all ten Scope cases, with independent review of the [116-case finite integration](../../verification/production-validation/0.5-runtime-capacity-2026-10-10/README.md). The first Debug build failed with a CRT/iterator mismatch; its records are preserved and the three test directories now match the SDK's fixed /MD and /U_DEBUG convention. Final installed consumer, real eight-hour execution, memory trends, complete toolchain provenance, compatibility and release qualification remain pending/false. The bounds are production admission policy, not a performance acceptance result.
