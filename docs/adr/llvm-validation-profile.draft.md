# Explicit LLVM validation and installed consumer inputs

Status: source proposal. No part of this slice has been executed or adopted by this document.

The default `MSVC143` entry keeps its existing compiler, tests and evidence format. `LLVM22MSVC142` is an explicit request with six external inputs: `LlvmRoot`, `MsvcRoot`, `WindowsSdkRoot`, `NinjaExe`, `WindowsCmdExe` and `PowerShellExe`. The identity bridge and helper are fixed siblings inside the current source delivery; the caller cannot supply scripts. The requested profile pins LLVM 22.1.3, the MSVC 14.29.30133 headers and CRT, compatibility version 19.29.30159 and Windows SDK 10.0.19041.0. LLD's binary resource version is not treated as its LLVM package version.

Testing a normal LLVM build requires its current profile request and a naturally closed standard-build observation. A request, a successful configuration, or an internal `Build.ps1` report is insufficient. The original test body remains in place, including all 54 exact vendor registrations, private ABI comparison when vendor tests are ON, and the final real CTest invocation. The 27 required private sources are frozen from the actual central CMake contract and checked again before and after CTest. An absent private root remains the portable OFF boundary; an existing incomplete root is rejected.

The nine measurement targets use the same requested profile and actual target width. Their preparation has its own request file so it does not rewrite the normal Build request. The LLVM observation binds thirteen real CXX commands to unique Ninja edges, VALID dependency blocks, source and header bytes, target COFF machine and nine actual executable link commands. It does not reuse the SDK's TU or test counts. `prepared`, `compiledObjectsVerified`, and a matching executable hash do not claim compiler Job closure, ABI compatibility or an OS qualification. External supervision remains required. A non-fresh preparation can reuse only a fully current v2 report and its original real compile records. A no-op build's new empty verbose log cannot become compilation evidence. A stale existing directory must be prepared explicitly with `-FreshConfigure`, outside a controller that holds the Runner being replaced.

Desktop smoke forwards the selected request through the existing build and measurement readers. Its input and report bind that request's raw pin and the same input and bridge identities. Application ready/close and the original 45-second deadline and 2-second drain remain separate checks; profile selection does not grant a smoke result.

The Reference application retains MSVC as its default. LLVM opt-in requires an imported installed `Soui::Sdk`, the current SDK-only request and its accepted standard-build observation. The installed archive must match that actual produced archive; the public header membership and bytes must match the current SDK headers and ActionJson header. It compiles only the Reference's own TUs. The consumer's real Clang version, MSVC frontend, simulated version, target pointer width, product toolchain and input identity are checked independently. SDK proof does not claim that the consumer compiled or exited successfully.

Tool FILEPATH observations may use the existing explicit PowerShell bridge to prove a different spelling is the same physical file. It holds both files and compares bytes, volume and the 64-bit file identifier; a same-hash copy with a different identifier is rejected. This is the existing file-identity contract, not ReFS 128-bit support or an atomic directory-tree lock. There is no PATH fallback for a selected tool, no Node-based bridge, no private script input, no forced compiler-tail acceptance and no weakened resource gate.

Integration depends on the separately owned standard entry, Finder/toolchain and LLVM standard-build Observer slice. Those files must be reviewed and adopted together before real normal-entry validation. The new pure reader tests and both native architectures still require execution by the controlled root caller. Full kernel, Win7/PE, long-duration resource and release qualifications remain false or unmeasured.
