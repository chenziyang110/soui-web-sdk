## 诊断与修复

外部页面每批执行 10,000 个整数各 16 次 LCG、240 个 DOM transform、一次串行 C++ `app.greet`，返回后等待 `setTimeout(16)`。分段诊断（2 秒预热、10 秒计量）中，基线 timer 等待平均 17.46ms，原候选 24.68ms；Bridge 平均为 0.94/1.53ms。候选吞吐约为基线 70.7%，未通过预先记录的探索性 95% 对照检查。

生产路径从高精度 waitable timer 改为普通 threadpool timer 后，仅靠短期 `timeBeginPeriod` 不能保证不可见 Windows 11 场景的精度。修复优先复用高精度 waitable timer 与 threadpool wait，不恢复逐 deadline 注册/注销；原 pool/native fallback、ticket、owner 绝对时间复核与锁外关闭保留。

## 结论边界

已关闭本次隐藏桌面合成场景中约 31% 的吞吐回归。宿主使用平衡电源方案、有其他 VM 和多个显示适配器，非独占基准环境；没有直接观测 Windows 是否忽略该进程的计时精度请求，不将机制推断扩大为所有系统前台表现。
