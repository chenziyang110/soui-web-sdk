# Request-close regressions

Configure this directory independently or include it from the native test parent. `SOUI_DISTRIBUTION_ROOT` points to the source delivery root; when installed under `tests/native/request_close`, its default is derived from that location. This target needs Windows/MSVC and the Windows SDK, and has no SDK-core, Blink-library, Node or PowerShell dependency.

The original eleven tests compile the current broker entry, registry/callout, native queue/timer, drain, failure and typed resource ledger implementation directly from actual source byte ranges. CMake requires unique markers and LF-only, NUL-free fragments with a terminal LF; CRLF/mixed bytes and missing final LF are rejected explicitly. Dollar bytes are protected during generation. Every generated include must equal its configured actual source bytes before compilation; changed sources trigger reconfiguration. No handwritten replacement queue or fake Win32 getter is used.

A real message-only owner HWND and real HMENU establish the native ledger. Successful `DestroyMenu` precedes actual broker release. A real allocation failure at task admission leaves the menu held and actual drain false, so retry remains necessary. Subsequent queued/running or active-action calls must not readmit cleanup. Later calls after actual drain keep the original sequence and sticky status without readmission. Native admission fault is produced by the actual rejected hold path and remains a false-drain condition. Every test has a ten-second CTest timeout and bounded timer pumping.

This is a leaf regression, with opaque registry identity and engine/UI on one native thread. Wrong-thread rejection uses another actual thread. COM coverage is the actual bookkeeping API without a COM object; the admission-fault case discards only its local opaque fixture registration and claims no endpoint-destroy receipt. The callout-reentry case intentionally uses no queued timer and reports that fact. Complete SDK/DLL integration, distinct engine/UI concurrency, Win7/PE, full compiler-input closure, performance and release qualification require their separate acceptance evidence.

`ordinary-first-menu` 还直接编译真实的 `InspectorResourceSnapshot.cpp`，补齐 broker 片段依赖的私有资源状态和 owner retirement 接口。该实现不依赖 Blink 库；不以常量计数、空操作或假 retirement 替换资源 fence。原有 11 个注册名称、每项十秒 CTest 期限、两秒消息泵界限以及真实 HMENU、admission、取消、drain 断言保持不变。

该用例先通过真实 lookup 验证原始 callback owner，再分别保持 operation/callback、排队的 terminal continuation 和独立存活的 dispatcher，要求 pending retirement 返回 BUSY 且不改写 drain receipt。新增资源消息泵通过真实消息就绪等待，使用不重置的两秒绝对截止时间；原消息泵与整个用例十秒 CTest 总限不变。实际 owner release 必须发生在 broker 的计数 callout 内；release 重入实际 inspectDrain 时只能看到未排空的外层 fence。外层调用返回后才允许 drained receipt，原 owner 恰好释放和销毁一次；随后保留再释放 cache identity 不得重复释放 owner。此覆盖仅验证独立资源实现与真实 broker 片段之间的关闭契约，不代表完整 Blink、SDK/DLL、跨线程或发布验收通过。

preview.8 的 broker 控制块和真实 drain 现包含独立业务 `LocalResourceState`。该 target 直接编译当前 `content/web_impl_win/LocalResourceState.cpp` 并包含其真实头和 ABI；不使用测试宏、空状态替身或复制的 owner 算法，也不需要依赖 Blink 的 `LocalResourceAdmission.cpp`/`LocalResourceMemoryLoad.cpp`。原十三个片段及完整字节生成门未改。

新增 `native-local-owner-fence` 是第十二个、同样十秒的定向用例。真实 State 对 callback owner、内存正文、operation 和 callback borrow 计数；fixture 只实现原生 loader 的外部 task/provider 边界。原 broker requestClose 接纳关闭但不得释放仍在栈上的正文，inspectDrain 必须 BUSY 且不写 receipt。实际 callback 和正文借用退出后才允许在 broker 计数 callout 内释放原 owner；release 重入仍 BUSY，物理退休后 sticky FAILED 与原 closeSequence 保留，cache identity 不重复释放。该用例不创建 HMENU，不声称真实 Renderer、DLL、GC 或 SDK snapshot IO 实测，原十一项所有断言和期限保持。
