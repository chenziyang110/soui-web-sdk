# SOUI Web SDK 0.6.0

发布目标：`v0.6.0`，普通 GitHub Release。当前状态：源码与发布材料集成中，尚未发布；下列能力说明不作为本轮构建或运行通过记录。

完整生产验收保持 `releaseReady=false`、`productionQualificationComplete=false`。本次用户明确授权普通 Release 分类，并将低收益长测后置；该分类与工程资格分别记录，见 [ADR-0136](../adr/0136-0.6.0-release-scope.md)。

## 主要变化

- 公共 Host 纳入原生受控 DevTools：默认 disabled、不透明且绑定目标的 grant、异步操作编号、有限操作历史、撤销与真实退休。兼容/现代模板和 Workbench 提供可信原生接入起点。
- MiniBlink 使用匹配内核和离线 Inspector 供应输入；WebView2 使用 Runtime 自带前端。源码诊断与调试许可分别控制，发行档默认不携带业务 source map。
- 显式可选 AutoHost 在启动前选择 WebView2 或兼容 MiniBlink；配置、权限和业务失败不触发运行中的后端切换或操作重放。
- 整合有界输入接纳/恢复、调度、帧与资源通知及数值因果诊断的源码能力。可选 owner 输出策略、GPU 和配置资格继续单列，不声明统一性能收益。
- 显式 Web 目标、资源清单、运行时组件、部署恢复、去重 Bundle 与压缩档位进入同一源码交付。默认 ZIP、完整独立应用目录和业务文件所有权边界保留。
- 首方 MIT 材料与第三方声明继续随源码、CMake 安装及应用 legal 目录交付。历史归档和旧包按原字节保留。

## DevTools 使用边界

调试会查看源码和目标数据，并可通过 Console 使用页面现有业务能力。它不是只读模式，也不提供自动脱敏。原生端必须明确选择策略并签发 grant；默认 No 的确认、菜单和当前窗口快捷键共用同一处理链，网页/CLI/环境变量不能签发许可。

当前内置结束策略为 `destroy_target`：结束诊断会继续关闭当前业务 Host。保存未完成工作由应用负责；撤销先使旧 grant 和业务准入失效，随后在原总期限内推进真实清理。pending、超时、失败、资源已释放和正常完成是不同事实，不能相互替代。

MiniBlink 离线映射接受有界 inline map、相对 source 标签与明确的 `sourcesContent`；外置/在线 map 不作为该路径的加载来源，冲突内容不能替换既有已批准来源。这是实现合同，具体 Sources、断点和未发表观察仍须绑定实际版本。WebView2 的 attached/paused/visible 无可靠公开观察时保持 unknown，不外推 MiniBlink 的能力。

## 从 0.5 和本地 preview 迁移

使用新的整套 source SDK、匹配依赖和应用资源重新编译。公共 Host/adapter 布局与可选方法、结束策略和实际 Runtime 所有权有变化，不承诺跨版本二进制 ABI。不要只覆盖单个 DLL，也不要把新 frontend 与旧内核、旧批准文件或旧 SDK 锁混用。

安装前备份业务工程；安装器保留用户业务文件，受管文件有本地修改时拒绝猜测覆盖。SDK root 的 `VERSION`、`<soui/version.h>`、Web 包/锁与生成项目的 `sdk-lock.json` 应形成同一身份。业务工程自己的 VERSION 独立；历史包的 GUI peer 声明保持原样，不能就地改写旧包来满足新版本。

详细顺序、源码 SDK 与 CMake prefix 的区别及关闭责任见[版本与升级](../versioning.md)。
