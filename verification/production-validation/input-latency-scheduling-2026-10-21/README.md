# 主线程任务批次让出输入

本记录对应 [ADR-0118](../../../docs/adr/0118-main-thread-timer-batches.md) 和补丁 0013。它是未发布的源码候选验证，不替换固定 0.5.0 DLL，不授权 SDK 发布。

## 问题与范围

隔离 Windows 消费者的 SDK 内存采样中，鼠标已提交后的队列等待在 x86 达到 104.222 ms、x64 达到 156.8621 ms，并与引擎线程的长 `WM_TIMER` 回调重叠。取消绘制限速仍有 90.8313 ms 排队。该观察不包含 noVNC、输入设备或最终显示的等待；单个鼠标函数长执行也尚不能归为同一个原因。

正常主线程现在在完成 32 个任务或超过 2 ms 协作预算后返回消息泵，保留任务及到期时间。工作线程和平台关闭前的三次调度仍使用原 50 ms 规则，最终退出排空不变。协作预算不能抢占单个长回调；余下任务继续由原 16 ms 周期定时器处理，因此必须同时检查加载与刷新吞吐。

## 当前证据

- [夹具来源和构建身份](fixture-builds.json)：原始实现、最初尚未保留关闭前排空的候选、最终修复的源码绑定；四个原生测试程序与客体启动器的实际构建结果及散列。全部 22 个测试载荷逐字节一致。
- [源码映射 Node 检查](raw/source-maps-final.tap)：8/8；补丁正向、反向原字节重放及差异空白检查通过。[Web SDK 锁文件依赖审计](raw/sdk-web-audit-final.json)：0 项漏洞。
- [完整源码基线比对](baseline-source.json)：两架构输入均为 23,545 个文件；仅还原补丁中的三项文件记录后，完整清单身份与固定 0.5.0 内核来源一致。
- [隔离客体结果](guest-scheduler-results.json)：35/35 符合预期，其中原始源码两项预算病例和中间候选一项关闭病例按预期失败，最终源码的 x86/x64 各 16 项普通病例通过。所有子案例均观察到预期退出、空 Job 和句柄关闭，无超时或强制清理。
- [完整内核构建与静态 PE 比较](kernel-builds.json)：x86/x64 均通过公开 `Miniblink` / `LLVM22MSVC142` 入口自然完成；构建前后源码清单一致，进程树观察为空，无强制清理。原有 9,871 / 9,659 个具名导出及序号保留，导入 DLL 集合不变；该检查没有加载或执行 DLL。
- 夹具的受控时钟只验证预算边界，不是性能计时。原生程序只允许在隔离 Windows 来宾中运行，宿主只进行构建和静态检查。

原始实现的任务数病例一次执行 96 项，最终实现为 32 项；以每项推进 1 ms 的受控时钟观察，原始实现为 50 项，最终两架构均为 2 项。关闭前排空的中间候选为 32 项，修复后恢复为 96 项。这些数字验证调度契约，不是实际鼠标延迟。

原始串口字节、固定案例顺序、子回执和来源绑定可离线重验：

```powershell
node verification/production-validation/input-latency-scheduling-2026-10-21/analyze-scheduler-run.cjs --check-only --self-test
```

该入口同时拒绝六种截断或篡改样本。两架构完整内核已重编，消费者输入/吞吐对照结果尚待独立记录；夹具和静态 PE 检查不能代替实际 DLL 和页面运行。

[中间构建中止记录](interrupted-builds.json)分别保留关闭路径复核及构建控制通道失效后的中止身份。它们没有正常闭合回执，不计为通过；随后按 PID 与创建时间核对的进程清单没有发现仍匹配的成员，这不追认历史正常关闭。

## 重现与限制

夹具构建方法及案例在[测试说明](../../../docs/testing.md#主线程定时任务批次回归)和[夹具说明](../../../tests/native/vendor_lifetime/worker_lifetime/README.md)。原始实现的两个主线程预算案例预期失败；最初候选的关闭前排空案例预期失败；最终修复应在 x86/x64 通过 16 个普通案例。另两个原有故障终止案例需专门包装，本轮普通案例启动器不执行它们。

完整内核通过公开 `Build-Dependencies.ps1` 的 `Miniblink` / `LLVM22MSVC142` 档位重新构建。实际应用、工作进程和功能运行不在宿主进行。Windows 10 中运行独立消费者不等于 WinPE 启动、原生控件定量对标、长期性能或完整 SDK 资格。

本轮 `benchmarkValid=false`、`fullSdkApplicationValidationComplete=false`、`releaseReady=false`。回退方式是撤销本次源码补丁后重新构建；没有需要回滚的已导入二进制。
