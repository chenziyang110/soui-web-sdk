# Electron 对照系列：实时负载门禁的无桌面回归

`run-series.cjs` 的系列门禁新增每五秒进程身份扫描：外部 QEMU、SOUI/验收应用和编译器出现时拒绝当前轮；若扫描找不到本轮运行器进程，也拒绝计数。进程子树清理前复核 PID 与创建时间，无法确认时仅停止自有进程句柄并将清理不完整记录在原始门禁日志。`summarize-series.cjs` 重新读取系列记录和各轮原件，要求至少五对交替、完整前后/实时门禁及全部配对预检，并以各轮真实起止时间核对交替顺序和互不重叠；每轮前后门禁时间须分别位于对应运行起止之外。失败不产生候选比值。

本次先执行两份无桌面单元回归：`node --test tests/benchmark/series-interference.test.cjs tests/benchmark/series-summary.test.cjs`。第一轮外层捕获器原始退出码 0、超时 false、错误 null；Node 原始输出为 **21 通过、0 失败、0 跳过**。[四份原始文件和 SHA-256](raw-manifest.json)逐字节复核外部原件。随后发现单条实时记录不足以证明约一分钟的完整观察窗口，诊断器增加起止和采样间隔检查。第二轮独立原始退出码 0，**22 通过、0 失败、0 跳过**，[三份新增原始文件](raw-manifest-attempt2.json)另存，不覆盖首轮。再发现记录的交替字段不足以证明实际运行顺序，补充真实起止时间校验；第三轮仅执行 `series-summary.test.cjs`，原始退出码 0，**7 通过、0 失败、0 跳过**，[三份新增原始文件](raw-manifest-attempt3.json)单独保存。第四轮补充前后门禁与真实运行时间的绑定，同一 summary 测试原始退出码 0，**8 通过、0 失败、0 跳过**，[三份新增原始文件](raw-manifest-attempt4.json)单独保存。最终重新执行两份最新测试，外层捕获器原始退出码 0、超时 false、错误 null；Node 原始输出为 **24 通过、0 失败、0 跳过**，[三份新增原始文件](raw-manifest-attempt5.json)另存。测试包含真实 Windows 进程查询、自有 Node 子进程停止与 PID 身份复核，以及合成的五对、缺失门禁、采样缺口、时间颠倒、运行重叠和过期门禁反例。五轮都没有启动 SOUI、Electron 或新的性能系列；其他虚拟机在运行，不能据此声称获得隔离性能样本。

五对同机实际运行、真实物理输入到呈现时延、冷/热启动、完整运行包大小和目标系统负载仍待补证。门禁五秒采样也可能漏掉在两次查询间完整开始并结束的外部短进程，正式对标仍须人工隔离设备。本记录保持 `benchmarkValid=false`、`releaseReady=false`。

后续发现短运行可以让仅落在运行前后的两次采样通过起止容差，因此加入“运行时间内至少一次采样”的反例。修复前仅执行 summary 测试的原始退出码为 1，8 项中 7 通过、1 失败，失败点为 `Missing expected exception`；修复后两份完整测试原始退出码 0，**24 通过、0 失败、0 跳过**。两轮命令、退出码与日志作为[六份独立原件](raw-manifest-attempt6.json)保存并核对，不覆盖先前五轮。它们仍是无桌面的门禁回归，不构成隔离性能数据。

进程名审阅又发现最初的 QEMU 判定只列出两个可执行文件名，会漏掉 `qemu-system-x86_64w.exe` 等变体。新反例在原规则上实际退出 1、16 项中 15 通过、1 失败；改为识别整个 QEMU 可执行文件家族后，两份完整测试原始退出 0，**24 通过、0 失败、0 跳过**。[六份原件](raw-manifest-attempt7.json)另存并核对。此修改仅提高后续隔离门禁的覆盖范围，仍未产生真实 SOUI/Electron 对照结果。

随后给每轮 `run.json` 增加运行器 PID，并要求系列诊断的实时门禁 PID 与该原始记录一致。PID 不匹配反例在修复前原始退出 1、8 项中 7 通过、1 失败；修复后完整回归原始退出 0，**24 通过、0 失败、0 跳过**。[六份原件](raw-manifest-attempt8.json)独立保存。这里只验证绑定逻辑，实际五对系列及物理呈现测量仍未执行。

启动前的 `tasklist /fo csv /nh` 查询原先会静默跳过无法解析的行，可能把异常输出误判为空闲。现改为在清单为空、行格式异常或 PID 无效时拒绝启动。新定向测试的[三份原始文件](raw-manifest-attempt9.json)记录原始退出 0，**1 通过、0 失败**；该测试未启动 SOUI、Electron 或 QEMU。当时尚未运行完整门禁回归或五对实测。

在已有外部 QEMU 运行期间，只读调用真实 `tasklist` 又发现合法的 `System Idle Process` PID 0；初版解析器错误拒绝它，原始退出 1 和堆栈保留。修正后仅对这个确切系统进程跳过 PID 0，其余无效 PID 仍拒绝；新定向测试原始退出 0、**1 通过、0 失败**，新只读实测原始退出 0 并识别外部 `qemu-system-x86_64.exe` PID 31300。[失败与修正后的九份原件](raw-manifest-attempt10.json)单独保存。此结果证明当前宿主的清单格式可解析、占用进程可被门禁发现，不是隔离性能样本，也未启动任何对照宿主。

最终还要求 PID 0 以外至少有一个可运行进程，避免只收到系统空闲占位行时误判为空闲。[最后六份原件](raw-manifest-attempt11.json)显示该反例的定向测试原始退出 0、**1 通过、0 失败**，同时对当前真实清单的只读查询仍原始退出 0 并识别同一外部 QEMU。此轮仍未运行完整门禁回归或实际性能系列。

最后在外部 QEMU 仍运行时执行两份无界面门禁逻辑回归，[三份原件](raw-manifest-attempt12.json)记录捕获器与 Node 原始退出 0、stderr 空、**25 通过、0 失败、0 跳过**。该回归包含真实 Windows 进程查询及自有短时子进程，不运行 SOUI/Electron 宿主、不采集性能样本；因此不能把这次通过计为隔离五对对照。

审阅系列诊断时发现另一种间接证据风险：旧校验只要求空闲门禁在运行前后，允许门禁与实际测量相隔近一分钟。新增反例在旧实现上原始退出 1、**9 项中 8 通过、1 失败**，失败为预期的 `Missing expected exception`。现在初始、运行前和运行后门禁分别要求距对应起止时刻不超过 15 秒；系列执行器把运行后门禁移到页面散列复核之前，确保不会因为散列耗时使占用记录变旧。完整两份无桌面回归原始退出 0、**26 通过、0 失败、0 跳过**；[六份红绿原件](raw-manifest-attempt13.json)独立归档，旧样本未覆盖。这个修正只保证候选系列诊断拒绝过期门禁，不能发现两次进程查询之间完全开始并结束的短负载，也尚未产生五对实测或生产性能结论。

单轮失败路径审查发现，旧 `run-one.cjs` 只停止宿主、采样器和输入器的直接进程，可能留下 Electron 子进程；它还在 `exit` 事件上固定退出结果，早于日志句柄真正关闭。现改为先核对直接子进程的 PID、父进程与可执行文件真实路径，确认后只结束本轮进程树；不能确认则仅停止已持有的句柄，并将未证实的清理写进 `run.json.cleanup`。真实测试中 `C:\nvm4w\nodejs\node.exe` 与目标文件路径不同，第一次定向测试原始退出 1；改用真实路径核对后，第二次定向测试暴露测试夹具要求将 CLI 入口与可导入函数分开，原始退出仍为 1。两次修正和首次夹具失败均保留，[十五份原件](raw-manifest-attempt14.json)逐字节核验。最终定向测试 **2/2**，连同现有系列门禁共 **28/28**，捕获器和 Node 原始退出均为 0。测试仅启动自有短时 Node 进程树；当时外部 QEMU 仍运行，未启动 SOUI、Electron 或正式性能系列。仍须实际五对隔离对照及物理呈现、启动和包体积证据。

随后修正测试夹具在异常收尾时对 Node 路径别名的判断；新的定向回归原始退出 0、**2/2**，三份[追加原件](raw-manifest-attempt15.json)保留在独立批次。此测试验证清理边界，不是正式桌面性能结果。若直接子进程已经退出，进程树清理仍可能无法确认；运行环境的进程预检必须拒绝残留负载。

隔离门禁还漏掉独立启动的 `ProcessTreeSampler.exe` 和 `InputTrace.exe`。分类回归先按旧实现实际失败（17 项中 16 通过、1 失败），加入两种工具名后完整无界面回归原始退出 0、**28/28**；六份[红绿原件](raw-manifest-attempt16.json)单独归档。该检查会识别外部工具，同时按进程父子身份排除本轮自有工具；五秒采样与名称列表仍不保证发现所有短时或未知外部负载。

进一步审查发现，原门禁把本轮运行器的**所有**子进程都排除；若本轮意外派生 QEMU 或编译器，这些额外负载也会被忽略。新反例初次因命令行正则引号错误退出 1、尚未运行测试，原件保留；正确命令在旧实现上原始退出 1、**1 项失败**，实际将应拒绝的两个子进程误判为空。现在只排除本轮预期的 SOUI/Electron 宿主、采样器和输入器；即便 QEMU 或编译器位于本轮子树中，也判作干扰。定向回归原始退出 0、**1/1**，三份测试的完整无界面回归原始退出 0、**29/29**。[十二份原始记录](raw-manifest-attempt17.json)与外部原件逐字节复核。该改动不产生实际五对隔离性能样本，`benchmarkValid=false`。

清理边界复审发现，直接子进程的原生创建时间虽已查询，却没有与本轮 `spawn` 时间比较；若 PID 被复用，单看 PID、父进程和可执行文件不足以确认原句柄身份。现在将 Win32 创建时间明确转换为 UTC，要求落在本轮启动调用的两秒容差内，核不准时退回仅停止自有进程句柄并记录树清理未证实。新增反例第一次因测试只改写启动区间的一端而实际失败，原始退出 1；修正夹具后定向 **2/2**、合并无界面回归 **29/29**，均原始退出 0。[九份原件](raw-manifest-attempt18.json)独立保存。时间窗核对仍无法消除查询与 `taskkill` 之间的所有竞态；正式系列必须拒绝残留进程，且尚无五对实测。
