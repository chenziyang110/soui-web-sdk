# ADR 0107：依赖来源声明以纯文本随包交付

状态：已采用；当前完整应用重新构建与启动验收进行中。

## 背景

独立生成项目完成编译后，真实启动返回 `E_REMOTE_RESOURCE`。宿主会检查本地资源中的 JSON 运行地址；新增 npm 许可材料中的原始 package.json 含有 repository.url 等来源网址，因此被该规则拒绝。旧许可文本没有触发此情况。

## 决定

68 份原始包声明使用 `upstream-package.json.txt` 文件名，并同步材料清单中的声明路径。只改变附件名称，保留声明及 LICENSE/NOTICE 的原始字节和散列。清单仍使用 `index.json`，其来源使用位置、包地址、完整性和文件身份不变。

不修改宿主资源校验，也不豁免 `legal/` 目录；应用中的远程脚本、样式、JSON 运行地址以及嵌入框架仍按既有规则拒绝。来源声明属于供人和审计工具阅读的附件，不是页面运行配置。相比移除来源声明或按目录跳过校验，此方案同时保留取证材料与现有资源边界。

## 验证与迁移

两项交付回归先失败后通过，核对全部声明、许可文本和实际部署字节。使用已安装 SDK 的原生 Host 校验，旧材料准确返回 `E_REMOTE_RESOURCE`，新材料通过并到达适配器；五种远程/框架负例继续被拒绝，包括 `legal/custom.json`。负例退出 1 的自有尾进程清理如实保留，不表述为自然成功。

此变更发生在尚未打包发布的 0.5.0 候选。既有 preview 包和原失败证据保持不变；新 SDK、源码和运行包由正常清单重新生成。许可完整性和再分发审核仍按各自门槛处理。
