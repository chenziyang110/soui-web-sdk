# ADR 0124：可选 Web 构建目标、资源清单与体积分析

- 状态：已实现候选，验证范围见本轮记录
- 日期：2026-10-23

## 背景与决定

同一业务工程可能有多个 Web 界面。单一入口在运行期选择界面、再复制整个
public 目录，会让互不需要的图片和页面进入同一运行包。SDK 提供可选的通用
构建目标，目标名称由业务定义；核心不认识 PE、安装器或具体业务图片。

project.json 的可选 webTargets 声明默认目标和各目标的 index.html 入口、
公共资源清单。入口位于 web 内，各目标输出固定为 web/dist/<名称>；该目录
沿用现有构建输入排除规则。未配置项目继续使用现有 npm 构建、web/dist、
resources/index.html 和纯 distribution 自定义输出规则。

标准 Build 对生成项目串行构建所有目标；每次调用原 npm build 脚本并传递
目标选择，仍使用业务的 React、legacy 和经典入口处理。公共目录不再整体复制，
仅按 publicAssets 发布；静态 import 依赖仍由 Vite 处理。每个输出具有完整
文件身份清单，绑定目标及规范化配置身份，拒绝缺失、额外和被修改的文件。
经典入口工具在改写前校验已有清单，完成自身 HTML 变换后重新记录身份。

构建证据包含所有声明目标；默认目标用于原生部署。兼容 CMake 未显式传递
WEB_ROOT 时查询默认目标，现代模板使用相同查询。部署继续由现有 resources
事务完成，顶层 legal 材料单独验证；成功构建读取也核对所有目标及实际部署
目标，避免用另一目标或旧产物授权打包。

runtimeProfile、webProfile 和业务目标相互独立，分别描述后端、发布/源码诊断
档和业务构建入口。新增目标不改变最低系统、原生 ABI 或 Web 兼容目标。

## 体积报告

现有 soui.application-size/v1、payload、categories 和 archive 字段保持。
追加 sizeAnalysis，包含按文件类型统计、大文件排行、同字节身份重复文件和
可选基线差异。重复潜力按未压缩字节计算，不能推导压缩后的收益。

基线比较要求应用、架构、配置、后端、Web 目标一致，版本可以变化。项目可以
显式指定 totalBytes 或 growthBytes 预算；增长预算必须提供可比基线。预算
失败返回非零，保留诊断报告，不创建新的应用归档。默认不设产品大小预算。

## 备选、兼容与恢复

- 按文件名排除 PE 或安装图片：SDK 无法推断业务用途，不采用。
- 仅拆 JS chunk：无法控制公共目录复制，不足以解决资源混装。
- 自动删除静态搜索无引用的资源：可能破坏动态引用，改用显式资源清单。
- 不改变已有项目配置、模板入口或固定已发布 SDK 包。应用主动声明目标后，
  需要为每个入口设置相对于该入口的模块路径；共享源码可以保留在 web/src。
- 去掉可选配置后重新构建即可回到单目标输出；旧运行资源由部署事务替换，
  不对业务用户数据做清理。
