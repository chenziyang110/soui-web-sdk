# ADR-0119：统一系统 WebView 桌面入口

- 状态：代码实现，目标机验收待完成
- 日期：2026-10-20

## 背景与决定

用户接受 Linux WebKitGTK、macOS WKWebView、Windows WebView2 路线，并要求同一
C++/Web 业务代码接入。保留现有 SOUI/Miniblink 路径，新增独立 `Soui::Desktop`
入口及平台无关 `soui::desktop::application` API，不让业务代码依赖 GTK、Objective-C、
HWND 或 COM 类型。首个实现管理单个主窗口；不声称 Electron 的全功能或渲染一致性。

统一窗口生命周期、受控本地导航、Promise 请求/JSON 响应、原生推送事件，以及标题、
尺寸、可见性、焦点、剪贴板和目录选择的能力查询。能力缺失返回明确错误。

## 安全与生命周期

资源根由原生应用指定并规范化。入口必须是根内的本地普通 HTML 文件；导航重新
核验目录边界，拒绝网络、脚本 URL 和根外路径。网页导航不自动获得任意本地文件或
原生服务权限。每次原生导航轮换系统熵令牌，Bridge 仅注入顶层文档；原生接收验证
当前页面、令牌、版本、请求大小、结构、方法名及有界请求 ID。平台能提供消息源
frame/origin 时同时核验。禁止新窗口、下载和默认设备权限授权。

GTK 的公开消息 API 没有 sender frame/origin；其令牌是顶层能力，而不是原生 frame
身份证明。同源 iframe/about:blank/srcdoc、顶层加载的第三方脚本与 XSS 都可能调用
顶层 API，视同应用代码。闭包不能隔离同一 JavaScript realm 的恶意 monkeypatch。
应用必须信任其全部页面脚本、正确设置 CSP，并保持资源目录不可被不受信任者修改。
入口路径检查不等于完整文件系统沙箱，不证明所有脚本、图片、CSS 子资源均受目录
边界限制，也不能消除外部进程更改资源的 TOCTOU。系统引擎自身沙箱保持开启。

每个真正的顶层 document 替换必须通过原生一次性导航 ticket 创建新令牌/代际。
引擎自行 reload 先取消，再转给公共 reload 路径。不能确认是否同文档的动作保守
拒绝；GTK 对非 ticket 的同 URI location.assign 也拒绝，应用应调用统一原生导航。
页面 pagehide 拒绝未完成 Promise，晚到消息/响应按代际失效，不跨文档交付。

Bridge 的应用回调是显式扩展点；不注册无权限检查的通用文件或系统命令。现有
Runtime 的 session、permission 和授权模型不因桌面入口而改变。宿主 API 只能在
创建它的 UI 线程调用，后台结果必须通过原生调度入口送回 UI。关闭必须先失效
回调与令牌，再释放 WebView/窗口；晚到异步回调不得访问已销毁宿主。

## 兼容性、备选与迁移

替代选项是移植整个 SOUI/Miniblink 或引入 Chromium/CEF；它们需要更大的引擎构建、
补丁及分发维护。系统引擎保持较小接入面，但 CSS、媒体、字体、沙箱和最低系统
随平台引擎变化，不保证逐像素一致。现有 Windows 兼容入口不删除、不改变默认构建。
新增桌面目标是显式选择；完整打包与版本发布沿用仓库维护者流程。

## 验证

共用协议/导航/线程/失败用例使用不依赖平台 UI 的测试。本次 Linux 已通过真实
GTK3/WebKitGTK 头文件和库的编译、链接、安装及独立消费者构建；图形服务被执行
环境限制，窗口、JavaScript 和原生 Bridge 集成尚未运行通过。缺少显示服务时返回
明确 E_DISPLAY，不能算 GUI 验收成功。原生集成测试已提供，需在可用图形会话下
显式开启并执行。Windows/macOS 必须分别在对应目标工具链与系统运行，当前均未
编译或运行，不以 Linux 或合成矩阵结果代替。架构支持由实际系统引擎、SDK、ABI
及发行版决定，不宣称现代 macOS 32 位或任意 ARM32 桌面可用。
