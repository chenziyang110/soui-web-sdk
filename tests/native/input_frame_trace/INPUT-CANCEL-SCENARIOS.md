# W02 actual Host cancellation scenarios — source handoff, unexecuted

Use `SouiInputUiHost` with this directory's `cancel-page` as `--page-root`, a unique run, `--trace=full`, matching rebuilt SDK/kernel, and an independently supervised native input driver. This is a correctness fixture, not the burst performance page; the ordinary burst reader deliberately will not qualify it.

- `accepted-down-overload-cancel-no-click`: arm the page's one finite computation, send a real pointer down over the subject, and first observe `down=1`. During the scheduled callback, flood the real HWND's ordinary route until the native capacity/cancel receipt records actual recovery. Release the physical button through the real native route. After recovery, `click` must remain 0. Send a fresh down/up after release; it must produce exactly one click. If no real capacity rejection/cancel was recorded, mark the scenario inconclusive; a button release fabricated by the fixture is not a cancellation proof.
- `composition-cancel-no-commit`: start a real OS IME composition in the seeded input, arm computation before composition starts, and retain the pre-composition value. During an actual composition update/long callback, trigger the same real admission/cancel route. Cancellation must not commit composition text or synthesize a character/up. Release native modifier/key state, then start a new real composition and explicitly commit it; the new operation must work. Unicode SendInput bypasses IME and cannot qualify this case.
- `release-quarantine-fresh-edge`: while recovery is quarantining a held physical button/key, moves and repeats cannot create a new DOM click/text action. After the genuine release, a fresh edge pair must be accepted and the fixture's counters/values must agree with native accepted/rejected/recovery totals.

Persist the oracle's `window.inputCancelOracle.snapshot()` through the verifier's existing actual Host inspection channel and retain raw native/desktop evidence. It bounds events at2048 and marks overflow. The fixed arithmetic callback intentionally creates useful JS work; it does not use `performance.now`/Sleep(0)/a zero timer loop to busy-wait. No callback is treated as preemptible. Navigation, close and actual capture loss remain separate barriers. This source does not call raw WKE input/reset functions or modify native production input state.
