# PR #103：一份业务代码的跨平台桌面迭代路线

更新：2026-10-23。目标是统一窗口、Bridge 和常用系统能力，让同一份 C++/Web 业务
接入 Windows、Linux、macOS；以 Electron 式开发体验为参照，不承诺全部 Electron
API 或不同系统 WebView 的逐像素等价。完成模板或一个最小接口不等于完成此目标。
本路线是后续代码与验收的统一清单，继续同一 draft PR，不在此执行正式发布。

原 Windows Host 的实现是迁移参考，不原样替换旧业务契约。系统辅助功能 Agent、UIA、
远程自动化等不是本次口头目标自动产生的承诺。全局快捷键属于常用系统能力候选，
但必须处理 Linux Wayland/桌面门户等约束，不用假成功填充矩阵。

## 阶段一：统一应用控制与业务窗口生命周期

1. 窗口状态纵切（已实现，目标交互验证进行中）：三后端 minimize/maximize/restore、观测快照与变化事件；
   同一typed前端接口，显式宿主授权，无平台业务分支。区分请求已接纳、观测值、未知与不支持。
2. 可取消用户关闭纵切（已实现，目标交互待验收）：区分用户关闭请求、程序close与应用quit；保留未保存
   业务确认入口，设计重入/重复请求/整组退出策略，不在原生关闭途中阻塞等待网页Promise。
3. 同一业务示例串起状态、跨窗事件、导航撤销和关闭保护，不止增加孤立按钮。

完成门槛：公共层权限/关闭/导航专项通过；三个后端目标编译证据分别记录；可运行图形
会话验证实际状态变化和关闭业务。环境阻塞不记通过，也不暂停其他可实现代码。

## 阶段二：可复用、权限明确的常用系统服务

按完整纵切逐项交付，保持网页新增系统服务默认权限为零。窗口属性、剪贴板读/写、
目录及打开/保存路径选择已实现独立开关与typed facade，目标原生交互仍待验证。
阶段二功能实现至此收口，下一步执行阶段三限定集中回归，不继续追加特性：
- 已有窗口控制标准服务先稳定，再接入标题/可见性/焦点等当前窗口操作；明确空参数、
  UTF-8/尺寸边界和是否需要真实手势，不允许网页指定其他窗口句柄。
- 剪贴板写入/读取、目录选择分别授权，不用单个“系统权限”开关全部放开；原生来源与
  真实手势能力不足的平台需拒绝或明示差异，网页JSON标志不能自授手势。
- 层级popup/tray模型已实现（64节点/4层、禁用祖先、每窗ID/修订号隔离）；
  原生交互仍待验证，托盘更新/退出/宿主丢失行为需目标桌面闭环。
- 原生宿主全局快捷键已形成独立有界契约，Windows/Mac/X11 实现；Wayland/未知会话
  明确不支持，Portal 与应用内 accelerator 未实现，目标机器实际注册/触发/释放仍待验收。

完成门槛：同一业务C++/JS只用统一服务；撤销/导航/关闭后不得继续触发旧授权；至少
针对新增操作做小范围参数与生命周期验证。平台特有能力必须由capability及明确错误处理，
不能要求业务绕开SDK直接使用GTK/AppKit/HWND作为常规接入方案。

## 阶段三：整体验收与可交付收口（进行中）

六个功能纵切已实现：窗口状态、关闭审批、标准服务、层级菜单、宿主全局快捷键、
打开/保存路径选择。当前停止增加接口；限定集中非 GUI 回归及 Mac 最终双架构安装交付核对已完成，
真实平台交互验收仍待闭环，不将这一阶段结果等同整个目标已完成。
最新状态与各项证据边界见[2026-10-23 集中记录](acceptance/unified-desktop-2026-10-23.md)。

- 用同一业务源码覆盖三引擎窗口、Bridge、模块/动态导入/fetch、菜单/托盘/快捷键、
  剪贴板/对话框、关闭保护，以及DPI/焦点/IME最小交互；集中回归与修复在此阶段展开。
- 在目标机完成安装SDK→消费项目→应用目录/归档→doctor→真实启动；记录外部运行库、
  系统版本、编译工具链、架构和失败状态，不能把自构建引擎当已打包系统依赖。

  改license或版本、不覆盖已发布0.5.0、不自动签名/公证/合并/发布。
