# ADR-0130：已校验应用的可分发归档

状态：开发交付物，不是签名发布或安装器。

## 决定

新增本地 Node archive 工具，只接受通过既有 verifier 的 staging 目录，生成
新的交付目录：ZIP、独立 SHA-256 与最后写入的 delivery manifest。使用无第三方
依赖的 ZIP32 store 模式，保存 UTF-8 路径、标准目录层次和 Unix 执行权限；不
压缩以避免新增依赖或不透明外部命令。包根使用有界的应用名/版本/平台/架构。
现有 .app 目录保持原样，不新建安装器、签名、公证或自动上传流程。

归档前核验输入，复制时分块校验源文件大小/散列并计算 CRC；完成后重新读取
ZIP 头部、目录和内容，与预期条目/散列/权限比对，而不是仅信任写入成功。
ZIP32 容量和条目数失败关闭，不静默截断或切换格式。输出必须新建且不与输入
重叠，拒绝 symlink/不安全路径，失败保留不完整输出但不写最终交付 manifest。

自附散列和 delivery manifest 仅证明内部一致，不证明来源身份或没有恶意
内容；结果必须保留 authenticityVerified/nativeRuntimeVerified=false。只读
输入且不执行二进制/doctor，不下载、安装或修改安全设置。目录须在运行期间
静止，校验不是防恶意并发替换的文件系统沙箱。

## 集成和备选

安装工具随 SDK 分发；CMake 独立 archive_stage 目标读取既有 staging 输出，
不重建或重新覆盖它。默认交付输出在 staging 旁，可显式指定新的 ARCHIVE_OUTPUT。
不复用 SDK 开发 ZIP 入口，以免混淆开发包与应用交付；不依赖宿主 tar/zip 工具
的模式差异。接收方解压工具仍可能忽略 Unix 权限，应在目标机重新验证。

## 验证

少量失败路径与 ZIP 内容检查，加一次真实 Linux 应用和安装 SDK/CMake 入口。
跨平台解压器、macOS .app 实际启动、签名、正式分发和完整回归仍待统一验收。
