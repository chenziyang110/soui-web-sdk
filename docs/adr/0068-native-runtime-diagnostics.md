# ADR-0068：采用 0.5.0 原生生命周期与运行诊断源码

状态：proposed。源码已采用，运行与发布验收未完成。

## 背景

仓库基线 `0201e30b` 的 Miniblink 原始导入清单和补丁 0001–0008 仍记录历史身份。0.5.0 已形成包含线程退出、Worker/MessagePort 生命周期、原生诊断和构建兼容修正的完整固定源码。只交付诊断头或沿用旧导入清单，不能表达当前源码边界。

## 决定

采用固定完整 Native 源码清单 SHA-256 `426b5d537bb294f984d896c84e90cd8f5d4875ff1b7fc0910dca40f91f8aca0f` 所绑定的原始文件。清单边界为 23,543 个文件、1,330 个目录、321,004,079 字节；在干净基线中仅复制实际不同的文件，保留所有未变文件的原字节。

新增补丁 `third_party/patches/miniblink/0009-0.5.0-native-runtime-diagnostics.patch`，以仓库相对路径记录基线到当前源码的差异，供维护者在原有补丁之后重放。保留 `SOURCE-MANIFEST.json`、`LOCAL-CHANGES.patch` 及补丁 0001–0008 的历史内容和验证范围；当前交付源码身份由新的完整交付清单记录。

本次源码包含进程/渲染器诊断的独立版本化 C 接口：v1 的 168 字节观察结构与 v2 的 264 字节模型结构，均须检查接口版本、结构大小和能力位。模型与观察记录在同一锁下读取；初始化身份、单调时钟、CPU/GPU 历史、关闭与终末记录分别保留。缺失、忙、未知、溢出或身份不一致不得被解释为零资源或运行通过。Worker/MessagePort 的退出与 join 仍按其真实所有者生命周期完成。

同时采用既有构建兼容修正；最后生效的 `Release|Win32` 定义新增 `CURL_STATICLIB=1`，使调用方声明与静态 libcurl 相符。已有 `Release_NoNode|Win32` 定义保留，不扩大到 Debug。公开构建入口的工具链选择由对应构建工具契约负责，此补丁不导入私有控制器、输出目录或开发机绝对路径。

## 备选方案与兼容性

只复制新增诊断头不能提供其实现与生命周期；全量重写源码会掩盖不必要的字节变化，均不采用。现有 v1 和原有业务接口保留；v2 是另一个显式可选接口，不能以接口存在推断旧二进制支持。软件/GPU 和最低系统的资格由实际构建与目标系统测试决定，源码采用不改变默认 GPU 策略。

## 迁移与验证

迁移仅涉及原生源码、补丁及本决策记录，不替换任何预编译 DLL/LIB，也不更新其 provenance、许可证或发布结论。采用前后核对精确成员集、全部原始散列、差异文件与未变文件；补丁须能正向重构当前字节并反向恢复采用前字节。

这些是文件系统和静态核对。两架构的真实重编、接口拒绝/初始化/终态测试、应用与长时资源测试、目标系统及当前二进制许可审核仍须分别执行。历史诊断、纯数据测试或源码审查不能替代这些结果；`releaseReady` 不因此变为真。
