# ADR-0067：分别绑定 LLVM 项目与验证工具的请求

- 状态：proposed
- 日期：2026-10-13
- 关联：[ADR-0033](0033-standard-owned-build-caller.md)、[ADR-0066](0066-versioned-native-toolchain-inputs.md)

本记录保留内部请求选择切片当时的设计与有限验证范围。后续公开 LLVM Release 入口及报告归属字段随 [ADR-0069](0069-sdk-source-delivery.md) 的交付实现接入；下述原切片结果不扩大为当前公开入口的运行验收。

## 背景

独立生成的应用项目和 SDK 验证工具位于不同目录。两个目录分别生成包含固定工具链、身份桥文件及完整输入摘要的 LLVM 请求。原桌面检查把项目请求同时传给工具目录的准备检查；请求读取器正确要求固定文件属于自己的目录，因此拒绝这次跨目录复用。

## 决定

桌面检查分别读取项目的显式请求与验证工具目录中对应架构的 `llvm-profile-request-Release.json`。两个请求都经过原 `readRequest` 验证，包括文件字节、目录归属、工具角色、头文件与库成员、BridgeIdentity 和 InputIdentity。检查不创建、复制或修改请求。

同目录的 `sameProfile` 继续比较全部值。新增的跨目录比较先重新读取两个请求并核对原快照，再仅规范化固定工具链、两个身份桥文件的归属路径，以及由这些路径独立推导且已经验证的两种摘要。工具和依赖的路径与字节、桥与工具链源码字节、目标架构、输入版本、包含与库目录及其余字段仍须完全一致。规范化只用于内存中的比较副本，不替代原请求和收据。

实际准备和后续重查使用工具目录自己的请求。烟雾报告继续记录项目请求的原始身份，同时把准备报告与当前工具目录的准备结果、OwnedProcessRunner 字节一起比较。报告里的路径不能用于选择或加载另一个目录的代码。实际应用进程、参数、就绪与关闭记录及拒绝强制清理的规则保持不变。

## 影响与迁移

不增加公开命令参数、请求格式或报告格式。当前公开 Release 检查仍选择 MSVC143；这项修复覆盖显式 LLVM 桌面检查内部入口，不能据此宣称公开 Release 已覆盖 LLVM。

验证工具的源码指纹包含此次变更。每个架构和工具链档位必须重新准备工具目录，应用目录也必须生成自己的请求并构建。历史准备报告、请求及 Runner 不作为新源码的通过证明。请求缺失、归属错误、工具或源码不一致、准备报告过期时直接拒绝。

## 验证

独立源码审查核对了三个源码成员，并确认原请求读取器与同目录比较保持原字节。23 个文件的独立逻辑工作区实际运行了 24 项工具链检查与 8 项发布检查：31 通过、0 失败、1 项文件符号链接检查因本机 EPERM 跳过。五个新增用例全部通过，覆盖两个架构、两种输入版本、错误归属、不同依赖、过期身份与缺失准备请求。监督进程自然退出，自有 Job 归零。

这些结果支持内部请求选择与比较规则，不证明实际 LLVM 工具准备、独立项目编译、界面运行或 SDK 发布资格。上述实际验收仍须绑定最终 SDK 和新内核载荷；跳过的文件符号链接边界保持未验证。
