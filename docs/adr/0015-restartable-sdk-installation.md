# ADR-0015：可跨进程恢复的 SDK 安装事务

状态：实现中，生产验收未通过。候选版本：0.3.0-preview.13。跟踪 Issue #33。

## 背景

preview.11 的真实终止实验表明：旧文件已移入备份后，进程没有机会进入 catch，下一次正式校验和安装均失败。内存中的 touched 列表无法支持重启恢复。原始失败见 `verification/production-validation/preview11-upgrade-interruption-2026-09-26/`。

## 决定

安装器在业务项目内独占 `.soui-sdk-transaction`。发布该目录前已写好本机进程身份；存活或身份不明的持有者不允许第二个安装/恢复进程进入。死亡持有者由顺序编号的不可变 claim 目录接管，claim 通过同卷非空目录重命名竞争发布，避免两个恢复进程同时修改项目。PID 复用或其他主机的记录按占用处理，不能自动猜测锁失效。

改动任何已安装文件之前，持久化全部旧 SDK 字节、完整新载荷及不可变 journal。journal 绑定两个合法 v1 清单和旧锁原字节。复制文件和记录关闭前执行 fsync。没有已发布 journal 时，协议保证尚未改动项目，可以回收准备事务。

每个目标由同卷临时副本原子替换；备份在整个事务中保持完整。新 sdk-lock.json 的原子发布是提交点。恢复时新锁与全部新文件吻合则完成提交后的清理；否则只有旧锁仍精确吻合时才恢复旧版本。恢复先完整校验备份和所有受管目标，发现超出旧/新/缺失状态的字节、链接、非文件或锁冲突即停止并保留现场，不能覆盖用户修改。恢复本身可以再次被终止，然后从相同 journal 重试。

`install` 先处理遗留事务，再执行本次请求；`recover --project DIR` 只恢复，不开始升级；`verify-project` 保持只读，未收敛事务必须报错。全部动作保持 SDK 与业务目录的既有所有权，拒绝大小写改名等跨清单歧义。清理先将独占事务移到随机退休目录，再删除该准确目录，避免删掉后来创建的事务。

Windows 目录发布/退休遇到瞬时 EPERM/EACCES 时沿用最多六次有界重试；仅在源仍存在且目标不存在时重试，永久失败保留事务并返回非零。不同版本的同一受管路径由文件变为目录或相反，在任何项目载荷修改前明确拒绝；此类迁移需要另行设计数据和目录所有权迁移，不能进入无法自动判断的中间状态。

## 兼容与边界

SDK 包/项目锁保持 v1，升级与回退可使用旧包，但应从完整新交付目录调用新安装器。受管安装器本身可以被替换，不依赖项目内后续动态加载。业务 VERSION 和 app/web/contracts/resources 不随 SDK 安装更新。

旧 `.sdk-install-*` 没有 journal，不能伪造为新协议事务；保留并明确报出需依据原包清单恢复，后续另行验证旧现场的受控迁移。新协议不宣称覆盖断电、磁盘损坏、网络文件系统或敌对并发写入。安装/恢复期间停止业务项目构建、运行及其他写入；fsync 不等同于所有 Windows 存储设备的掉电保证。未发布的准备目录或已退休目录可能因进程退出而留存，不影响 SDK 身份，不自动扫描删除未知目录。

## 备选方案

- 仅扩展 catch：无法处理进程终止，拒绝。
- 每个文件移动后再记日志：退出窗口会留下无法判断的状态，拒绝。
- 无条件用旧包覆盖：可能覆盖本地修改，拒绝。
- 新增数据库/常驻服务：对本地源码 SDK 交付成本过高。完整备份加不可变事务记录足以识别本次操作允许的状态。

## 验证

真正终止独立 Node 子进程，覆盖准备、journal 发布、替换、删除、新增、锁提交及恢复中断。再启动新进程恢复/继续安装，检查旧锁原字节、全部 SDK 文件和中文业务数据。测试初次安装、升级、回退、重复恢复、并发拒绝、备份/目标/锁篡改、链接和非法 journal；保留失败输出。既有包测试、独立真实包迁移和安装后消费者仍需执行。通过这些文件事务测试不能授予 GUI、完整源码、Win7 或生产通过。
