# ADR 0094：应用等待真实 Runtime 关闭

状态：实施中；真实桌面红测已复现，修复与候选验证尚未完成。

## 背景

兼容模板和 Workbench 的三个实际启动场景均完成页面就绪与 Host 关闭，
但最终返回 7。`shutdown_miniblink_runtime()` 已是非阻塞接口，首次提交
Worker 准备后返回 `E_RUNTIME_SHUTDOWN_PENDING`；应用仍只调用一次。
Modern 模板仅关闭 Controller，主进程返回 0 后五个浏览器子进程仍存活，
原两秒收尾期限因此失败。不能把这些状态当成 Runtime 已关闭。

## 决定

- 保持现有非阻塞接口。新增有期限的应用便利函数，反复调用原接口，
  只重试 pending，保留其他错误；使用单调时间与有限消息批次，不能因
  消息持续到达而绕过期限。适用于所有 Host 已销毁后的最终应用退出。
- 初始化前必须同时存在 `wkePrepareWorkerShutdown` 与
  `wkeFinalizePrepared`，缺失时以 `E_DEPENDENCY_API` 拒绝旧内核。
  不能到应用退出时才发现已初始化的模块无法按现有契约关闭。
- 兼容模板、Workbench 与参考应用使用二十秒的应用关闭预算；外部启动
  和自有进程组收尾期限保持原样。COM 在真正关闭成功或明确失败后释放。
- 发布升级/回退所保留的同一业务夹具也遵循该顺序：编译到 0.5 及以后 SDK
  时使用二十秒等待；编译到历史 0.3/0.4 SDK 时仍调用其已有关闭接口。
  依据 SDK 版本头在编译期选择，四次安装之间不改业务源码，不向旧包补入
  新函数，也不覆盖原有业务失败码。
- 独立基准宿主同样遵循已有 Host 关闭契约：收到关闭请求后保留消息循环，
  在后续计时器轮次重试 `E_BUSY` / `E_CURSOR_CLOSE_PENDING`，二十秒内成功后
  才销毁 HWND；其他失败与期限耗尽保持失败。随后使用统一 Runtime 等待函数。
  不能在一次 `destroy()` 尚未成功时销毁窗口并调用 Runtime 关闭。
- Modern 模板明确独占自己的持久配置目录，使用已有 Runtime exit watch。
  Controller 关闭后保留窗口消息循环、adapter、Bridge 和 watch，直到
  实际退出事件、进程信号及回调收尾满足现有 `finish()` 契约。
- 真实失败、期限耗尽或不能安全释放的借用均保持失败，不能直接销毁未
  完成的 watch。成功日志仍只在真实完成后写入。
- 对实际未取得 Environment 的初始化失败，保留原错误并在回调已结算、
  worker/Bridge 已释放且无任何 Environment、Controller、Core 或 watch
  后，允许查询失败清理完成。此状态不生成 Runtime 退出成功证明；已取得
  浏览器身份的路径仍必须经过原退出 watch。错误线程或重复 prepare
  不得改写正在运行的适配器状态。

## 兼容性与替代方案

非阻塞调用者不变；新增便利函数不改变现有 ABI。需要重新构建使用新函数的
应用。Modern 最小模板拒绝并发共享同一配置目录；多实例应用应明确分配配置
目录，或自行使用 SDK 的共享模式及对应生命周期契约。

不采用加长监督器收尾期限、忽略 pending、杀死浏览器或把 Host 关闭等同于
Runtime 关闭。每个应用复制轮询规则容易再次遗漏，故放入 SDK 统一维护。

## 验证

第一轮修复后 x64 Release 完整构建及 185 项原生回归通过，Modern 正常
就绪/关闭通过，兼容入口仍返回 7：随包 DLL 缺少源码所需的
`wkePrepareWorkerShutdown` 导出，须重建并更新真实依赖，不能把缺失接口
当成已关闭。Modern 启动后 36 ms 收到关闭请求的诊断另复现
`E_PENDING` 和 fail-stop：尚未挂载的 Host 不会收尾适配器的异步准备。
应用现保留初始化完成回调，取得真实退出身份后再关闭；即使未挂载，也
显式重试适配器 `unmount()`。关闭总预算不变；隔离诊断构建在实际 29 ms
关闭请求下自然返回 0，正常就绪/关闭复验也通过，最终候选仍须重跑。

对实际轮询策略验证立即成功、连续 pending、原错误保留、期限耗尽与消息
处理失败；继续执行现有原生回归。重新构建后必须重跑三个兼容入口和 Modern
实际启动，并要求原期限内根进程、监督器均为 0，整个自有进程组自然归零。
这不关闭长期稳定性、共享配置、多实例、目标系统和正式发布门槛。

另外，实际 SDK 隔离构建验证了两项独占初始化失败（相对 profile、缺失
Fixed Runtime）及原有取消、回调重入、回调异常、异步 preload 失败的完整
准备回归，均自然退出 0/0。旧实现在失败清理断言处返回 1，原件保留。
这些诊断输出不替代最终候选的完整构建与桌面验收。
