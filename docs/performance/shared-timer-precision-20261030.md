## 诊断与修复

外部页面每批执行 10,000 个整数各 16 次 LCG、240 个 DOM transform、一次串行 C++ `app.greet`，返回后等待 `setTimeout(16)`。分段诊断（2 秒预热、10 秒计量）中，基线 timer 等待平均 17.46ms，原候选 24.68ms；Bridge 平均为 0.94/1.53ms。候选吞吐约为基线 70.7%，未通过预先记录的探索性 95% 对照检查。

生产路径从高精度 waitable timer 改为普通 threadpool timer 后，仅靠短期 `timeBeginPeriod` 不能保证不可见 Windows 11 场景的精度。修复优先复用高精度 waitable timer 与 threadpool wait，不恢复逐 deadline 注册/注销；原 pool/native fallback、ticket、owner 绝对时间复核与锁外关闭保留。

## 自动回归与构建身份

修改前新增高精度后端选择断言：旧源码编译成功、52 个断言仅该新增行为失败。修改后 `scheduler_continuation` 在 x64/x86 各 3 项 CTest 通过，主契约各 64 断言、0 失败；覆盖复用、重臂无同步 drain、API/创建/arm 失败回退、提前/迟到通知、旧票号与锁外关闭顺序。Win32 替身不证明真实精度。

x64 真实 TU 编译与重链 exit0，实际 include 记录确认读取修复头；其他冻结对象/依赖和编译所消费源码前后散列不变。修复 DLL 为 39,208,960 字节（原候选 +512 字节），SHA256 `590d2eed41c818f36247cd79ea060312761fc60b47e1ab15fa93df5384af60d6`。最小重链是定位/复测构建，不冒充完整公开 Build 收据。

## 结论边界

已关闭本次隐藏桌面合成场景中约 31% 的吞吐回归。宿主使用平衡电源方案、有其他 VM 和多个显示适配器，非独占基准环境；没有直接观测 Windows 是否忽略该进程的计时精度请求，不将机制推断扩大为所有系统前台表现。

完整前台性能、物理输入延迟、长期稳定性、WebView2/Scratch 以及正式运行目录/ZIP 零增长门槛仍需原流程验证。内核 +512 字节不能称为零增长。无需为本次修复重跑已冻结的长期测试，也不能据此将整个 PR 标成生产验收通过。回退仅撤销本修复对应源码与补丁，保留旧证据及其他 PR 实现。
