# ADR-0134：原生后端终态与关闭重入边界

## 背景

Linux 的 WebKit 进程终止与加载失败可能发生在文档回调已经排队之后；仅设置失败
标志不足以撤销旧回调。macOS 的 AppKit 窗口关闭通知也可能同步重入后端清理，
不能在系统已经执行关闭时再次调用同一窗口的 close。

## 决定

- Linux 失败终态必须失效旧文档的排队回调和异步求值，不让旧 loaded、message
  或 reload 工作越过终态边界；保留明确失败通知，不把失败转换成成功。
  普通窗口 dispatch/close 保留；只有显式原生 load 清除失败态，迟到引擎信号
  不得恢复旧文档。取消、策略中断与其他 URI 失败不误伤当前文档。
- macOS 区分系统发起的窗口关闭与后端主动关闭，清理只执行一次，并在关闭栈
  返回前保留必需的对象生命周期。系统关闭通知不递归发送 close。
- 保持既有公共 API、权限和应用退出契约，不扩大到新增窗口功能。

## 备选方案与兼容性

不依赖回调碰巧按预期顺序发生，也不通过吞掉所有通知规避生命周期问题。
修复只收紧过期回调和重复关闭行为，业务不应依赖失败后仍交付旧文档事件。

## 验证边界

以少量针对性无 GUI 契约检查与可用 Linux 头库编译验证实现；这些不等价于真实
WebKit 或 AppKit 验收。Linux 自构建运行时仍在并行编译，macOS 没有原生目标
环境。实际执行结果另记验收记录，未执行的原生交互不得标为通过。
