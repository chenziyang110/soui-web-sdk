## 真实完整包

在仓库外分别复制既有账本小样的 22 个应用/中文数据文件，使用正式 CLI 安装 preview.11。由独立子进程执行升级，在实际替换 version.h 后、实际发布新 sdk-lock.json 后分别暂停；父进程真的终止子进程，记录 PID、边界、signal 与输出，不向安装器抛可捕获异常。

两个项目在遗留事务存在时，正式 verify-project 均退出 1。新的恢复进程均退出 0：替换边界恢复旧 preview.11 锁和全部 418 文件；提交边界确认新 preview.13 锁和全部 419 文件。每个项目随后升级、回退、再升级都由独立 CLI 完成并逐文件核对，22 个业务文件全程原字节不变。回退也验证了新安装器辅助文件从项目中移除、之后仍能由外部新安装器再次升级。

`raw/preview13/result.json`、完整输入/锁清单、各步 stdout/stderr/退出码和终止边界均归档。原生编译和 GUI 没有执行，不能把业务字节保留表述为业务运行成功。

## 合成包的真实进程故障覆盖

prepare、journal、替换、删除、新增、锁提交、清理七个边界；首次安装；恢复接管和恢复写入再次中断；活跃安装者及竞争恢复拒绝；目标、旧/新备份、锁和 journal 篡改；提交后内容冲突；旧锁 BOM/换行保持；链接保护；回退方向。还有 Windows 目录重命名瞬时/永久错误的可捕获注入测试，这两项不冒充进程终止。

小包来源和父/子进程测试代码可在仓库复现；各次外部原样本留在输出所指的独立 `out/sdk-recovery/attempt-*`，本归档保存最终一轮的进程边界与 CLI 记录。

## 失败历史与限制

内部 preview.12 的首次真实包驱动误用生成目录层级，退出 1，尚未安装。第二次完整包在回退提交后清理时连续遇到 Windows 目录退休 EPERM，退出 1；项目锁、journal 和输出保留。增加有界目录重命名重试后另用 preview.13 包，不修改旧包身份。文件/目录形态变更的保护负例也先失败；新协议在项目载荷修改前明确拒绝此类迁移，未声称支持自动形态迁移。

旧 preview.11 `.sdk-install-*` 没有 journal，本次仍明确拒绝自动恢复，原始失败副本未修改。断电、磁盘损坏、网络文件系统、其他主机/PID 复用、敌对并发写入不由本验证覆盖。发生冲突保持现场，不能删除事务目录来跳过恢复。

raw-manifest.json 按原字节绑定 223 个记录；完整 SDK 包和失败项目的二进制保留在外部路径，不在原始日志中重复分发。原 preview.11 的 Win7 关闭、续期页面与 V04 失败均未因本修改解决，既有 C++/GUI 结果不迁移到本候选。`sourceDeliveryVerified=false`、`benchmarkValid=false`、`releaseReady=false`。
