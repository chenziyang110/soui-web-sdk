# ADR-0017：版本分支整合与固定 SDK 身份

日期：2026-10-08。状态：accepted；用户明确要求合并现有 PR。

## 背景与决定

公共桌面服务、续租、安装恢复、公平调度和 Agent/现代后端从同一基线分叉。使用保留祖先关系的合并提交整合，不重写共享历史；各分支的实现和冻结证据同时保留。重复的 ADR 序号沿用原文件名，引用以完整路径区分。

原生 Bridge 组合文档白名单、动作输入/输出校验与 permission_store 解析得到的 scope。回调不能接收调用者伪造的 scope；续租只有实际被授予时才返回 lease。撤销会话后在锁外等待任务释放。现代安装在恢复或写入项目之前检查所需公共组件。

最终 SDK 与发布的 0.4.0-preview.1 内容不同，整合使用 0.4.0-preview.2。旧标签、固定 SDK 和发布包不覆盖。各历史冻结验收仍绑定原版本；当前完整交付和生产状态不继承。

## 备选与迁移

整文件选择某一分支会丢失权限或生命周期能力；只移动版本号会造成固定身份冲突，因此分别组合契约并使用新 preview。C++ 使用源码编译，新增公共服务继续显式启用；Web 客户端同时保留能力发现、语义动作与可选续租。业务项目须按标准 SDK 安装流程升级并重新构建。

## 验证

增加原生动作/续租/白名单和现代档位/安装恢复的组合回归。现代模板显式启用续租和最小文档白名单；现代传输与业务共用有界队列，不能继承旧后端业务满载时的专用续租槽保证。执行 Web 构建与审计、双架构原生契约及两后端短启动；原始结果归档。此次合并不发布新安装包，也不关闭 Win7/PE 全矩阵、高刷、长期资源、授权及签名门槛。
