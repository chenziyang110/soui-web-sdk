# 0.5 资源与生命周期根因调查

日期：2026-10-08。审计基线为 `05e7d93b6bb36904cfabaea6147552b4d62dfb70` 的 0.4.0-preview.3；本记录随后补充本轮诊断结果所有权修复。**本轮只完成源码审计和实现/测试编写，没有运行 GUI、重编依赖、长测或实际内核复现。** 新原生测试运行结果由集成构建另行绑定，不在这里填写通过值。没有修改固定 DLL、已有 0.4 SDK 包、历史原始报告或验收状态。

## 调查入口与可信边界

通过外层项目的 `specify-runtime learning start --command analyze --format json` 消费 Learning，匹配并展开 `soui-sdk-demo-tests-production-value`：从公共 SDK 到独立消费者和真实失败证据追踪，不能把 Demo/模拟/短测视为生产结论。补充 owner/consumer/timeout 上下文的查询未匹配到新规则。GPU 白三角、灰色多边形和 dirty-clip 等 Learning 的触发条件没有在本次故障中出现，未套用这些修复。

Project Cognition 路由提示 graph store 缺失；工作区没有独立项目图。未启动用户未调用的映射 workflow，以下事实以已列出的 live 源码和历史归档为准。

## 首批可验证的修改

### A. 已实现：诊断超时结果的栈引用

`sdk/src/host/soui_miniblink_host.cpp::request_memory_recovery()` 原来用 `[&result]` 捕获局部 `host_result`。`engine_thread::invoke()` 默认十秒等待后返回 false，已接纳工作并不会取消，因此迟到回调可写已结束的栈。

本轮按 [ADR-0022](../adr/0022-diagnostic-result-lifetime.md) 改为 `sdk/src/host/diagnostic_result.h` 私有 helper：任务持有结果与工作，只有完成确认后读取。超时、拒绝、异常保持 `E_ENGINE_THREAD`；真实工作返回的 `E_GC_API_MISSING` 保留。回调不捕获 Host/adapter。未改变 FIFO/关闭契约或 GC 策略。

`tests/native/engine_thread_timeout_tests.cpp` 共用真实 helper，在实际 engine FIFO 以 promise 阻塞首项，验证短期限返回先于迟到工作，然后放行、验证闭包归还和失败不可变；另覆盖执行中超时、成功、原生失败、异常及停止后的拒绝。不用 Sleep 排交错。**尚未执行；root 统一注册并构建。** 该诊断宏专用缺陷不能解释没有启用该路径的历史挂载失败。

### B. 待分配：自定义光标所有权补丁

- `WebPageImpl.cpp` 的最后一份 `m_platformCursor` 未在页面销毁释放；标准 `LoadCursor` 返回共享句柄，必须和拥有的自定义句柄区分，不可一起 DestroyIcon。
- `PlatformCursor.h` 非 alpha 分支重新声明 `andMaskDC`/`xorMaskDC`，遮蔽外层待清理变量，创建的两个 DC 离开作用域没有释放。该分支条件是系统版本不高于 Vista，正常 Win7+ 不走它；可用独立构造 helper 的故障/分支注入覆盖，不能拿它解释 Win11 GPU 样本。
- `hCursor` 来源是 `PlatformBitmap` 所有且已选择进 surface 的 bitmap。应消除错误的借用释放尝试，保持 PlatformBitmap 管理原位图，并为 CreateIconIndirect 的输入建立明确的选择/借用边界。
- Microsoft [CreateCompatibleDC 文档](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-createcompatibledc)明确允许用 DeleteObject 删除 HDC；不能仅凭 API 名称把现有 `DeleteObject(workingDC)` 判为泄漏。建议 DeleteDC 是表达所有权，不是此项根因。
- Microsoft [CreateIconIndirect 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-createiconindirect)说明返回句柄由调用方 DestroyIcon，输入位图复制但仍由原所有者管理，并要求输入 bitmap 不正选在 DC 内。

建议文件所有权：`content/ui/PlatformCursor.h`、`content/browser/WebPageImpl.cpp`、独立新补丁与诊断消费者。复现需页面明确设置一份 CSS image cursor，实触发 WM_SETCURSOR，记录拥有句柄的创建/销毁成功、每轮窗口关闭后 USER/GDI，并区分不生成 custom cursor 的对照。仅 SetCursor 消息次数不能证明每次创建新对象。正确释放时序须先使 cursor 不再使用，不能销毁仍在显示的 cursor。修改上游后需要两架构新候选 DLL 和补丁来源，不替换固定 prebuilt。本轮没有改这些文件。

### C. 待分配：内核线程启动失败与状态同步

`WebThreadImpl.cpp` 未检查 CreateEvent 或 _beginthreadex 失败，随后 `while (!m_hadThreadInit) Sleep(20)` 无限等待。_beginthreadex 返回 null 时没有线程会设置该标志；这是能用创建函数失败注入稳定验证的源码缺口。CreateEvent 失败还会令 worker 的等待返回失败，当前没有分支处理。

`WebThreadImpl.h` 的 `m_hadThreadInit`、`m_willExit`、`m_threadClosed` 是普通 bool，多线程读写缺少 C++ 同步；Sleep 不建立状态发布关系。建议使用原子或创建/退出事件明确发布，并对所有资源失败配对清理后返回失败；不能简单给构造循环加超时然后释放仍被新线程访问的对象。

这是历史 x86 stall 的**候选机制**，不是已捕获根因。优先先记失败状态与创建 error，再做故障注入；需要上游小补丁、新候选内核和两架构验证。没有必要现在重编全部依赖碰运气。

## 仍须现场验证的路径

1. **x86 mount/驻留**：同一冻结 EXE/内核/资源根、参数与门限，在新日志目录启用 `SOUI_ACCEPTANCE_MOUNT_TRACE=1`；独立消费者现有阶段记录区分构造/窗口创建/Host start/ready 等待，配置同架构调试器在监督器杀进程之前保存所有线程。slot 2 失败须记录 adapter/文档/Bridge 身份、script context/ready 的阶段。Workbench 开 `SOUI_DIAGNOSTIC_SCRIPT=1`、`SOUI_BRIDGE_TRACE=1`，保留原 45 秒门限。不能仅重编成功或把 20/45 秒延长就关闭故障。
2. **合成关闭阻塞**：`LayerTreeHost` 析构会等待进程共享 RasterTaskWorkerThreadPool 的 pending 数归零、apply/draw counters、compositor shutdown。共享 raster 的等待可能被其他窗口持续提交影响；需在关闭 A/保持 B 活跃的故障栈记录 task owner、计数和线程心跳，先证明依赖边界。不能贸然把全局等待换成逐窗口等待而释放 B 仍借用的对象。
3. **菜单**：自动 timer 与真实托盘/快捷键输入分开；两种消费者 owner 当前都可隐藏。增加 owner/root 的 IsWindow/visible/enabled/process/thread、foreground HWND/线程、当前输入 desktop 和触发源，记录调用前后；[SetForegroundWindow 官方契约](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)允许合规条件下仍被拒绝，且没有文档化 LastError 根因。隐藏 owner 是需验证的条件，不足以直接认定根因。不要强抢前台、忽略 E_MENU_FOREGROUND 或伪造 trusted gesture。
4. **GPU USER**：在相同 fixture 下记录每轮完整窗口（含 message-only）、cursor/icon/menu 与 Skia 创建释放类型、线程归属，关联关闭前后对象计数。当前 native interface 装配未走 SkWGL 的 dummy-window 路径，`GrGLGpu` 的额外 SwapBuffers/GetDC 位于禁用的 SWAP_PER_DRAW；这两处不能当作实际调用根因。

## 缓存与泄漏的判定及后续验收

M0 先冻结每条后端/架构/设备的预热、采样点、静置、采样频率、分段趋势算法和缓存/增长预算。采样至少分为 WebView 活跃、全部 WebView 关闭但 Runtime 存活、Runtime 显式关闭；现代后端要包含完整子进程树。报告对象类型、归属和同候选回收周期，不只看 Private Bytes 首尾或退出码。

软件路径先记录自然 GC/缓存周期，若使用 memory recovery 诊断，把它作为独立实验条件，不混入默认通过样本或靠强制 GC 掩盖增长。持续增长且没有生命周期所有者/释放解释才进入泄漏定位；平台常驻池需说明数量与上界。当前证据既未证明软件泄漏，也未证明缓存预算合格。

小修复的无窗口回归通过后，根因候选再按单改动、绑定消费者/源码/DLL/完整载荷进行短对照，随后双架构 100 次重载、1,000 次生命周期和 8 小时混合负载。GPU 默认软件回退和实验身份保持；不把任何短样本、单机/VM 或 8 小时退出 0 自动改为资源、兼容或生产放行。
