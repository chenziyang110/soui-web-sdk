# 就绪任务调度策略回归

后续实际内核结果见 [x86 完整重编与原动画实测](../scheduler-fairness-x86-rebuild-2026-09-26/README.md)。以下保留策略测试执行时的范围。

关联 [Issue #35](https://github.com/chenziyang110/soui-web-sdk/issues/35) 和 [ADR-0016](../../../docs/adr/0016-scheduler-ready-task-fairness.md)。候选从提交 `0872075ec45d07b1428719725a8ffbcdd5d962de` 建立；此记录只证明提取出的真实选择策略，尚未证明新内核或 SDK 生产能力。

旧策略在 x64 首次测试中因“已到期的加载任务被新普通任务持续压住”退出 1，采用遇错即停的测试版本。随后 x86 使用保留全部失败的十二项版本，实际报告五项失败、退出 1：50 ms 边界、已久候加载、多个久候任务的顺序、idle 等待、连续补充普通任务。两份旧策略及各自测试源码均保留，不能把 x64 首次结果称为完整十二项失败检查。

候选保留短暂突发的原优先级；等待达到 50 ms 的就绪任务优先，多个久候任务按到期先后选择，相同到期仍按优先级。它不承诺端到端 50 ms 上限，也不改变未来任务的资格或退出清理原规则。该 helper 直接被 `WebThreadImpl::schedulerTasks` 调用，测试未另写一套替代实现。

候选 x86、x64 均实际配置、编译、运行退出 0，各十二项检查覆盖正常优先级、同级时序与相等键、退出清理、50 ms 两侧、loading/idle 长等待、持续动画提交和未来任务排除。两份绿色源码快照与当前候选字节一致。

[94 份原始文件](raw-manifest.json)保存各架构红绿源码、实际构建命令、编译链接配置、原始输出/退出码和[复核结果](raw/policy-review.json)。完整内核依赖重编另行记录，不把仍在运行的构建日志归为终态，也未替换固定 DLL。SDK 版本暂未变化；实际二进制进入交付时必须升级完整候选版本并刷新依赖身份。两架构完整底层重编、原动画页面、真实应用、Win7 和全部生产门槛仍待验证。
