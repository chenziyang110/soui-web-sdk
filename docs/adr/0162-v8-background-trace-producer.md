# ADR-0162：登记 V8 系统线程池诊断 producer

- 状态：采纳，x86/x64 作用域合同已验证，实际内核复验待执行
- 日期：2026-11-05

## 背景

M01 的 0.6.0 基线发送完整 3,750 个指针事件后，kernel recorder 报告两次未注册写入。新的冷生命周期快照将一次受控复现定位到 Host destroy 成功之后、Runtime shutdown 完成之前。原始失败仍有效，不能据此免除 source_loss。

在未修改的 K0 内核上，普通堆 CDB 数据断点捕获同一线程依次将 unregistered_writes 从 0 增至 1、2，两处均为 recorder 的原子自增；不是进程卸载时的堆填充。调用栈经过 gin::WorkItemCallback 的 task->Run。K0 回调完整 35 字节与有 MAP 的独立内核中该具名函数逐字节相同，使用各自 RVA 定位，没有借用其他内核地址或把最近导出符号当作真实函数名。源码通过 QueueUserWorkItem 进入此回调，却没有 WebThread 入口已有的诊断登记。

## 决定

只在 gin::WorkItemCallback 的已知系统线程池入口，使用内部 background_producer_scope：没有现存登记时调用现有冷 register_current_thread；只撤销本作用域成功取得的登记。已登记调用方的 producer 和 context 保留。复用已有 TLS slot 的 resume 规则，不修改记录器容量、ABI、计数器、FIFO、task ownership 或退出期限。

登记异常记录 causal loss，随后仍执行原任务；登记被拒绝不会伪造成功、跳过原有 trace 写入或消除 source_loss。作用域析构包含异常退出。不在通用 postTask、输入或 record 热路径自动登记，不新增线程、队列或后台服务。

## 备选方案

- 忽略关闭阶段计数或将失败改成通过：拒绝，会隐藏真实来源缺失。
- 在所有 task post/record 上惰性登记：拒绝，会扩散热路径分配与锁竞争，并掩盖未知 producer。
- 为 V8 新建受控线程池：本问题不需要，生命周期和体积影响过大。

## 兼容性与迁移

内部诊断修复，不增加公共 API、权限或最低工具链要求。默认业务任务内容和所有权保持原契约。32 个 producer 的进程生命周期上限仍存在；超限、停止后的登记和仍在运行的后台任务必须继续导致诊断不完整。新构建使用新开发版本与独立载荷身份，不覆盖历史 SDK 或旧内核。

## 验证与回退

用实际 Win32 工作项和原 recorder 验证登记、作用域退出、重复 TLS 复用、嵌套既有 context、异常和拒绝路径。执行受影响两架构编译与定向内核运行；同身份的无调试器 3,750 次输入及正常关闭用于验证来源完整性。调试器记录只定位故障，不计性能分数。旧失败、调试器扰动与所有未测项保留。回退时撤销回调作用域、内部头及对应测试，恢复旧诊断缺失限制，不放宽验收门槛。
