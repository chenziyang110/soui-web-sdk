# ADR-0113：软件单进程的缓存观察预算

日期：2026-10-16。状态：已实现；预算在正式八小时执行前冻结。当前 x64 有限资源运行已校准，x86 在更新后的完整候选上验证。

## 背景

0.5 路线图要求队列/缓存有冻结上限、完整进程范围没有未解释增长、退出按契约回收。现有命名缓存容量、容器所有权与 TaskStore 分配额度覆盖不同对象；仅把命名缓存相加会遗漏分配器留存、外部借用和其他容器，重复归属也可能重计。当前长期分析中的 cacheBudget 一直保留未评估，没有完整实现。

当前软件路径已有有界 VirtualQuery 观测：最多 50 毫秒或 32,768 个区域，返回范围、分类、进程/线程身份与开始/结束时钟。扫描非原子，部分结果明确不完整。这些限制继续适用。

## 决定

为实际 Owned 记录证明只有一个进程的兼容软件路径，采用完整进程 committed 地址范围作为保守的进程内缓存字节包络。MEM_PRIVATE、MEM_MAPPED、MEM_IMAGE 全部相加，不扣除代码、栈或推断为非缓存的内容。已提交的进程内缓存、容器和分配器留存在该范围中；映射类别在 copy-on-write 后可能不变，不能只看 private。

固定观察预算为 1 GiB（1,073,741,824 字节），两架构一致。这一数值已在正式长期运行前选定，不随正式结果调整。历史校准只能支持工程预算选择，不能授权本次通过。32 位结果不保证存在同等大小的连续可分配空间，不代替低内存设备测试。

这是一项完整范围的采样预算，不是各缓存的分配硬限额、原子时刻总量、唯一物理内存或逐缓存所有权证明。对象账本与末态回收、命名缓存配置和覆盖、TaskStore 128 MiB 请求硬额度、Private Bytes/句柄/线程/GDI/USER 趋势、逐小时动作延迟、真实八小时和自然关闭仍是独立必需门槛。不得用包络通过掩盖其中任一失败或未知增长。

所有 sample 均纳入，包括启动、尾周期与关闭；不得挑选最低点或只取稳定段。缺失、部分或范围不符保持未评估；非法身份/时钟/总和、重用扫描或超额失败优先。完成扫描距父采样至多 180 秒，相邻完整扫描不允许复用 QPC；同一 owner 上的新扫描不得早于上一父采样的完成时钟，父时钟不得倒退。原采样、小时数量、间隔、趋势与所有执行预算保持不变。

新读者先校验原始 UTF-8 NDJSON 字节散列，再检查源清单、载荷、消费者构建、EXE、Owned/context、实际 PID/FILETIME 与架构。汇总入口使用完整绑定和原始样本重新计算，拒绝手工修改的 gate、peak、scope 或样本。纯数据重放仅证明分类逻辑，不能证明文件来源或实际八小时。

## 备选方案

- 仅累加若干命名缓存：覆盖不完整，不能承担总范围预算。
- 给所有第三方分配器加硬限额：涉及分配失败语义和兼容性，当前没有完成的实现，不能作为本版已具备能力。
- 用工作集或 Private Bytes 替代：工作集会受系统回收影响，Private Bytes 不包含全部 mapped/image；两者仍可独立观测，不能冒充相同范围。
- 永久保持占位项：无法执行完整的采样预算判断；保留未知所有权的局部诊断，同时实现上述清楚限定的范围判断。

## 兼容与迁移

不改变公共 SDK API、运行时分配、缓存配置或页面行为，不强制 GC、压缩工作集、清空缓存或周期重启。长期策略版本显式从 v3 更新为 0.5.0-m0-software-cache-envelope-v4。旧原件和旧结果仍按原策略解释，不就地追认为通过。GPU、多进程 WebView2 和其他系统需要独立规则，不适用本决定。

## 验证

原集成回归在占位实现上真实失败；追加的父时钟倒退/新扫描早于前次父采样的用例也先复现误判通过，再修复。新增边界与原有资源/所有权/TaskStore 回归共 131 项已通过。当前 x64 有限运行的 114 个采样均完整、新鲜且低于既定预算，原资源门通过。x86 有限验证安排在更新后的完整候选上，并在正式八小时之前完成；不因预校准结果修改预算。缺失/非法/超额分支和来源检查保持不变，短资源运行不能代替八小时。采用后冻结新源码、策略与运行输入，再执行适用正式长期负载。只有全部独立必需门槛通过，长期整体结论才可通过。
