# ADR-0124：有界异步资产读取与会话撤销

状态：开发分支决定，未发布。

## 背景与决定

ADR-0123 的小文件限制限制内存，但不能保证文件系统 I/O 延迟。资产读取移到
进程共享的两个工作线程，最多16个未完成作业（包括等待 UI 交付的结果）。
不为每个窗口或请求创建线程。队列满时以 `asset_queue_full` 拒绝 Promise，
现有 `readAsset(path)` 调用及成功结果格式不变。

每次导航创建独立取消令牌；导航、关闭和析构撤销令牌，移除尚未开始的作业，
晚到结果不会交付旧页面。取消是取消排队/交付，不保证中断已经开始的系统调用。
正在读取的作业仅持有复制的根、路径、取消令牌和独立完成通道，不能持有或销毁
原生窗口/应用对象。进程级工作状态独立生存，不在 UI 线程 join 阻塞 I/O；
即使旧窗口销毁或新应用组创建，工作线程上限仍是两个。
进程单例刻意不注册退出析构，避免全局 application 在单例销毁之后撤销会话；
这两个线程与有界共享状态由进程退出回收。独立测试执行器可停止，停止只撤销
排队/结果交付，不等待进行中的文件读取。

完成通道通过短临界区向既有线程安全 backend dispatch 投递；UI 在关闭/析构前
撤销通道，避免工作线程与 backend 销毁竞态。投递后的结果仍经公共串行回调队列
并核验原窗口、导航代际和接受状态。导航、关闭不能等待文件读取结束。

## 兼容性与限制

默认关闭、256 KiB、可信且不可被不可信进程修改的资源根、严格路径和 MIME/base64
契约不变。同步业务 invoke 不变；仅资产读取异步。页面卸载仍由现有 pagehide
拒绝待处理 Promise；被撤销页面不接收新的原生取消通知。没有新增硬取消 API，
不将 Promise 超时解释为操作系统读取已被中止。若两个系统读取长期阻塞，新的
作业可能饱和并失败，但不得拖死窗口或无限增加线程。不是完整文件系统沙箱。
若原生 UI 投递队列拒绝完成消息，结果释放且不重试，网页按既有30秒超时失败；
不能承诺每个已接收作业在 UI 已不可投递时仍能送达明确错误。

## 验证

使用确定性门闩验证真实工作线程、饱和、取消排队、运行中撤销、非阻塞析构及
关闭竞争；真实文件读取回归保持。公共 fake backend 验证 UI 完成交付、
刷新/关闭后无晚回调及窗口隔离。真实 GUI 和其他目标平台仍须实机验证。
