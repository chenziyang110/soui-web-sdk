# Actual controlled Host startup regressions

These three finite tests use the normal public SDK and a caller-hidden real owner. Hidden start must confirm the actual uncancelled kind3/scope0 OLE registration and quiet pre-navigation drain before publishing a session, then observe at least two real public page-port calls. Sent WM_CLOSE during startup must cancel without publishing a session. The two-Host case retains A's real document while stored A engine-call QPC events fall strictly inside B's actual registration fence. Each case retains Host, Bridge, HWND and initialized module owners until real close/drain/join; timeout is not cancellation.

Enable the parent option SOUI_BUILD_HOST_STARTUP_FENCE_TESTS explicitly and supply absolute SOUI_HOST_STARTUP_KERNEL plus its exact lowercase SOUI_HOST_STARTUP_KERNEL_SHA256. There is no successful no-kernel mode. Resources, navigation logs, receipts and MAP are created in the build directory. Each CTest has TIMEOUT35 and RUN_SERIAL; Root's outer owned-process runner is still required for authoritative held PID/creation FILETIME, whole Job closure and deadline validation.

Normal soui_sdk is compiled once from all 25 production sources, without any observer definition or insertion. This consumer compiles a generated startup_observed_host.cpp containing exactly six pinned read-only insertions over the actual production Host bytes. The consumer uses the normal archive for the remaining SDK objects. The mandatory post-link MAP gate requires the generated private object and rejects extraction of the normal soui_miniblink_host.obj archive member. Source hashes, exact SDK inventories, the six byte spans and generated whole hash are checked before configuration and compilation. This is a test composition, not a production SDK seam.

The same fixture body and resource first passed three direct cases plus serial CTest3 in private x64/x86 builds that substituted the observer Host in the SDK archive. Those historical results did not prove this public consumer's MAP composition. Root then freshly built and ran the normal archive and public composition on both architectures: all three direct cases and three serial CTests naturally returned0/0. Actual CL24/OBJ24, the two private consumer objects, the full absolute archive path in LINK.read and the required MAP contributions were independently checked. Configure/build root0/supervisor124 compiler tails still remain generic-false. A read-only readiness wait invokes bootstrap once when the public port exists; it never retries actions, replays navigation, disables renewals or loosens admission.

This slice does not qualify invalid timer recovery, every OS/Win7, general GC/OOM rollback, long-duration resource trends, initialized DLL unloading, complete toolchain provenance or a release. The SDK and consumers require rebuilding after the private Host layout change; old binary ABI compatibility is not claimed.
The input gate explicitly canonicalizes only CRLF to LF before checking byte length and SHA256. Lone CR, encoding and every other byte remain significant. The manifest records both the observed raw values and approved canonical values; only canonical values govern portable source equality. The generated Host uses the canonical production source and exactly six canonical unique spans. This handles Git text normalization without allowing substantive changes.

The source inventory is deliberately frozen at 98 inputs, 25 SDK CPP, 16 private headers and 33 public headers. The preceding dual-architecture observations used the earlier 24-source composition; the explicit GUI adoption refresh changes only six existing native input pins and adds three GUI inputs. The six Host insertions and generated Host bytes remain identical. This 25-source composition requires a fresh actual build and run before inheriting any finite test result. Pending GUI or other SDK changes must receive a reviewed explicit manifest/span refresh and fresh build. There is no automatic source-count/hash bypass. This finite source composition does not qualify an installed Host consumer or a release. See ADR0053 for the two actual summary identities and preserved failures.
