These nine regressions cover the bounded registry ownership and C++ lock-unwinding repair in ADR0042.

The endpoint test includes an exact byte range generated from the current vendor `wke.cpp`, from its unique `InteractionEndpointImpl` declaration to the unique `retainInteractionEndpoint` declaration. Supported fragments must be NUL-free, use LF-only line endings and end in LF. CMake rejects CRLF, mixed CR bytes and a missing terminal LF before generation; it never appends, trims or normalizes source bytes. It checks both markers, verifies exact generated bytes before either test target builds and reconfigures when `wke.cpp` changes. The test uses leaf view/compositor doubles and does not embed a second implementation of the registry algorithm.

The activation test compiles the actual vendor `net/ActivatingObjCheck.cpp` with its actual header. It injects STL allocation failure, then uses another Win32 thread to query and update the same registry. A blocked thread is reported as a failed diagnostic process; the test does not destroy the critical section beneath it.

There are seven endpoint cases and two activation cases, each with a 10-second CTest timeout. Every case must pass; there is no expected-failure CTest flag or separate baseline implementation. Fault-injection diagnostics remain failures when run against the old production code.

These tests prove narrow allocation and lock behavior. They do not qualify real Blink object creation, concurrent endpoint use in the full engine, constructor rollback, native resource drain, PartitionAlloc exhaustion, GUI, target-system compatibility or release readiness.
