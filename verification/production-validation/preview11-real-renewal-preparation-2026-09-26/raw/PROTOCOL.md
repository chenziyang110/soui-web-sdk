# InstalledRenewalProbe: real-clock public SDK continuation probe

This external fixture consumes the frozen preview.11 SDK (compile source a0c1d7900d39555508288d5459e65d3852e543cf7ec3879126bd6af59d2c2550). It must not modify the SDK/development checkout. Preparation/build/self-check does not prove GUI or elapsed-time success.

Native target: `InstalledRenewalProbe`, public installed `Soui::Sdk` only, normal Win32 owner with `soui_miniblink_host`, one host mount, explicit `json_bridge.enable_session_renewal()`. No reload, bootstrap retry, fake clock or shortened native lease. Native CLI: `--runtime ABS_DIR --report ABS_NEW_FILE --duration-ms N`, where N is exactly 30000 (harness smoke), 2100000 (35 real minutes), or 28800000 (8 real hours of this scenario, not the full mixed-business gate). `--self-check` is a no-GUI command validating CLI/logging helpers and returning the SDK version; it must not initialize Runtime/COM/create HWND. Run/output/report identities are frozen before GUI execution, report must be outside runtime and new.

Methods, all registered before bootstrap:

- `probe.describe {}` -> `{runId,durationMs,version,architecture}`. First authenticated request binds sessionId/origin/authorization scope; all later probe methods must use identical live identity.
- `probe.ready {}` -> `{}`; called once after both tasks and subscription are established, native tracks count and logs it. A second call fails the run.
- `probe.record <object>` -> `{}`; native records bounded params as JSON text string `dataJson` (maximum 16384 bytes) alongside authenticated sessionId/origin and `sameAuthorization:true`. It does not log request token. The result acknowledges durable logging; logger errors must fail, not be swallowed.
- `probe.finish {}` -> `{}`; only after Web has confirmed both result retention, long task cancellation and original unsubscribe ACK. The UI loop owns shutdown after this handler unwinds; native may delay 500ms for delivery, but that is not a claim that this final ACK reached the page.
- `probe.fail {message:string}` -> `{}`; bounded diagnostic and nonzero native termination; expired authorization may prevent this call, so native watchdog is still necessary.

Task kinds: `probe.long` input `{}` reports progress/message every second with real monotonic elapsed, cooperatively stops on cancellation, hard bound duration+90000ms; `probe.result` input `{}` immediately returns `{value:42}`. Native counts and logs invocations separately, each must be exactly 1. Task worker logging must be thread safe and callback state must outlive workers. An application-owned public bridge_adapter decorator may record task event JSON before forwarding; events contain this fixed fixture's data, never bearer tokens.

Web uses the frozen built public Web SDK and exactly one standard `connectSouiNative()` connection. Instrument the application's injected port only by a synchronous forwarding wrapper which returns the same native result and records white-listed protocol metadata; do not change responses, deadlines or business calls. Observe original native subscriptionId from subscribe ACK; no SDK private fields/getters. Record single document nonce, bootstrap count, start/subscribe counts, current lease generation/relative expiry, the fixed two task IDs, original subscription ID and event sequence. No polling-only success: require continuing progress events, same session, strictly increasing received sequences, same subscribed handle and actual post-original-30min evidence for the 35min/8h modes.

Web sends `probe.record` objects with `kind` in `begin`, `protocol`, `heartbeat`, `complete`, `failure`; native records them without logging secrets. `begin` includes documentNonce, longTaskId, resultTaskId, subscriptionId, initialGeneration. `protocol` includes a bounded array of request/response observations (method/requestId/operationId/ok/errorCode/sessionId/taskId/subscriptionId/generation only). `heartbeat` includes elapsedMs, same identities, lease, eventCount,lastEventSequence,lastEventElapsedMs,querySequence,bootstrapCount,startCount,subscribeCount,documentNonce. Heartbeat every 5 seconds queries both tasks; completed result must stay value42, long task running. Client errors, multiple bootstrap/start/subscribe, changed identity, event silence over 15000ms or renewal generation regression fail. This is a functional deadline, not a latency/performance claim.

Clarified evidence fields: protocol request records also carry task kind and input operationId for task.start, taskId for task.query/cancel/subscribe, subscriptionId for unsubscribe. Response records carry the matching requestId/method plus actual task.query state, sequence and resultValue (42 only when present), task.start accepted/duplicate/taskId, task.cancel cancelRequested/state, task.unsubscribe removed/subscriptionId, and native sessionId/origin/generation on bootstrap/renew. These are observations of actual responses, not an alternative implementation of the SDK. Metadata rows never copy token or complete response bodies. Analyzer must correlate each response to exactly one request and native `task.invoked` kind/operationId/session, and independently confirm cancelled query, retained result and unsubscribe removed=true before accepting complete.

Each metadata observation includes observedElapsedMs from the same document performance clock. A rejected renewal transport is recorded as transportError:true/errorCode:E_TRANSPORT without inventing a native response or preempting SDK retry; terminal onError remains failure. Report observed recovery spans and >25-second observations without treating scheduler timing as proof of an exact recovery deadline. Require the bounded attempt count and stable operation ID. Flush bounded observations during preparation/cancel polling; do not truncate or enlarge the 128-row limit. The final heartbeat waits for a fresh progress event within the original 15-second silence bound, avoiding a false failure from a shortened final sleep.

Runtime evidence may exclude exactly the root source-navigation.log produced by the frozen Host. The supervisor must preserve its full raw bytes outside the runtime and bind length/hash/archive path; the analyzer checks both copies. No other new runtime file is allowed. Reusing a runtime appends that diagnostic: analyze and archive each result before a later run; a subsequent live-file validation of an older snapshot is expected to reject drift and does not erase its previously preserved evidence. All executable/library/resource files still require exact before/after manifests. Synthetic verifier inputs always remain separately labelled and never authorize real runtime success.

Clock rules: native `probe.describe` first event is the conservative initial-expiry reference; because it is authenticated after bootstrap, describe.elapsedMs + 1800000 is an upper bound for the original lease expiry. First ready.elapsedMs is the run-duration start; Web starts its duration clock after the ready ACK. For long modes, native complete-record time minus native ready time must be >= configured duration. At least one native progress event after the conservative initial-expiry bound must be received by the Web and referenced by a later heartbeat; cross-match the exact session/task/eventName/sequence, and require that later heartbeat also passed both real queries. Do not count a stale lastEvent carried across expiry. Native and Web time origins must never be numerically compared without the explicit native record correlation.

At duration, require generation>=2 when N>=2100000 and >=20 when N==28800000 (25-minute scheduled renewal); retained task/result and events must also be observed beyond the original 30-minute expiry. Cancel the original long task, await cancelled state, await original subscription.unsubscribe(), re-query retained result, record `complete` with final counts/IDs/lease and `cancelled:true,unsubscribed:true,resultValue:42`, then finish. Smoke must explicitly say realRenewalVerified=false.

Native NDJSON envelope: `{schema:"soui.renewal-probe/v1",seq,elapsedMs,event,...}` with mutex-protected strictly increasing seq and monotonic elapsed. Events: `run.started` (duration/version/architecture/runId), `host.mounted`, `probe.describe`, `probe.ready`, `web.record` (dataJson/sessionId/origin/sameAuthorization), `task.invoked` (kind/count/sessionId/operationId), `task.stopped` (kind/reason), `native.event` (dataJson), `resource.sample` every 5s, `probe.finish`, `host.destroyed`, `runtime.shutdown`, `run.finished` (exitCode,readyCount,longInvocations,resultInvocations). Failure events never become pass on cleanup. Native checks initial ready within 60s, maximum post-ready record gap 30000ms, overall duration+120000ms; resource samples are observations with no resourceGate approval. UI pumps continuously. No actual desktop run until all external QEMU/SDK loads are absent.
