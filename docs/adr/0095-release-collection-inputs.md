# ADR 0095：发布汇总的编译档位与冻结输入

状态：proposed（实施中）；当前候选尚未发布。

## 背景

当前候选使用显式 LLVM22/MSVC142 档位，测量工具也有该档位的独立准备
记录。汇总入口却省略测量请求，默认按 MSVC143 读取。SDK-only 的汇总
还只检查构建记录，未调用已有的完整已接受构建读取器。

完整源码清单包含发布文档和验收记录。构建观察器把其活动路径作为永久
控制输入，后续收集记录并刷新源码清单后，历史编译证据便因清单字节变化
失效。生产源文件、实际编译依赖和完整源码归档有不同的核验时点。

## 决定

- 汇总入口新增显式 `--native-toolchain LLVM22MSVC142`；默认 MSVC143
  保持原行为。每架构测量命令必须传递该仓库内对应的准备请求，由现有
  读取器核验实际工具和档位。未知、缺值和重复选项明确失败。
- SDK-only 汇总调用完整已接受构建读取器，不能只看原生编译成功字段。
- 应用、Modern 和 SDK-only 构建读取均显式传递所选档位及对应架构、配置
  的请求路径，拒绝从已有记录自动推断另一档位后混入同一汇总。
- 构建捕获时保存完整源码清单的不可覆盖副本，并验证活动清单在实际
  构建及观察期间未改变。后续读取验证该副本与输入记录的绑定，以及
  当前生产源码、真实依赖、工具和载荷的既有完整检查。
- 上述副本只描述构建时的输入，不能认证后来生成的整个源码包。最终
  归档仍须在报告、文档完成后刷新并实际验证完整源码清单。旧记录保留
  原来的活动路径检查，不能追认为新捕获格式。

## 兼容性与验证

新增 CLI 选项不改变默认档位。源码变化仍要求重新编译，不能通过修改
汇总配置或更新元数据接受旧二进制。所有实际失败和缺失证据继续阻止汇总。

回归覆盖参数边界、两架构实际命令传参、不可变副本篡改、错误绑定、构建
期间活动输入变化和旧格式拒绝。候选重新构建、实际测量和汇总仍须执行；
纯数据测试不构成编译、GUI、长期或发布验收。
