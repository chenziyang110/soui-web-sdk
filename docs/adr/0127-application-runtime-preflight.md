# ADR-0127：应用运行依赖诊断与启动错误

状态：开发增量，诊断不等于运行验收。

## 决定与边界

应用目录附带不依赖 Node 的 doctor 脚本：Linux/macOS 使用系统 shell，Windows
使用 PowerShell（不修改执行策略）。staging 工具生成固定代码/建议和 manifest
入口；Linux launcher 在执行应用前运行只读诊断，明确阻塞时停止，unknown 不
冒充缺失或通过。应用本身可能尚未加载就因动态库缺失退出，因此仅在 SDK 内
增加检查不足以覆盖启动失败。

诊断不运行待检查二进制、不执行 ldd、不安装运行库、不提升权限、不更改环境
安全配置。Linux 库缓存/常见 helper 候选只证明发现候选，不能证明 ABI、加载
路径或任意发行版布局；Windows 注册表发现不等于可加载，未发现也不能证明
不存在固定版本 runtime；macOS 系统框架可在 dyld cache 中，不能以独立文件
不存在判为缺失。原生后端使用支持的运行时发现 API 给出更准确错误。

输出固定状态码和操作建议，不记录环境变量值、资源 URL、绝对用户路径或应用
数据。默认不写持久日志，可由用户将 doctor 输出重定向保存；不捕获或宣称
过滤应用自身 stdout/stderr。返回0仅表示无已知阻塞，1表示已确认的阻塞；检查
工具不可用以 unknown 输出，不自动绕过系统策略。

## 兼容性、备选和验证

不新增公共 C++ API；保留显式路径和原生安全/来源策略。只生成静态依赖文本
无法帮助无输出启动，执行目标二进制/动态加载器扫描则不适合作为可信诊断默认。
重点检查生成脚本语法、固定状态码/退出行为和 Linux 实际环境结果；Windows/
macOS 真实诊断和完整回归留待统一验收，不以候选发现代替目标运行通过。
