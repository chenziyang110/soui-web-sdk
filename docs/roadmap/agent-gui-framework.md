# 模块化 GUI 与 Agent SDK 建设路线

日期：2026-10-02。目标：以 C++ 原生能力为底座、Web 为主要界面，让人和 Agent 都能开发、使用和维护桌面应用。当前支持边界仍为 Windows/MSVC，当前引擎仍为 Miniblink49；所有未来项均需独立验收。

2026-10-03 增量：增加 [WebView2 独立实验消费者](../../experiments/webview2-consumer/README.md)，复用 preview.9 固定 SDK，双架构重载与Controller销毁重建共40轮通过；R01 的监督器改为单调计时并增加每轮能力发现，Miniblink四场景双架构共80轮回归通过。[实际结果与失败证据](../acceptance/webview2-experiment.md) 保留未验收门槛；完整 R01/R02 仍须按下表补齐证据。

## 工作包与完成条件

| 顺序 | 工作包 | 实施范围 | 完成证据 |
|---|---|---|---|
| F01 | 渲染边界与发现 | 本轮：移除普通宿主操作对具体适配器的转换；发现已注册授权方法；Web 校验；模板接入 | 自定义适配器测试、真实原生发现、Web 测试、独立消费者及当前源码启动证据 |
| R01 | 当前版本可靠性 | 沿用 0.3 计划，定位长循环超时、资源趋势、退出问题，保留软件默认 | 可复现根因与回归；1,000 轮生命周期和 8 小时持续运行；原始资源样本与源码/载荷身份 |
| R02 | 现代后端验证 | 先建立 WebView2 实验消费者；验证导航、生命周期、可信 origin、消息、输入法、DPI、无障碍、离线部署 | 同一公共业务在两后端运行；差异与能力矩阵；真实设备输入、启动、占用与部署数据 |
| D01 | SDK 开发流程 | 统一创建、检查、开发、构建、测试、打包、升级；适用命令提供结构化输出；预构建包与源码构建分工 | 全新目录/机器接入、升级回退、锁定身份，Agent 可据错误码定位失败 |
| A01 | 统一动作契约 | 从一个明确的业务契约生成类型、校验、文档、工具定义；先实现一个可完成的任务 | C++/TS 一致性测试；发现→执行→进度→完成→取消/失败路径；无 Demo 私有依赖 |
| A02 | 界面语义与授权 | 稳定控件 ID、角色/名称/状态、动作、等待条件；UIA 适配；Agent 身份与授权策略 | 普通用户与 Agent 完成相同流程；受限动作拒绝；页面不能伪造手势；记录不含凭据 |
| P01 | 专业扩展 | 按需媒体/设备/数据库/AI 模块；数据通道与控制消息分离；有需要时进程隔离 | 模块独立消费者、数据压力/取消/崩溃恢复、增量体积与支持范围 |
| X01 | 平台扩展 | 平台接口稳定后，逐个平台实现原生窗口、输入、文件/设备服务与部署 | 每个平台独立构建/真实运行/发布支持矩阵，不以编译通过代替支持 |

R01 与 R02 可独立推进；实验后端不得改变当前应用默认。A01/A02 可复用 F01，但方法清单本身不提供参数 schema、业务前置条件或 Agent 操作授权。领域扩展按使用需求选择，基础包不默认携带专业依赖。

## 性能与体积

复用 [0.3 测量协议和拟定门槛](0.3.0.md)，先完成同设备、同数据、同窗口数、同功能的 Electron 对照。记录冷/热启动、真实输入到呈现 p95/p99、帧时间、Bridge、整进程树 CPU/内存、重载及关闭趋势。显示差距与失败样本；性能目标不写成既有结果。

分别报告应用下载增量、首次完整安装、离线分发、安装后占用与运行内存。系统 WebView 运行时、可选模块和内核都单列，不能只计算 EXE 或业务脚本。大型图形/媒体优先使用专用数据通道，不能靠扩大 JSON 消息上限获得专业吞吐能力。

## 专业交付

每个公开能力建立“公共契约 → 独立消费者 → 实际场景 → 测试证据 → 支持限制”链条。目录所有权、SDK 与 Demo 分离保持不变。稳定版还需要关闭目标系统、输入法、多屏、无障碍、安装升级回退、依赖维护及再分发等适用门槛。后端变更和公共 ABI/权限变更先写 ADR。

本路线没有承诺同一个包同时覆盖所有操作系统、现代浏览器功能、旧设备、硬实时与专业图形需求；每个交付档位以实际能力与验证矩阵描述。
