# ADR-0167：合并 WebView2 活动 drain 内的输出通知

状态：候选源码已实施，独立源码审查通过；SDK4基座上的私有renderer完成v143/19041 x64三TU构建、10项策略合同及原真实WebView2容量/关闭回归。新源码版本为 `0.7.0-preview.5`，最终SDK载荷须以自身的构建、安装和验收记录核验；上述私有原型不授予其输入、帧率、公平性或发布资格。既有SDK包保持不可变。

## 背景

`webview2_adapter::pump()` 在进入时清除 `wake_pending`。Bridge worker 的 `push_output()` 在当前 drain 的 COM 调用期间仍可入队并再次投递 payload-free owner 消息；即使该输出随即被同一 slice 消费，已投递的消息也无法撤回，产生额外空 pump。2ms/16项单次预算不能解决这种重复通知，更不能证明跨 slice 的消息类别公平性。

R42持续负载已出现输入尾部晚到及绘制/定时器长间隔，但缺少消息来源的完整归因。队列状态查询可能改变合法宿主的等待语义；固定10ms timer和内部paint续跑也各有成本或公平性缺口。本项不引入这些机制，不将减少重复通知描述为已修复整个持续负载问题。

## 决定

1. 增加私有、受现有输出队列mutex保护的 `output_pump_active`。只有取得外层 `owner_pump_guard` 的 drain，在既有队列临界区内准备取第一项时才进入活动状态；空 pump不增加锁或设置活动标记。
2. `push_output()` 保留原接纳、字节账本、generation复核及FIFO。仅当处于活动drain时暂不投递**输出**通知；所有非输出生命周期、错误和关闭通知继续走原 `wake_owner()`，不受此标记限制。
3. 已进入的栈上退出作用域在原尾部使用的同一mutex内清除活动标记，检查是否仍有输出，并按原 `wake_owner()` 至多补一次通知。生产者在此之前入队由退出路径负责；在此之后入队由生产者负责。异常、预算耗尽、重入导航及关闭均不能跳过这个退出路径。未进入drain的正常空pump仍保留原尾部mutex/queue检查：首次观察为空之后可能已有生产者入队且首次PostMessage失败，不能因lazy scope删掉旧代码的第二次通知机会；该检查不新增相对旧实现的锁。
4. 标记属于外层drain作用域，不属于文档generation。导航清队列、stop或嵌套pump不得提前清除或拥有它；退出对象在 `owner_pump_guard` 释放之前结束。既有 `wake_pending` 不因队列空而在尾部清除，避免吞掉生命周期通知责任。
5. 不更改lane选择、跨lane优先级、COM前释放admission credit的时点、原业务deadline、过期/撤销/关闭行为或COM owner STA。无新增线程、timer、队列状态查询、消息抽取、同步派发、业务payload或公开API。

## 备选与不采用范围

保留原代码会继续允许同slice的冗余通知；该代码可作为工作量对照和局部回退。单纯缩小单slice预算会增加通知频率，不作为此问题修复。此前pending-state/低优先timer草案未通过默认采用审查，其等待语义、跨实例token与吞吐代价不由本项顺带解决。

## 兼容与回退

只减少已经由当前活动drain承担的输出通知，不删除回复、输入、生命周期消息或已有通知。公开类型、Bridge协议和发行最低系统/工具链不变。原 `PostMessage` 失败后的进展限制保持未扩大的原边界；本项不宣称解决该失败路径。回退时同时撤回生产接线和私有helper，保留原始失败及两侧工作量证据。

## 最小验证

复用 `sdk.native.webview2-owner-policy`，直接测试生产退出作用域，覆盖：同slice全部消费时不补冗余通知；预算剩余输出只补一次；入队在退出前/后的通知责任；COM重入被拒后外层仍负责；异常退出；导航/stop清队列且新代际入队时不丢通知；非输出通知不受抑制；首次空观察后入队且首次native post失败时保留原normal-tail通知机会。测试使用真实mutex/有界线程交错及原15秒期限，不以复制生产算法的模型代替。

编译受影响renderer与原生目标，适用时执行真实Host容量/关闭回归。仅在有当前候选和新的具体假设时补持续负载对照，保持原负载与期限；原R41/R42的tag0 veto、Finish边界及失败不改写为通过。减少实际通知调用数的证据与宏观输入/帧率收益分开报告。
