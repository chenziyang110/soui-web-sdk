# ADR-0008：公共 SDK 长任务服务

- 状态：proposed；双架构原生契约与模板编译已验证，真实页面和维护者评审待完成
- 日期：2026-09-25
- 关联：[ADR-0004](0004-web-connection-lifecycle.md)、[0.3 验证方案](../roadmap/0.3-sdk-validation.md)

## 背景

Bridge 已能异步回送普通请求，但长任务的运行、进度、取消和订阅仍由 Demo 适配器自行管理。页面连接器有 `task.*` 便捷调用，标准 `json_bridge` 此前并没有相应实现；新业务项目复制 Demo 代码才能使用，无法作为公共 SDK 能力验收。Bridge 的请求工作线程也不能承担长时间业务执行，否则取消和普通请求会在其后排队。

## 决定

1. `json_bridge` 内置 `task.start/query/cancel/subscribe/unsubscribe`，在 Bridge 验证会话、来源和能力授权后，把完整的已认证请求交给 `task_service`。业务仅在 bootstrap 前注册处理器；页面无权注册原生代码。
2. 服务维护固定的两个工作线程、最多 32 个未完成任务和 128 个订阅。超过容量明确返回 `E_BUSY`；不为每个任务创建线程。Bridge 自身的请求/回送容量仍独立生效。
3. 任务按 session、origin、token 归属。相同会话中 `operationId` 与相同 kind/input 的重试返回原任务；不同请求内容返回冲突。导航和会话撤销取消未完成任务、删除订阅并拒绝旧令牌访问。
4. 取消采用协作式协议：取消请求先置位，处理器通过 `task_control` 检查并退出后才确认终态。关闭服务会等待处理器退出，因此处理器必须定期检查取消并限制自身阻塞；SDK 不提供强制终止线程或业务事务回滚。
5. `task_store` 保存最多 1,024 个任务，超出时仅淘汰最早终态。结果为不超过 32 KiB 的 JSON 对象，消息最多 4 KiB；结果仅在内存中保留，不承诺进程重启后恢复。页面侧事件的序号使用任务状态序号，迟到的旧事件不会覆盖较新的终态。
6. 公共 TypeScript 映射声明与原生实现一致。模板用一个可取消计数任务展示原生处理器、页面调用、进度事件和查询兜底。Workbench 旧任务适配器暂保持独立，不能把它的扫描或媒体能力计入公共 SDK；迁移时应按业务数据归属逐项处理。

## 验证与限制

原生契约覆盖授权后的任务启动、进度查询/事件、结果、取消、重复请求、32 项准入、超量拒绝、结果边界与会话撤销，并分别在 x86/x64 编译执行。模板页面的 Chrome 49 目标构建和 x86 原生构建通过。真实宿主点击路径、独立安装工程、Win7 SP1 x86、连续业务负载和 Demo 迁移仍需单独留证；这些缺口保持 0.3 preview 的生产准入未通过。
