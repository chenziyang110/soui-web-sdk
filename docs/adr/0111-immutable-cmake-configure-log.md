# ADR-0111：保存每次构建的独立 CMake 配置日志

日期：2026-10-16。状态：实现已整合，待新候选的实际完整构建。

Source24 的 x64 Debug 构建及 187 项原生测试通过后，同目录的 Release 配置改变了 `CMakeFiles/CMakeConfigureLog.yaml`。该日志由多个配置共用。Debug 桌面入口随后按原始散列拒绝读取，报 `Pinned bytes changed`；此次失败保留，不能追认为 Debug 桌面通过。Release 两架构的桌面与现代后端记录仍通过其原有读取器。

在原 LLVM 观察器完成实际编译/链接观察时，把共用日志原字节复制到该次观察目录的 `cmake-configure-log.input.yaml`。新文件必须不存在，来源必须是普通文件，长度为 1 至 64 MiB；复制后和写出最终观察前均核对来源与副本。记录包含原路径、原散列、长度和副本路径。后续读取严格约束来源路径、观察目录、实际观察器 argv 中的输出路径及唯一副本 pin。

这只改变追加型诊断日志的保存方式。当前 CMake 缓存、编译器记录、编译数据库、Ninja 配置、源码/头文件、对象、资源、归档及链接产物仍按原规则核对。旧记录没有副本绑定时继续要求旧的 live pin，不补造旧日志或修改旧失败。历史增量观察也必须校验原始副本绑定。新增两份辅助源码纳入观察器代码散列清单。

独立原生探针实际执行两次 LLVM CMake fresh 配置，共用日志确实变化，首次副本字节保持不变，重复捕获拒绝覆盖。整个探针自然退出 0/0。读取器夹具覆盖后续追加、捕获期间 live 重检失败、路径/散列/长度替换、缺失或重复副本、混入 live pin、错误输出 argv，以及损坏副本；这些夹具不等同于完整 SDK 编译。实际 Source24 失败与探针记录均保留，最终四配置桌面验证须在整合后重跑。

安装验收和发布消费者共用的读取器同样核对副本归属及原始观察器参数。两项回归先复现旧适配器忽略该字段，再验证篡改、错误路径、缺失/重复副本和错误 argv 均拒绝；该组 16 项通过。辅助源码已由共同的控制源码清单继承绑定，未另设放宽路径。
