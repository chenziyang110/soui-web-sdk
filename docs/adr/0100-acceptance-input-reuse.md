# 0100 — 单次验收核验复用实际已验证输入

状态：已实施；Source16 两架构实际消费者及完整 100 重载入口均自然通过。

## 背景

真实 100 次重载已自然结束，但外层验收在重复扫描输入时超时。
`currentRecords` 经 runner、installed reader 和 nativeInputs 多次核验同一
SDK 与工具清单。重复读取占据了整个执行预算，不能通过省略输入校验解决。

## 决定

installed reader 的 `verifyWithInputs` 执行原有完整核验（含末尾重新核验），
返回本次实际获得的 SDK 上下文。runner 的 `verifyInputs` 保留原 Web、SDK、
运行载荷、安装目录、消费者源码和内核检查。私有 `nativeInputs` 使用本次
返回值；每次完整绑定核验仍重新读取输入，不跨调用缓存或接受 JSON 的通过声明。

保留所有 pin、目录清单、记录集合比较和 runtimeRunner 的独立校验，
以及 freeze、分析和最终复核。旧 `verify` 返回格式、MSVC 路线和原生步骤期限不变。
外部执行器总预算须覆盖准备、原生协议的最坏期限和后置分析；实际超时仍保留失败。

## 备选、兼容与迁移

拒绝取消文件校验、跨运行缓存和缩短测量协议。新增内部返回上下文不改变
公开 SDK API；旧调用者无需迁移。新源码需要重新生成输入清单和实际构建证据，
不能沿用旧源码的通过标记。

## 验证

在实际函数体上覆盖每次调用重验、各类输入漂移拒绝、旧返回格式和架构路线。
运行相关 LLVM、资源与发布 reader 回归，再构建安装 SDK 和独立消费者，
执行真实重载。模型测试不构成原生或发布资格。
