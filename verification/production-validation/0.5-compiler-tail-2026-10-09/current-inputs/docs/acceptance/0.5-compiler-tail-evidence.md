## 覆盖

- console-free Win32 fixture 不创建窗口。ready event 与 held process/FILETIME 明确确认子进程已启动，避免用 Sleep 判断同步。
- 唯一 pinned helper 全部身份与同时持有的磁盘对象相符；真正终止 whole held Job，≤1s等待真实 process signal，再取两次空 accounting，固定 pre-cleanup total 不更新。
- 同 bytes 的另一个磁盘对象拒绝；两个和九个成员完整记录且拒绝例外；九个成员实际触发列表扩容。
- pin 持有期间 write/rename 被拒绝，正常 root/Job 关闭后可打开与 rename；已有 writer、junction/reparse 目录、超过64MiB文件在创建 subject 前拒绝。
- 独立 TEST_ONLY API response target 覆盖成功但截断、普通 count 变化、重复 PID/零洞和第一次 image ACCESS_DENIED；不把合成响应冒认本 OS 实际返回。
- 独立 TEST_ONLY mutation target 在 cleanup 调用点真实增加并 Assign suspended process，随后真实 TerminateJobObject；最终 total +1而固定 total 不更新，证据拒绝。不宣称复现生产调度。
- 独立另一个 owned process 在被测失败清理后仍存活，随后按自己的 finish-file 条件自然关闭；没有按名称或裸 PID 广杀。
- hash不匹配、opt-in不全/重复不启动 subject；正常默认无pin没有snapshot事件或新增terminal字段，v1首行客户端契约保持。

## 复核入口

在该独立目录执行 `node out/tail-validation/run.cjs native` 只产生自己的新测试进程、复制自己的 fixture、创建自己的 junction/输出，使用 held Jobs 并写新 UUID raw。它不编译、不运行窗口、SendInput、VM 或实际 vctip。`legacy` 复核既有 console tests，`vctip-pin` 只固定实际 MSVC 磁盘对象并运行 brief fixture，均不构成实际 compiler-tail 接受。`build` 会最小重编独立 out，不得在只读审查中运行。

新的最小原生目标位于 out/tail-x86/Release 与 out/tail-x64/Release：OwnedProcessRunner、OwnedTailProcessFixture、OwnedTailMutationFixture、OwnedTailApiFixture；OwnedProcessAssignmentFixture 仅保留原测试依赖。Native test env 的真实路径与 SHA 均在每个 attempt/inputs.json，外层报告保存本轮 executable/runner SHA 与准确启动参数。
