# 0.3 SDK 中期准入判定

日期：2026-09-24。候选：`0.3.0-preview.5`。本文件只汇总已执行证据；不是正式发布批准。完整门槛见[验证方案](../roadmap/0.3-sdk-validation.md)，逐能力缺口见[能力矩阵](capabilities.md)，原始结果按 run-id 保存在 `verification/production-validation/`。当前 `releaseReady: false`。

| 必须回答的问题 | 当前判定 | 决定性的现有证据与缺口 |
|---|---|---|
| SDK 能否独立交付 | **部分通过，尚未形成完整交付通过** | preview.5 [双架构完整构建、三项 smoke、仓库外生成项目及无 Git 完整源码搬移后重新构建](../../verification/production-validation/preview5-task-capacity-2026-09-24/README.md)已通过。preview.5 的[Win7 x86 QEMU 四模式公共消费者短测](../../verification/production-validation/win7-sp1-x86-qemu-preview5-consumer-2026-09-24/README.md)已通过；preview.4 的[x64 Release 业务小样](../../verification/production-validation/preview4-upgrade-2026-09-23/README.md)升级回退仍保留原候选身份；新版 x86 Bridge 长循环两次超时，物理目标机尚未执行。底层依赖的搬移后源码重编译、Debug 和目标机交付仍未闭环。 |
| 指定范围能否生产使用 | **未通过** | preview.4 已将修正 HTTPS 校验的内核纳入固定包，[双架构 12 项正负向测试](../../verification/production-validation/preview4-fixed-2026-09-23/README.md)通过；[新固定包生命周期记录](../../verification/production-validation/preview4-lifecycle-2026-09-23/README.md)完成双架构各 100 次重载及四种模式各 1,000 次，但所有资源门仍未评估，三窗口与 Bridge 分段内存总体上升。GPU 关闭曾出现访问冲突，历史双架构 GPU 重建 30 轮仍有 USER 对象逐轮增长且 Runtime 关闭后残留。[GPU 专项](gpu-lifecycle.md)未达到资源门槛。preview.5 的[任务表容量硬边界](../../verification/production-validation/preview5-task-capacity-2026-09-24/README.md)已有双架构测试，但公共任务业务链还未完整验收。[Win7 SP1 x86 QEMU 四模式短测](../../verification/production-validation/win7-sp1-x86-qemu-2026-09-24/README.md)与[模板/Demo 三项短测](../../verification/production-validation/win7-sp1-x86-qemu-apps-2026-09-24/README.md)仅对应 preview.4；[preview.5 的 Win7 SP1 x86 QEMU 三应用入口短测](../../verification/production-validation/win7-sp1-x86-qemu-preview5-apps-2026-09-24/README.md)已通过；[新版四模式公共消费者三轮短测](../../verification/production-validation/win7-sp1-x86-qemu-preview5-consumer-2026-09-24/README.md)已通过，任务满载业务仍未执行。8 小时混合负载、物理 Win7 x86 设备与 DPI/IME、完整业务任务、实际信任根/代理、授权和旧 TLS 组件维护仍缺证据。 |
| 相对 Electron 的采用价值是否成立 | **未测，不能判定** | [共享页面与双端最小宿主](../../benchmarks/README.md)已可构建，[三份结果落盘探针](../../verification/production-validation/benchmark-host-smoke-2026-09-23/README.md)确认写入链路；Electron 精确版本已锁定。尚未取得正式两端配对运行、输入到呈现、帧间隔、进程树内存、完整包体积和维护工时原始样本。不能把较小的单个 DLL 或主观流畅性当作产品价值结论。 |

preview.5 的[固定载荷 x86 生命周期复测](../../verification/production-validation/preview5-lifecycle-2026-09-24/README.md)新增明确阻塞：Bridge 目标 1,000 轮两次分别在第 86 和 977 轮挂载阶段超时，监督器终止进程；同载荷后续三次诊断完成 1,000 轮，其中一次保留原 20 秒门限，一次并行自有 QEMU 快照。成功样本不能覆盖失败，且均未捕获停滞栈。100 次重载的 Private Bytes 末点增量 7.0 MiB，低于 16 MiB 数值线，但句柄与线程增加且资源整体门未评估。两次超时与其他 QEMU 负载重叠；可控 QEMU 负载测试通过，说明并行 QEMU 本身不是充分复现条件。根因仍需抓栈定位，Win7 虚拟机内目前也只有短测。

[带阶段日志的另一诊断载荷](../../verification/production-validation/preview5-mount-phase-2026-09-24/README.md)在 x86 宿主完成 3 次预热加 1,000 次 Bridge、无超时，并保留 10,030 条逐阶段事件；第 977 轮这次通过，8 秒停滞观察器未触发。其源码/消费者载荷与上述冻结失败样本不同，不能用这次成功消除生产阻塞。该诊断运行的每百轮 Private Bytes 中位数约 79.4→96.0 MiB，资源归属仍未解释。

下一阶段按风险顺序收敛：先定位 x86 Bridge 长循环超时和 GPU USER 残留，完成当前公共连接器的双架构生命周期/资源门槛；并行补齐公共任务、桌面模块与六组 Demo 场景；随后冻结共享负载与 Electron 宿主，完成同机性能/体积对照；最后跑 8 小时、目标设备与安装升级回退、安全授权和发布责任审核。每阶段保留失败样本，改变源码或内核后重跑受影响项。正式报告仍分别给出工程交付、指定范围生产和采用价值三个结论。
