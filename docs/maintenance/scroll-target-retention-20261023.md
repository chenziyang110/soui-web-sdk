# 已接纳滚动目标在临时覆盖边界处的保留

核对日期：2026-10-23。**第二版 Controller/Snapshot 主回归已在 x86/x64 通过，完整 x86 内核编译及文件绑定核验通过；真实宿主返回、取消关闭可用，但滚动过程中 epoch 改变，目标守恒及 producer 闭环验收未通过。** 原始反例及首版的两项边界失败保持记录。独立覆盖收缩反例在旧基线与首版修复上仍真实失败，不计作主回归通过，也不属于已解决范围。

设计、生命周期与资源约束见 [ADR 0119](../adr/0119-preserve-scroll-target-beyond-raster-coverage.md)，构建和隔离运行入口见 [测试说明](../../tests/native/scroll_target_retention/README.md)，公开的架构、源码与测试散列及结果见 [验证摘要](../verification/scroll-target-retention-20261023.json)。这些文件不修改全局发布或验收状态。

## 可复现的缺陷

测试直接编译生产 `ScrollController.cpp` 与 `ScrollTreeSnapshot.cpp`，使用固定单调时间。真实内容范围为 `[0,1000]`，初始已准备覆盖为 `[0,300]`，依次接纳 `+250` 非平滑输入和 `+100` 平滑输入。同一 scroll epoch 的覆盖扩展，分别在第二次输入之前和运动之后发布；两种时序都应最终到达 350，中间可视位置始终不得超过当时已准备覆盖。

旧基线两架构结果一致：

| 覆盖扩展时序 | 实际终点 y | 已接纳输入 | 所有记录状态在覆盖内 | 结果 |
| --- | ---: | ---: | --- | --- |
| 第二次输入之前 | 349.99999925233919 | 2 | 是 | 通过 |
| 运动之后 | 299.99999936159156 | 2 | 是 | 失败，预期 350 |

两个进程均退出 1。预期 RED 只说明测试用于复现缺陷，**不反转退出码，也不将失败算作通过**。恢复后的每架构 610 条状态记录均完成覆盖检查，stdout 散列与隔离来宾记录相同。这个反例证明 Controller/Snapshot 层会丢失已接纳距离；它不证明某次 GUI 的结束内容差异必然由此引起。

## 最小修复方向

旧实现将输入预测和运动目标裁到真实内容与临时 raster coverage 的交集。输入被整体接纳后，临时覆盖以外的目标没有独立保留，后续扩大覆盖也无法恢复。

当前补丁把逻辑目标与可绘制位置分开：逻辑目标只按真实内容边界裁剪，可视位置和插值仍受已准备覆盖限制。平滑与非平滑输入都累加到同一个逻辑目标；停在临时边界时不空转，新的 ready scene 允许运动后恢复。覆盖等待的墙钟时间不参与恢复首帧积分；连续同 epoch ACK 不应反复重锚而阻断运动。

接纳仍要求合法身份、epoch、序号、有限输入、正尺寸 viewport、资源资格，以及朝候选目标方向的已准备余量。反向输入按候选目标相对 base 的方向判断，不能机械按 raw delta 符号拒绝。真正到达内容末端且没有待完成距离时仍应回退。新身份、新 epoch、成功同步 barrier 与明确撤销继续取消旧目标。

`LayerTreeHost` 在激活 ready scene 后重新汇总动画需求，防止场景激活恢复了目标却没有后续帧。既有 resource fence、实际覆盖限制和 producer 链保持；没有新增定时轮询、扩大预取预算或绕过主线程原因位。单元测试不运行这些真实 raster 和调度路径，静态链路存在不能代替集成验证。

## 首轮修复：原反例通过，边界仍失败

| --- | --- | --- |
| 原始目标保留 oracle | 2/2，退出 0 | 2/2，退出 0 |
| 新增目标与接纳边界 | 17/19，退出 1 | 17/19，退出 1 |
| 既有覆盖与浮点回归 | 13/13，退出 0 | 13/13，退出 0 |

原始测试源码与旧基线字节相同，晚扩展终点恢复为 `349.99999936159156`，没有放宽原断言。六个测试进程退出完整，恢复的 stdout/stderr 散列匹配来宾记录；整套运行仍为失败，退出 1。

边界失败项是 `real-content-bounds` 和 `saturated-target-noop`。已静止的 base 可能比真实 maximum 小约 `7e-7`，逻辑目标却已等于 maximum；首版严格不等比较把这段无法形成有效采样的舍入尾差当成在途目标，额外外向输入错误返回已接纳。该定位来自失败断言、状态和源码核对；不是通过修改测试结果得到的通过结论。

失败后，尚在进行的首版完整 x86 内核构建被受控停止，已运行 375.532 秒，退出 124，进程闭合确认、活动进程为 0。该构建没有通过，输出和失败记录保留。它不能用作首版或第二版的完整内核成功证据。

## 真实滚轮：epoch 连续性中断，闭环未通过

同一隔离系统的旧覆盖内核与新目标内核各接收 8 条原生滚轮输入，原始 wheel delta 均合计 `-960`；转换后的已接纳请求 y 均合计 `+800`，8/8 接纳、无 fallback、无日志丢弃，smooth 均为 1 条关闭、7 条开启。实际输入跨度分别为 701.2638 ms 和 660.0938 ms，并非完全相同的调度负载。只读探针在引擎 pump 后以不快于 100 ms 的间隔读取 controller visual/consumed；这些值不是 DOM 位置或屏幕呈现，亦未记录逻辑目标和真实内容末端。

| 观测 | 旧覆盖内核 | 新目标内核 |
| --- | ---: | ---: |
| 输入前 visual y | 0 | 0 |
| scroll epoch | 1 → 7 | 1 → 6 |
| 最后观测 visual y | 226 | 203 |
| 最后观测 consumed y | 0 | 0 |
| 尾部静止采样 | 20 条 / 2373.2148 ms | 19 条 / 2249.4535 ms |

各进程内 view/document/geometry 与节点 31、node generation 1 保持，epoch 发生变化，观测链因此中断；节点编号只是进程内身份，不用于跨进程建立全局同一性。这里保留最后观测值，**不将它们认作已完成的逻辑终点，不跨 epoch 相减推算丢失距离，也不据此判定新旧流畅度优劣**。返回、关闭可用和局部单元通过均不足以解除这个真实集成问题。

本补丁目前只证明同 epoch Controller/Snapshot 的目标保留，不能阻止已有新 epoch 取消规则。epoch 重置原因仍在排查；真实 producer/raster/激活唤醒闭环、完整 GUI、性能和完整 x64 内核没有通过结论。公开摘要保留源码、内核及脱敏证据散列，未替换固定预编译包，也没有提高发布就绪结论。

## 独立限制：覆盖收缩后再扩大

另一个既有反例针对同 epoch coverage 突然缩小到不包含当前 visual，再扩大时累计 consumed 与位置校正的关系：可能重放旧位置或反向校正。它与本轮“临时扩展导致已接纳目标丢失”分开跟踪，目前没有纳入已解决范围。

该反例通过默认关闭的 `SOUI_BUILD_SCROLL_CONTRACTION_DIAGNOSTIC` 构建。已实际完成旧基线/首版修复 × x86/x64 四项独立对照，使用同一测试源码，SHA-256 `DBEB5391C0F506645FFFB142F864A9B4D469D397510BEF16A7A9570FC07E338A`。四项均为 0 通过、1 失败，实际退出 1：覆盖缩小到 200 时 visual 为 200，扩大到 400 后、尚未执行动画 sample，visual 即重放到 250，触发 `coverage-shrink-expand-no-replay` 断言。输出和来宾散列已核对，保留真实失败，不使用 `WILL_FAIL` 倒置，也不计入主回归通过数。

该对照的旧 Controller 是 `196A0E1A7D45DD9D930436712A6740A62348D7F1CEECCAA99A5D1958C5F08DD6`，新 Controller 是首版 `23624807419B68681A374AA7EA4D8F3F432B03694C3135163140F6580A24B41F`，**不是**第二版 epsilon 修订 `3C0D…DEF8`。它证明收缩重放在旧基线和首版均存在；不得把它写成第二版已实跑的结果。本次保留该独立限制，不扩称任意 viewport 变化或覆盖收缩都正确。
