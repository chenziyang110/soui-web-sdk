# ADR-0004：标准 Web 连接器与请求生命周期

- 状态：proposed；首批实现、双架构独立消费者短测及应用回归已完成，长稳与维护者评审待完成
- 日期：2026-09-22
- 关联：[Issue #23](https://github.com/chenziyang110/soui-web-sdk/issues/23)、[完整验证方案](../roadmap/0.3-sdk-validation.md)

## 背景

模板自行调用 `bridge.bootstrap`，把返回类型固定为 string，事件端口为空实现。实际 Host 对 bootstrap 返回字符串，对普通请求返回 Promise。Web SDK 已有请求关联和页面超时，但缺少统一连接器、dispose、请求上限、可观察的订阅失败及完整注销竞态处理。Demo 又维护另一套客户端。独立消费者发现返回类型误判，说明模拟端口测试不能替代实际原生连接。

Host 的普通请求进入独立 Bridge worker，因此长方法不会直接占用页面引擎线程；但现有队列无容量上限，单个无界方法仍会阻止该 worker 处理取消和退出。现有 `task.*` 类型包含 Demo 业务字段，类型声明不等于公共 `json_bridge` 已提供这些方法。

## 决定

1. 公共 Web SDK 提供唯一标准连接入口，统一 native discovery、严格 bootstrap 校验、真实事件接线及错误。模板和新的验证页面使用该入口；Demo 按业务适配器逐步迁移。连接返回 Promise，兼容 bootstrap 的同步返回和普通调用的异步返回，不使用忙等。
2. 每个文档的连接具有明确所有权。重复连接不得重新 bootstrap 或覆盖别人的事件分发器；同一客户端不能把另一个会话的响应或事件交给业务。初始页面脚本早于 document-ready 执行的路径也必须可用。
3. 为客户端增加显式 dispose：幂等地停止接收新请求、拒绝仍在等待的请求、移除本客户端事件监听和计时器。重载/页面退出触发相同清理。不得用“页面不再等待”冒充原生任务已经取消。
4. 页面超时、页面 dispose、原生取消请求及原生确认取消是四个不同结果。长任务取消仍通过原生任务句柄；只有任务服务确认终态才显示已取消。原生任务服务和调度器的公开设计另立 ADR，不在连接器里复制 Demo 的线程代码。
5. 请求数量和消息字节数均有限制，超限返回明确错误。第一版以公开可配置的请求上限服务至少 32 并发；容量内请求完成、失败、超时和 dispose 后都释放页面槽位。Host 必须另有队列容量和过载返回，不能仅靠合作的 Web 客户端保护 native。
6. 订阅必须可观察建立失败；移除幂等，移除早于订阅响应时，迟到成功需要补做一次 native unsubscribe。错误事件、非当前会话、重复/乱序序列和移除后的消息不触发业务回调。业务回调抛错不得中断其他订阅。
7. Host 保存的 Promise resolver 有明确上限和销毁策略；页面等待结束后不允许无限保留 resolver。跨重载响应按 document generation 丢弃。事件进度允许按任务合并，但任务终态和关键错误不得被静默丢失。
8. 通用协议类型与业务方法映射分开。新的 SDK 功能只能在其原生模块公开可用并有独立消费证据时进入对应方法映射。现有 Demo 映射迁移时保留明确的兼容入口和文档，禁止把缺少原生实现的类型列为已支持能力。

首批 Web 接口细化：新增 `connectSouiNative`，同一 Window 重复调用复用一个连接 Promise，参数冲突或其他分发器占用时明确拒绝；连接失败或 dispose 后需重新加载文档，不能偷偷重新 bootstrap。自定义 port 继续支持，其可选 `dispose` 只负责端口自身清理。客户端 dispose 立即清理本地等待和监听，对已知及迟到订阅尽力发送注销，但不承诺原生任务已取消；需要确认注销的调用者等待订阅句柄的 `unsubscribe()`。

保留 `subscribe()` 返回值可调用的兼容形式，增加 `ready: Promise<void>`、`closed` 和 `unsubscribe(): Promise<void>`；旧式函数调用启动注销，新式调用可观察失败。订阅与普通请求分别有上限，注销使用有界控制请求容量，避免普通请求占满后无法发送释放操作。客户端默认最多 128 个普通等待、128 个订阅，消息最多 64 KiB；具体原生容量及队列清理随后以真实消费者验证。回调异常通过可选错误观察器报告并隔离。

Host 首批容量固定为每个 Host 256 个普通请求和 128 个释放/取消请求，涵盖排队、执行和等待回送的整个阶段；所有请求仍按 FIFO 执行，控制槽位不代表可以抢占正在执行的方法。重载不能重置仍占用的原生容量，同一文档的未完成 requestId 不得重复。排队期间已超过请求期限的工作不再启动，已经执行的业务不会因页面超时自动撤销。消息与响应各限制 64 KiB，JSON 深度限制 32。原生 Promise resolver 最多 384 个，完成、超时及页面退出均删除其记录和计时器；这些释放行为需通过真实原生消费者验证。

关闭 Host 时先停止接受新的原生请求，并等待引擎线程上的已进入回调越过屏障，再停止/释放 Bridge worker；不能在页面仍可调用 `post` 时从 UI 线程销毁该 worker。已在执行的方法仍必须具有业务自己的有界完成/取消机制。

回送到达引擎线程后，应在通知 JavaScript 完成之前归还请求槽位。V8 可能在 `wkeRunJS` 返回之前执行 Promise 的后续回调；如果一直等回送 lambda 析构才归还槽位，业务在已完成请求的回调里发起下一批请求，会少得到一个本应可用的槽位。显式归还必须幂等，旧回调对象随后析构不能释放同 ID 的新请求。

客户端 dispose 拒绝普通等待并移除其计时器；已发出或迟到建立的订阅注销仍允许使用有界控制请求，在确认或期限到达后结束。因而 dispose 之后的控制等待数量不保证立即为零。自定义 port 必须自行遵守同样的原生队列与等待期限约定。

## 备选方案

- 继续在模板和 Demo 复制连接器：失败与释放语义会分叉，独立应用无法复用同一验证结果，不采用。
- 将所有 native 调用变成同步：长调用占用引擎，违背 V01 的响应目标，不采用。
- 只加页面超时：不限制 native 队列、resolver 或任务寿命，无法通过生产资源门槛，不采用。
- 任意超时自动取消 native 任务：可能中断业务操作，也无法证明底层已停止，不采用。

## 兼容与迁移

保留现有自定义 `SouiNativePort` 接入方式。新增连接器、清理和订阅行为会更新类型、CHANGELOG 及模板调用示例；若调整旧 subscribe 签名或公共方法映射，必须提供明确迁移说明和验证。SDK 开发内容可继续修改尚未打包的 preview.3；一旦生成该版本 SDK 包，后续内容变化必须增加版本。

## 验证

- 单元层：异常 bootstrap、错误响应、乱序关联、异常事件、重复连接、双重移除、建立期间注销、dispose 与完成竞态、计时器与 listener 释放、超限恢复、业务回调异常隔离。
- 原生层：真实延时调用期间页面定时器继续推进；1/32 并发；事件建立和移除；重载后旧消息无效；关闭时仍有请求；使用原始 native 入口绕过客户端仍被容量限制。
- 回归：模板、Workbench 默认与 React、公共独立消费者。两架构运行边界测试；真实 SDK 模块完成前不以模拟 `task.*` 响应替代其验收。
- 长稳前核查当前凭据 30 分钟有效期：持续会话的过期、恢复与任务归属要有显式行为和测试，不能靠频繁刷新页面避开验证。

本 ADR 不授予 V01 或生产门槛通过。当前执行证据继续以[执行记录](../acceptance/progress.md)为准；标准公共任务服务、实际事件洪峰及取消语义仍需完成。
