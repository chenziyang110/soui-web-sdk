# ADR-0110：显式构建与绑定可选 UIA 交付

日期：2026-10-16。状态：实现已整合；独立安装已验证，最终公开入口验证待执行。

## 问题与决定

可选 `Soui::Uia` 已有 CMake 开关，公共构建入口却不能选择，构建记录也只收录 WebView2 可选库。三个入口统一支持显式选择：`Soui.ps1 build --with-uia`、`Build.ps1 -WithUia`、`standard-build.cjs --with-uia`。不选时每次明确配置 `SOUI_BUILD_UIA=OFF`，选中时为 `ON`，避免继承旧 CMake 缓存。

源码、SDK-only、生成应用沿用既有所有权和工具链规则。生成应用默认 MSVC 路径直接转发 PowerShell 开关，LLVM 路径沿用标准监督入口；不会自动接入业务 UIA 投影。旧 MSVC 编译器尾进程例外没有覆盖 UIA，因此拒绝二者组合，普通自然退出与 LLVM 的原有门槛不变。

构建记录根据当前 CMake 缓存，独立收录 WebView2 和 UIA 库。UIA 选中但缺库、请求与交付不一致、路径或当前文件被替换均拒绝。LLVM 还要求精确路径、长度和散列对应当前观察中唯一的 `ARCHIVER` 输出；无关输出、链接边和重复记录不能替代。

## 验证与边界

新增用例先在旧实现验证失败，再验证修正结果。实际运行了标准构建 46 项、LLVM 记录读取 13 项、Host64 观察读取 175 项、统一命令入口 24 项，共 258 项纯逻辑与文件夹具测试。PowerShell 入口通过语法解析。保留初次失败及后续结果，不将夹具成功写成真实编译成功。

随后独立构建了当前 SDK 核心及 ADR-0109 通知实现，两种架构都完成 ON 安装、逐文件核对后的目录搬移、外部 imported `Soui::Uia` 消费及 11 项原生用例；重新配置 OFF 并安装到新前缀后，REQUIRED Uia 配置均以预期非零拒绝。各阶段自然闭合。首个 x64 消费者因测试自身直接使用 JSON 却未声明 `Soui::ActionJson` 而编译失败，修正测试依赖后重跑，原件保留。

该安装探针走真实 CMake 和安装目标，尚未通过新增公共 Build/Soui 开关完成最终候选交付。上述探针使用原 Source24 核心及独立 UIA 实现，不能认证后续整合候选。合并提案另含 ADR-0111 的共用配置日志修复；组合回归为 306 项通过，1 项文件符号链接夹具因主机 EPERM 跳过，不能算通过。最终整合后仍须执行公开入口及四配置验证。
