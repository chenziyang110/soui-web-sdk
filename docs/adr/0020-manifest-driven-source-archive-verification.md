# ADR-0020：完整源码包按清单验证历史输出目录

- 状态：proposed，随 0.5 首批源码交付修复提交评审
- 日期：2026-10-08
- 范围：完整源码 `soui.full-source/v2` 的无 Git 文件集合检查

## 背景

完整源码清单以 Git 暂存集合和 blob 原字节生成。历史验证原件中有已经跟踪的 `raw/.../out/...exe`，但解压目录没有 Git 时，校验器复用构建输入扫描的缓存排除规则，跳过任何名为 `out`、`dist` 等的目录。结果是合法源码包在导出末尾复验失败；不能通过移动历史证据或改写清单掩盖这一差异。

## 决定

保持 v2 格式、逐文件散列、文本换行规范、版本检查和 Git 暂存区生成规则不变。无 Git 扫描根据清单确定必须包含的缓存同名路径及祖先；清单覆盖的 `out`、`dist`、`dist-legacy`、`node_modules`、`.vs` 等路径不能再因名称被跳过。

清单覆盖的缓存同名子树视为固定交付内容，遍历其完整子树，包括再次出现的缓存同名目录；未声明的文件仍使复验失败。未被清单覆盖的构建缓存子树继续按既有规则排除，构建输入身份扫描不变。排除入口先检查路径安全，不能借缓存名称隐藏符号链接或 junction；被排除的普通缓存目录内部不纳入源码完整性范围。

无 Git 文件集合仍必须与清单逐路径相等，缺失、额外或修改的文件均失败。路径逃逸、非法 Windows 路径、大小写冲突和已遍历路径上的链接继续拒绝。清单生成、源码导出和校验均不修改历史证据字节，也不扩大发布或生产验收结论。

## 备选方案

- 移动或删除历史原件：破坏固定路径和证据，不采用。
- 删除所有缓存排除规则：会将解压后合法构建产物误判为源码新增，不采用。
- 只逐项校验清单、不检查额外文件：无法发现未声明内容，不采用。
- 仅放行两个已知 EXE 或仅扫描清单中的单个文件：规则依赖具体历史路径，且会漏掉同目录新增内容，不采用。

## 影响

不改变 SDK 包格式、公开 API、ABI、系统或工具链要求。无 Git 校验新增少量由清单路径决定的扫描范围；冻结证据子树中的缓存同名新增文件不能再逃避集合检查。Git checkout 的检查和历史 v1 原字节校验保持原行为；新导出仍要求 v2。

## 迁移与回退

已有 v2 清单无需迁移，使用修复后的工具复验其对应原件即可。旧版本包和历史失败报告不覆盖；新的发布候选仍须重新冻结输入、生成清单、导出并复验。回退工具可能重新触发合法历史目录的误报，不能将回退后的失败视为历史字节已改变。

## 验证

使用临时 Git fixture 跟踪缓存同名目录中的原件，验证生成 v2 清单、导出到无 Git 目录、逐字节对比和再次校验；继续验证不在清单中的普通构建缓存可以存在。负向回归覆盖缺失原件、等长篡改、普通额外文件、固定子树内额外文件（包括嵌套缓存同名目录）、重复/逃逸路径和目录链接。

局部验证入口为 `node --test tests/sdk/delivery-identity.test.cjs`。完整发布仍需对最终候选执行清单导出、实际解压和无 Git 复验；局部 fixture 通过不能关闭该发布门槛。
