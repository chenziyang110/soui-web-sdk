# ADR-0125：显式启用的窗口本地 HTTP 资源源

状态：开发增量，未发布，真实三引擎验证待统一执行。

## 背景与备选

`readAsset` 只返回字节，不接管浏览器模块图和 fetch。继续 file URL 不能统一
系统引擎的来源规则；三端自定义 scheme 对标准模块/fetch 的语义不同且维护
成本更高。本增量选择内置小型 loopback 服务，不引入第三方库或放宽浏览器安全
设置，代价是本地端口、有限 HTTP 功能及额外目标机网络验收。

## 决定

保留默认 file URL，新增 `options.enable_resource_server`。启用时每窗口拥有独立
`http://127.0.0.1:<随机端口>/<随机前缀>/`，使用标准 HTTP 加载 HTML、相对资产、
ES modules、动态 import 和 fetch；不把自定义 scheme 的实现差异隐藏为兼容性。
服务器只绑定 IPv4 loopback，不监听外网，校验精确 Host，不提供 CORS 放宽。
请求只允许 GET/HEAD，头部有界，禁用 keep-alive，响应 no-store，未知方法/路径
明确失败；文件根边界和可信不可变部署目录要求沿用资产读取设计。

每文件最多 8 MiB；每服务串行处理连接，头部读取/网络发送有截止时间。进程至多
16 个仍存活的服务（包括已关闭但系统读取尚未返回的服务），每服务一个后台线程，
不让资源内容读取或服务退出阻塞 UI；既有根目录/入口初始化元数据校验仍同步。关闭撤销服务接受状态，不保证硬中断系统读取，
资源和额度在后台实际退出时释放，不用替代线程绕过额度。

随机 URL 前缀避免其他本机页面猜测资源，不能作为对同用户恶意进程的身份认证。
页面可见自己的资源 URL；不能把它当秘密保存或对外分享。不新增网络能力给
远程导航，Bridge 仍仅接受当前原生选定文档和会话。顶层导航与资源获取是不同
策略，模块/fetch 可读根内资产不等于允许任意页面获得 Bridge。

## 生命周期与兼容性

端口/前缀按窗口独立且在窗口内保持稳定；导航仍轮换 Bridge 令牌，关闭撤销
晚到回调。原生后端必须显式支持本机选定源的加载，但不能放宽远程加载策略。
HTTP入口不宣称能控制应用脚本发起的任意子资源网络访问；应用仍须配置CSP。
不提供HTTPS、通用代理、文件上传、目录列表、Range或自动安装依赖。

## 本轮检查与后续验收

以实现为主，执行必要编译、语法及路径/Host/方法/容量边界检查。三引擎真实
模块、动态import、fetch、CSP、关闭/导航竞争及平台网络策略统一留待目标机验收；
源码实现不等于已通过这些项目。服务启动受环境禁止时明确失败，不能关闭安全保护。
## 连接中止恢复补充

accept 阶段的 POSIX ECONNABORTED / Winsock WSAECONNRESET 属于待接收连接失败，
不直接终止仍有效的 listener；仍通过原停止检查和等待路径接收后续连接。
该分类仅用于 accept，不扩大 send/recv 的重试范围；永久错误仍停止服务，
连接处理和 shutdown 期限不变。生产源码故障注入与真实 loopback GET 可验证
恢复路径，但不替代目标 Windows/macOS socket 行为验收。
