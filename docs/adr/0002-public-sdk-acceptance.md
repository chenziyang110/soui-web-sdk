# ADR-0002：公共 SDK 独立消费者与生命周期证据

- 状态：proposed，实施与验证后交维护者评审
- 日期：2026-09-22
- 范围：生产验证方案阶段 A；V01/V04/V05/V06 的独立原生测试边界

## 背景

模板和 Workbench 的短启动不能证明重复重载、多窗口及运行时释放。通用能力注册仍部分存在 Demo，测试若复制这些实现会掩盖公共 SDK 的缺口。

## 决定

1. `tests/acceptance-app` 是独立 CMake 消费者，只使用 `find_package(SouiSdk)` 和公开头文件，提供原生父窗口并调用 Host；不链接 SOUI Demo、SDK 私有源码或测试宏。页面通过公开原生连接执行 bootstrap、带窗口身份的 echo 和就绪回报。标准连接器实施后，消费者页面改为直接引用同次构建的公共 Web SDK 产物；测试工具拥有单独锁定的 Chrome 49 构建依赖，不借用模板或 Demo 的连接代码。
2. `tests/acceptance` 定义场景和结果核验；`tools/Test-Acceptance.ps1` 负责 SDK 安装、独立编译、干净运行载荷部署及串行桌面监督。复用现有桌面互斥锁。每次运行写新目录，失败结果不可覆盖为成功。
3. 首批场景为同进程重载、销毁重建、三个并存 WebView。多窗口必须验证关中间窗口后另外两个页面仍能重新 bootstrap/echo，随后重新创建已关闭窗口。每步记窗口、周期、操作及结果；原生窗口存在不等于页面可用。
4. 每次运行绑定 SDK 构建记录、安装库散列、测试源码、场景参数、EXE/DLL/页面散列、系统与进程身份。核验器检查计划步骤完整性及真实退出码；启动失败、步骤缺失、日志截断、超时或载荷漂移一律失败。
5. 测试期间采样 Private Bytes、Working Set、GDI/USER/普通句柄及线程数；资源指标是测量结果，首批运行通过不自动授予长期内存或生产准入。
6. 测试应用及工具不进入默认应用运行包。测试页面保持 Chrome 49 经典脚本语法，使用当前可用公开传输：bootstrap 返回字符串，普通调用返回 Promise；SDK 标准事件/释放连接器完成后统一迁移，不另造测试专用通信实现。
7. v2 构建先复制并冻结消费者源码和实际内核 DLL，独立编译使用该副本；运行前后核对安装库、消费者源码、候选内核及完整载荷。`-RuntimeBinary` 允许验证重编译候选，不修改固定 prebuilt。报告同时记录 SDK/工具源码指纹与内核散列，不能用前者代替原生依赖的来源身份。归档保留消费者源码、构建日志及逐轮原始记录；旧 v1 证据保持历史含义。
8. v3 增加公共 Web SDK 产物和独立页面构建记录，要求 Web 输入与 SDK 库来自同一源码；最终部署页面必须与实际 Web 输出逐文件匹配。`bridge` 场景消费标准连接器并运行并发、延时、容量和错误探针。`-PrepareOnly` 允许先编译，真实窗口运行仍必须单独取得互斥锁和完成结果，准备成功不能计作场景通过。

## 备选方案

- 在 Demo 中加特权测试接口：不能证明公共 SDK 独立接入，不采用。
- 每轮重启进程替代 WebView 重建：隐藏进程内资源和全局引擎问题，不采用；进程重启另设生命周期场景。
- 未验证就把运行时改成全局单例：缺少可复现失败和关闭契约；先运行独立探针，再以独立 ADR 决定所有权修复。

## 兼容、迁移与回退

新增测试消费者不修改现有公开接口和运行时行为。既有模板、默认 Demo 及 React 启动验证继续有效于其原有范围。新报告使用独立 schema，不改写历史 `acceptance.json` 的发布结论。运行时/API 的后续变更需增加 preview 版本和迁移说明。

## 验证

从 SDK 独立安装目录配置并实际编译运行消费者。核验器的测试覆盖退出失败、丢步骤、重复事件、参数不匹配和篡改证据。真实场景先保留现状结果，再用于后续修复回归；1,000 次、100 次、8 小时及平台全矩阵分别收集，不能用短探针代替。
