# ADR-0093：内存不足时仍可释放 JSON

日期：2026-10-15。状态：已实现，完整候选验收进行中。

## 问题与决定

公共 Bridge 的逐次内存分配故障测试复现了进程终止：固定的
nlohmann/json 3.11.3 在析构对象时用 `std::vector` 保存待释放子节点。
该分配失败会从 `noexcept` 析构逸出，普通调用方的 catch 无法恢复。

仅移植上游 #5762 的无分配、无深度递归析构，以及 #5767 的前向对象
迭代器兼容和 #5770 的枚举覆盖。基准是上游提交
`9b179cee1e1813020fbd14d15bcced6b4ffee109`。其余 3.11.3 API 和布局保留。
树遍历暂借正在释放的子节点保存祖先链接，节点只在成为标量或空容器后
释放，不需要辅助堆空间，也不随树的深度增长原生调用栈。

不采用删除故障扫描、在析构外围捕获异常、OOM 时递归回退或泄漏对象的方案。
不升级整个依赖到未发布的开发分支。

## 兼容性与来源

- 只改变已交付 JSON 头文件的私有释放实现；SDK 和外部消费者需统一重编。
- 不改变 Windows、CRT、C++17、Chrome 49 或公共 Bridge 协议要求。
- JSON 位于公共 SDK/构建工具依赖中，未改 Miniblink/SOUI 内核源码或固定 DLL。
- 补丁和原始版本、上游提交、散列见 `third_party/patches/json/README.md`。
- 新版本内容必须使用新发布身份，不能覆盖历史同版本 SDK 包。

## 验证

`tests/native/json_destruction_tests.cpp` 在构造后禁止所有普通全局 new，
测试标准和 ordered JSON、宽树、十万层数组/对象/混合树及异常展开，并检查
清理期间零分配和分配余额回到初值。CTest 分别编译诊断开关 0/1，保留断言。

原头文件的最小复现已实际编译、链接并异常退出；移植后两种诊断配置通过。
这只是定向回归。公共 Bridge 的全部 nth 故障注入、x86/x64 构建、完整原生
测试和最终交付验收仍必须绑定新的 SDK 产物，不能拼接历史 181/182 结果。
