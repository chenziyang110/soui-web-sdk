# ADR-0137：统一窗口状态与显式网页控制

状态：代码实现，原生状态交互验收待完成。旧 Host 保持不变。

统一入口补齐 minimize/maximize/restore 与 minimized/maximized 观测快照，三后端
提供原生状态变化事件。操作成功只表示请求被接纳，不冒充窗口管理器已完成请求；
状态查询和事件反映系统观测值。查询 status 失败时 value 不代表状态；能力存在但
窗口尚未实现的 unknown 与不支持分别返回错误。minimized/maximized 不互斥，允许
平台保留最小化前最大化状态。平台不能提供能力时明确 not_supported，不模拟成功。
最大化请求先取消最小化；恢复清除最小化与最大化，回到普通窗口；不新增全屏、位置或跨窗口控制。

C++ UI线程操作沿用窗口关闭/回调重入屏障。状态事件可合并连续变化，不承诺每个
系统中间态。原生 callback 属于窗口，不属于某一网页；网页事件绑定当前导航代际，
旧页面排队状态不得发送给新页面。窗口关闭后不得回调。

options.enable_window_controls 默认 false。开启后仅向当前可信顶层页面提供
`desktop.window.minimize/maximize/restore/getState`，参数必须为空对象；同名状态事件
`desktop.window.stateChanged` 携带 {minimized,maximized}。这四个固定方法名保留，业务通用 invoke 不能
绕过其显式授权；其他 desktop.window.* 名称仍转发给原业务回调，不接受网页传入窗口 ID/句柄、session 或权限标志。
现有通用回调没有方法注册清单，无法在初始化探测同名实现；已有业务使用这四个
名称须重命名或迁移到显式授权服务，不能静默期望业务handler仍接管它们。
这不是旧 Runtime 任意权限自动迁移，也不授予文件、全局快捷键或设备权限。

前端适配器只包装既有 invoke/on 协议，不注入第二套通道。示例显式授权并提供真实
控制与状态显示。共用层仅做聚焦的权限/状态/生命周期回归；目标编译与实际GUI证据
分开报告。后续受控服务及可取消关闭请求另行实现，不把本增量当整个跨平台目标完成。
