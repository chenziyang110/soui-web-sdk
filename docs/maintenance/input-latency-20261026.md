## 代码审查重点

- pending 消息只有一个有效票号；旧消息不会清掉新请求，关闭先封住发布，回调时不持锁。
- 正常批次最多接纳 32 项、执行 32 项，共享 2 ms 协作截止时间。保留批次在 owner 线程访问，已转移槽位置空，退出包含剩余槽位。
- 执行前让出当前待处理的原生输入和绘制，暂停生产者补投唤醒直到原 timer 恢复调度；未来任务不会因新唤醒提前执行。原生压力下仍可能回到 16 ms timer。
- 资源不可用时不立即递归重试；同线程延时的既有语义保持。资源 fence、commit 合并、页面销毁通知和滚动 ACK 保留。
- 已接纳任务继续使用原优先级/老化策略。尚未接纳的后批次需要等前批次接纳，需检查大量未来任务混合交互任务时的尾延迟。
