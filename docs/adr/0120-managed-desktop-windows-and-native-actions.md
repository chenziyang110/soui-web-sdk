# ADR-0120：受管理的多窗口和原生桌面动作

状态：实现中，目标机交互验收待完成。

## 背景与决定

统一入口需要同一份业务代码管理多个窗口、原生菜单和托盘，不能让关闭任意一个
窗口结束所有业务，也不能共享窗口间的 Bridge 授权。保留已有单窗口 API，新增
`application::create_window` 返回需要调用方持有的窗口句柄，每窗获得进程内不复用
的稳定 ID、独立资源根、回调、系统熵令牌和导航代际。最多同时存在 32 个活动窗口。

只有根 application 可运行事件循环。`close` 只关闭当前窗口，最后一个窗口关闭
才停止公共循环；`quit` 关闭整个窗口组。根对象析构关闭所有子窗口，外部持有的
子窗口句柄之后明确失效。销毁必须在创建 UI 线程，不能在业务回调中销毁对象。
所有窗口的业务回调在公共层串行化，避免原生模态消息泵引发跨窗口重入。

新增平面原生弹出菜单、托盘设置/移除和原生 command 回调。菜单至多 64 项，
命令 ID 唯一且有界，文本严格 UTF-8。菜单/托盘事件只投递所属窗口，不自动导出
到网页，不授权网页创建窗口或控制其他窗口。能力表示后端实现，实际桌面宿主
不可用时操作必须返回失败；没有托盘宿主的平台不能返回空成功。

托盘绑定窗口生命周期，不提供关掉全部窗口后继续常驻的隐式模式。需要常驻的应用
可隐藏持有托盘的窗口，并通过显式 quit 退出。图标使用平台原生应用/状态图标，
本轮不引入跨平台任意图像解码或热键语法。菜单层级、系统菜单栏和全局快捷键另行设计。

## 备选、兼容性与迁移

没有让业务直接操作 HWND/GTK/NSWindow，也不让多个独立 Runtime 争用全局消息泵。
没有共享 token 或在 Web 暴露任意窗口查找/调用。已有单窗口 initialize/run/close
调用保持语义；新增窗口须使用 create_window，不能创建第二个独立应用组。

这不是完整 Electron API 兼容。Windows/macOS/发行版托盘行为和图标呈现仍有差异，
安装、签名和自动更新不能由源码构建成功推导为完成。

## 验证要求

公共测试覆盖不同窗口的 token/序号/来源隔离、相同 URI 不同窗口、只关闭一窗、
最后一窗退出、根先关闭、显式整组退出、回调创建/关闭与模态跨窗口重入、命令
隔离和参数上限。真实 Linux 头库编译不能替代实际菜单/托盘可见和点击。
Windows/macOS 的源码审查与目标编译分别报告，现有图形权限限制不得绕过。
