# ADR 0061: opt-in native scalar runtime metrics

状态：实现已采纳，2026-10-10 常规 x86/x64 × Debug/Release 四配置集成回归通过。本文保留原候选的设计边界；实际验证见文末记录，不代表真实八小时资源验收。ADR0060 属于独立的 Unicode 复制修正。

## Boundary and ownership

The native application may explicitly construct json_bridge, task_service, permission_store, engine_thread or dynamic_miniblink_adapter with diagnostics::mode::scalar. Existing constructors delegate to disabled. There is no Bridge method, page switch, credential, virtual function, task_invocation field, observer thread, history buffer or second service. The application retains the real owners until reads and their ordinary callbacks finish; diagnostics do not extend facade lifetime or make destruction concurrent-safe. All existing request, authorization, cancellation, renewal, queue and shutdown policies remain in their production owners.

runtime_metrics.h contains only fixed-size native scalar DTOs. A component returns disabled, ready, busy, not_started, wrong_owner_thread or unavailable. Each actual lock is attempted with try_lock. Busy/unavailable snapshots are incomplete data and cannot be interpreted as zeros or success. Scalars use saturating totals; epochs never wrap or reset on reading; invalid/reversed clocks remain explicitly invalid. Facade precedence is wrong_owner_thread, unavailable, busy, disabled, not_started, ready. The absent optional GUI facet is not_started in its DTO and does not alone prevent json_bridge's present Task/Permission facets from being ready. A closed GUI coordinator is still readable data, not an authorization grant.

The Task facade attempts its existing service mutex then its existing Store mutex, in the service-to-Store order already used by admission/query. It does not call query, allocate JSON, copy strings, copy maps, promote weak owners or call application code. It releases those locks before the Permission and GUI facets. The GUI facade copies its coordinator shared owner under the Bridge mutex and releases that mutex before the GUI snapshot. Inside GUI locking it counts weak.expired() only, never weak.lock() followed by a final context destruction. Its read does not run native readiness/proof, page events, effects, Host operations or callbacks.

The software facade is restricted to the adapter's construction/lifecycle owner thread before it reads plain borrowed pointers. Foreign calls return wrong_owner_thread without touching lifecycle fields. An enabled adapter samples its actual request budget, actual Bridge worker FIFO, and actual process-shared engine FIFO separately, with context receipts before and after. The process engine's diagnostic mode is fixed at its first real construction: a later enabled view cannot enable a shared engine already created disabled. An unmounted adapter returns not_started; this slice does not make a mounted Host or shared process composition claim. Existing Host owner, six observation spans, WebView2 watch and runtime policies are untouched.

## Exact scalar meanings

TaskService retains its actual 2 workers, 32 inflight limit and 128 subscriptions; TaskStore retains 1024 entries. Committed starts count only the successful existing transaction. Duplicate starts count existing retained receipts and do not increment starts/inflight. Capacity rejection totals count the existing inflight/store/subscription refusal branches. active_handlers spans the actual native handler or GUI worker callback, including that callback's own wait; finished_handlers counts callback returns/throws. cancelled_before_handler counts actual dequeued jobs which do not enter a callback. No new worker or scheduling priority exists. Queued age covers the actual FIFO front after successful admission, excluding running callbacks. Workers can be created before a later admission preparation fails, so worker_slots is not inferred from accepted starts.

Store state counts and eviction totals are read directly from the bounded actual retained entries. Evictions count only the successful existing terminal-eviction commit, never attempted preparation. Owner/operation/result-cache entry counts come from the actual service maps. String size/capacity sums cover only Store task_id, operation_id, message, result.task_id, result.message and service result-cache JSON. They exclude map keys, container nodes, allocator overhead, scopes, external borrows and other strings. They are lower bounds for those selected owners, not heap or process memory totals.

Permission counts describe stored scope owners and bearer aliases, not all live application references or still-valid credentials. One owner can retain two aliases after rotation. Alias validity still uses the real 30-minute lease, five-minute renewal window and 30-second overlap. Previous aliases remain stored beyond overlap until the existing rotate/revoke removes them; metrics do not sweep them. Owner flags under the existing Store/scope locks make revoke_scope and revoke_session count a two-alias scope once. checked_renewal_rejections covers valid request parameters that reach the Store-locked renewal check, excluding early syntax/foreign-binding rejection before that lock. No total scope cap or automatic expiry cleanup is introduced or claimed.

Software request lanes keep actual outstanding RAII leases at ordinary=256, control=128, renewal=1. The timestamp replaces the existing identity-set value with a lane/age record within the same maximum 385 identities; it does not retain a second identity history. A lease remains outstanding across queue, callback and resolver ownership and releases capacity exactly once before existing JS resolution. Separate lane capacity is neither scheduling priority nor authorization. Drop totals cover precisely try_enqueue_message's second receipt check, Bridge-worker generation/receipt refusal, pre-handler queue expiry, pre-engine generation/receipt refusal, engine post refusal and Bridge-worker post refusal. Later resolver/JS delivery failures and other Host errors remain outside this counter slice.

Engine/FIFO data covers only actual engine_thread::work_, executing FIFO callbacks, posting/stopped refusals and actual clear/discard on stop. Each existing FIFO item carries a timestamp only for enabled owners. ADR 0062 subsequently adds the enforced 580-slot FIFO and its scalar capacity/full-rejection fields. The Windows native message queue, its bounded service batches, other event sources, application queues and GPU work are not counted or capped by this DTO. An enabled FIFO read from inside an actual callback is outside the FIFO mutex; no diagnostic callback is added.

GUI retains its actual 16 context slots and 16 effect-vector capacity. pending_live_contexts counts non-expired weak contexts; retained_weak_slots is the actual retained vector size. queued_effects is retained effect-vector occupancy, including abandoned phase-3 entries until owner polling removes them; oldest_queued_effect_age covers only phase 0 work. effect_borrows and owner_poll_active retain their existing meanings. Snapshotting never grants page/Agent authority, consumes a ticket, executes an effect or settles a task.

## Verification and delivery

Eleven proposed normal-SDK CTest/direct cases exercise production services and real existing bounded operations, without TestKit or copied SDK implementation TUs. They cover disabled/epoch semantics; real admission/duplicate/full/cancel-before-handler; subscription cleanup; 1025 real sequential tasks and one actual terminal eviction; two-alias unique revocation; stored permission owners; FIFO reentry/discard/join; real lane capacity/release; optional GUI read without proof calls; unmounted software owner-thread checks; arithmetic/clock/status boundaries. The last helper boundaries and direct drop recording are native diagnostic method tests, not mounted Host observations. Blocked fixture storage outlives actual service join; assertions release gates and join owned test threads before teardown.

The normal SDK remains 25 CPP and the optional WebView2 is separate. SDK GLOB install rules already enumerate public headers; no new public installer or parallel schema is introduced. The normal native parent now registers metrics, Engine and Scope tests. All 29 cases passed on x86/x64 Debug/Release under the original Owned rules, with actual source/CL/OBJ/LINK and SDK archive binding. See the [116-case finite integration](../../verification/production-validation/0.5-runtime-capacity-2026-10-10/README.md); no new MAP or complete-toolchain qualification is inferred from that integration.
