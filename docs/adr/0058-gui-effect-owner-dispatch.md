# ADR 0058: GUI effect dispatch through the native owner pump

Status: adopted; finite x64/Win32 native regressions and actual x64 Compat React, Compat Vue and Modern workflows passed. Broader release qualification remains pending.

The real Compat React coordinator reached five GUI receipts and then observed form_submit still running with progress 0 at its unchanged final poll. The Root V5 record is out/rcgui5-0fa92112. This record does not contain the internal gui.effect error. Frozen source establishes a concrete incompatible thread route: both Compat and Modern adapters run page Bridge requests on their Bridge worker; GUI effect requires the thread that created the coordinator. The application creates, binds and polls that coordinator on its window owner. The former service therefore rejects the worker's effect as E_GUI_WRONG_OWNER. Its failed ACK is also rejected while effect_done is false, leaving the task waiting. This remains a source finding about the original failure. The new cross-thread regressions and actual React workflow passed after adoption; they do not add an internal error observation to the historical V5 record.

Use the existing bind_gui_document/poll_gui_commands owner service. Only the registered, authenticated gui.effect route may enqueue an effect request. There is no general JSON dispatcher, new Host callback, new worker, new task service, user gesture or grant. At most 16 private requests retain the original authorization scope and prepared GUI context. A Bridge worker may wait for its own response only up to the existing request/context deadline, with a bounded cancellation recheck. The owner never waits for that worker, and all proof/application callouts occur outside queue and task locks. The existing effect implementation still checks owner identity, current native proof, both scopes, document and deadline before and after the one native callout. Owner poll handles at most one queued effect or one GUI dispatch.

Queue admission reserves a monotonic private one-request flag; native effect consumption stays separate. The owner callout receives the minimum of the original GUI context deadline and this page request deadline, and rechecks that minimum before and after the actual handler. A wait/serialization failure also atomically abandons an unused effect; it does not leave a queued callout after a failed response. Revocation, close, cancellation and expiry prevent any queued request from executing. Once owner execution starts, a missing response is unknown and cannot be retried or rolled back. Queued requests retain their context until the owner removes them or close releases them outside the GUI lock. Close wakes waiters before Host joins its Bridge worker; the application already closes the GUI service before Host destruction. No wait budget or external Owned drain is extended. Shared and exclusive browser-runtime policies are untouched.

A negative page ACK is independently valid before an effect has been consumed (including an admission already abandoned unused by its deadline). Under the context lock it atomically changes the unused consumption state to a terminal rejected-before-effect state. This prevents an owner callout racing that ACK. It sets no effect_done flag and publishes confirmed=false/effectState=unused. A positive ACK still requires the actual effect result. A negative ACK during consumed-but-unfinished effect is still rejected; a finished effect retains its actual committed/unknown receipt even when the page failed. ACK cannot mint authority or a successful effect.

Normal-SDK regressions use the actual public Bridge, endpoint, fixed two-worker task service and a separate real page-call thread while the actual creating thread pumps poll_gui_commands. They cover foreign-thread effect completion on owner, queued request expiry without owner execution, close inside the owner proof, and negative ACK without any effect, negative ACK during an unfinished consumed effect, and an ACK racing inside the actual pre-consumption owner proof. Existing once-only, scopes, child admission, cancellation, secret projection, owner reentrancy and real external process cases remain. The previous owner-callback test must not synchronously join a thread that now legitimately waits for that same owner; it is replaced by the actual owner-pump test. Root executed all fourteen direct cases and fourteen CTest cases on each architecture; each native stage ended naturally with root/supervisor 0/0. Independent review checked the actual external child membership and the ordinary SDK25 compilation/link inputs.

Real application validation rebuilds the ordinary SDK/archive and actual applications, keeping the same coordinator requests/input/poll count/deadlines. Compat React, Compat Vue and Modern each completed form_submit with a committed native receipt followed by actual summary admission/query/cancel. Each view was exercised separately. Service tests are not a GUI or physical input qualification. Performance, OS, release and whole application qualification remain false.
