# 0.5.0 resource input file bindings

2026-10-13. Proposed Source contract; no program or test execution.

ResourceCapture produces lifecycle samples without a passed resource gate. A single SDK source hash cannot cover the independently copied acceptance consumer, Web SDK, Web output, installed SDK and kernel input. The file reader must validate their current physical membership and original byte identities rather than accept a caller's claim that inputs match.

Add a fixed local producer API, `freeze(suite, runRoot)`, in `tests/acceptance/resource-file-bindings.cjs`. Both paths must belong to the current SDK's ordinary `out/acceptance` suite. The run is the real frozen reload request and policy already written by the runner. The API has no CLI and no input-root, hash, module, schema or native-scope overrides. It uses existing `runner.verify(suite)` and `builds.verifyBuild` and the shared `identity.sourceSnapshot`; the SDK snapshot must equal the accepted build's original source files/hash/bytes. This preserves the existing meaning of sourceSha256.

The v2 file-binding document keeps source, payload, policy, runner and executable fields. It adds separate fixed-role consumer-source, web-sdk, web-output and install snapshots with their actual suite paths and original record files/hash/bytes. These snapshots compare the complete tree without directory exclusions. Only acceptance payload uses the runner's existing exact `resources/source-navigation.log` diagnostic exclusion. SDK source alone uses shared sdk-source exclusions. No roots from the document may redirect these roles outside their fixed current SDK/suite locations.

Bind physical SDK build, acceptance build, pending, Web build and public Web SDK records; typecheck config/log; copied kernel-input/node.dll; actual policy/request; runtime EXE and selected Owned runner. Validate record schemas, architecture/configuration/version, buildId/consumerBuildId/sourceSha256, public Web artifacts and each original snapshot. The copied kernel is a byte input, not an OS, licensing or native-build qualification. The Owned runner is read as data and never imported from a binding.

Freeze writes `runRoot/file-bindings.json` with CreateNew semantics while known launch markers are absent. This is a local prelaunch condition, not a whole-system no-process assertion. Future runner integration must invoke it before launch, then invoke `recheck(file)` after the original Owned finished result. Recheck verifies the same fixed records, exact membership, current bytes and IDs; it does not supervise a process or itself certify that closure has occurred. This Source step deliberately leaves runner/PowerShell unchanged until the contract is reviewed.

The resource file reader recognizes v2, invokes real full-binding verification and retains the original policy, transcript, Owned identity/context, arithmetic and natural closure checks. Its computed resource observations cannot grant qualification while actual native software/presentation scope is missing: v2 resourceGate remains not-evaluated, passed=false, nativeScopeGate=not-observed. It preserves the observed counter-rule result and any observation failure for diagnosis. A caller-supplied software flag or fabricated native-scope record is rejected; future collector integration requires a separate reviewed contract.

Legacy v1 synthetic tests retain their existing finite caller-frozen input-root behavior and are labelled as legacy finite scope. They do not gain complete-input or actual software evidence from this change. Source coverage still means the original SDK delivery identity roots, not every compiler, tool or operating-system input.

Focused tests will use real temporary file trees for exact snapshots and logical record DTOs for cross-record validation. They cover incomplete membership, changed bytes, traversal/normalization, divergent build/source IDs and forged native scope. These fixtures never execute a native application or claim a current SDK build. All tests are unexecuted during the active Root native lane. Actual coherent SDK rebuild, runner integration and independent resource/native scope evidence remain pending.
