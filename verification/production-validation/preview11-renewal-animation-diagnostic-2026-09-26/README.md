# preview.11 续期夹具：解析、动画与监督器诊断

本轮只诊断已冻结的 preview.11 x64 独立消费者。五份新副本均保留原 EXE/DLL、JS、初始 60 秒就绪期限及 90 秒外层期限；只修改受控 `resources/index.html`，原冻结 SHA `80d19d4e2008a505bbb8a9293849f3756d4bf07ad7838ad38aa5bb054ac0ee3a` 未变。运行串行，门禁记录未见外部桌面负载，运行前后载荷及父输入核验通过。

## 实际观察

| 诊断副本 | 原生结果 | 已观察边界 |
|---|---|---|
| 补丁内部细分标记 | exit 1，60 秒未就绪 | 未到补丁前标记；不能把先前停止位置直接认定为 DOMException 缺陷 |
| 保留原字符集声明位置 | exit 1，60 秒未就绪 | 保留字符集在字节 51 的位置仍失败 |
| 解析状态观察 | exit 1，60 秒未就绪 | 1 秒和 20 秒均 `readyState=loading`，仅两个诊断 script 节点；原生绑定和定时器可用，原始尾部脚本尚未进入 DOM |
| 关闭旋转动画 | exit 0，78 条原生日志 | 相比上一项只将一处 `animation:turn 1s linear infinite;` 改为 `animation:none;`；bootstrap/ready 各一次，两类公共任务、订阅、取消与清理完成 |
| 15 秒后关闭动画 | exit 1，69 条原生日志 | 页面后来完成 bootstrap/ready 并开始任务；43.156 秒报“Page record gap exceeded 30 seconds”，其前一条页面记录在 43.141 秒，相隔仅 15 ms |

第五项截图在 5.523 秒已有补丁前标记、14.534 秒已有补丁内部标记；因此不能把这一次描述为“15 秒停止动画后才开始恢复”，也不能从一次关闭动画通过就宣称调度根因已完全证实。`WebSchedulerImpl` 将加载任务设为较低优先级，`WebThreadImpl::schedulerTasks` 严格优先选择就绪的高优先级任务；连续动画与加载饥饿是下一步需要原生队列/线程证据验证的假设。

第五项另外揭示监督器的独立风险：轮询先读取 `now`，再读取跨线程观察快照；页面回调可能在两者之间推进 `last_record_at`。两者为无符号数，`now - last_record_at` 可能下溢。退出前 15 ms 的页面记录与“30 秒无记录”不相符，源码存在明确竞态，但原日志没有记录当时相减的两个操作数。不能把这次原生 exit 1 改写为通过；需在新的夹具输入中补回归并修正时序后再验证。
