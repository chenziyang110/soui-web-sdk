# ADR 0097：0.5 内核重建与公开接口验收

状态：两架构组件重建及公开接口验证已完成；完整应用验收尚未结束。

## 背景与决定

旧交付内核缺少当前源码的 `wkePrepareWorkerShutdown` 和
`wkeFinalizePrepared`，应用完成 Host 关闭后无法执行保留所有者的退出
握手。按现有显式 LLVM22MSVC142 入口从冻结源码重新构建两个架构，再
逐项核验来源、真实自有进程自然退出、导出、实际应用与目标系统。
不回退为直接 `wkeFinalize`，不将缺少接口解释为完成退出。

编译器切换会改变静态依赖的偶然导出。首轮 x64 全导出对比保留了 82
项缺失：26 个 MSVC STL/V8 模板实现符号与 56 个 `ares_*` 符号。后者
对应当前 libcurl 工程显式 `CARES_STATICLIB`，并非公开 SOUI API。
完整差异必须交付，不声称新旧 DLL 的所有符号或任意 C++ ABI 相同。
x86 对比缺少 26 个同类 STL/V8 模板符号；该架构的 `ares_*` 导出仍在。
两个架构均保留原有 355 个 `wke*`/`js*` 导出及全部 SDK 必需接口。

验收分别执行：旧 DLL 的全部 `wke*`/`js*` 导出继续存在；SDK 直接
解析的必需接口存在；未解释的其他缺失阻止导入。交付的上游兼容头
是较宽的函数表，25 个条目在新旧 DLL 均不存在，也没有被 SDK 解析
或调用。逐项记录这些旧有缺口，不能将头中声明视为运行时能力。
首次把整个上游函数表当成必需导出的失败记录保留；后续判定以 SDK
真实使用及旧运行时已提供的函数为边界。静态库散列、实际链接映射和
网络行为另行验证，导出对比不证明 DNS、TLS、OS 或生命周期正确。

## 替代方案与兼容性

保留旧 DLL 无法满足当前关闭握手。按旧编译器重新导出 STL 内部符号
也不提供跨编译器 ABI 承诺，且不能恢复所缺的公开关闭能力。
应用及 SDK 均从当前源重新编译；只支持公开接口，不将旧编译器的
标准库或嵌入依赖内部符号提升为 SDK 契约。默认构建档位不静默改变。

## 验证与迁移

两个架构必须共享同一源身份、保留原构建及对比原件，更新二进制
来源、散列、许可证与 SBOM。公开接口静态检查与真实调用分开记录。
首次 x64 实际组件构建自然 0/0；使用历史应用 EXE 仅替换新依赖的
三个诊断场景退出 0，证明该有限退出复现已消除，不替代最终 SDK 验收。
两架构构建均在原有期限内自然退出，物理源码身份一致；实际 TLS
六组用例均通过，覆盖受信任匹配、非信任链、主机名错误、回调不能
关闭校验及重定向目标主机名错误。原始构建、接口差异和 TLS 记录
保存在 `verification/production-validation/0.5-kernel-rebuild-2026-10-15/`。
