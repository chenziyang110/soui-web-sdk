# ADR 0090: Exact test-generated compiler dependencies

Status: proposed Source-only correction. No compiler, CMake, Owned runner, SDK helper, GUI or VM is executed by this candidate.

The ordinary default graph in the failed x64 Release SDK attempt compiled and installed with natural root/supervisor exit 0 and Job active 0. Its subsequent semantic reader exited 1. The first rejected actual Ninja dependency was `tests/native/vendor_lifetime/generated/interaction_endpoint_source.inc` below the build directory: it had correctly not been declared as a file frozen before Build. The whole SDK result remains failed. This correction does not revise or accept that attempt.

The complete recorded Release database and Ninja dependency query identify 128 selected compiler objects and 26 distinct generated compiler inputs absent from the 5845 pre-Build dependency pins. They belong to three writers: one endpoint fragment, twelve worker files, and thirteen request-close fragments. Dragdata, constructor-shell and legacy-drag tests use tracked fixtures and pinned source-byte validation; they contribute no missing generated compiler inputs in this recorded graph. The input schema has no `withVendorTests` field. Selection therefore comes from the already validated compiler/default-graph and exact VALID Ninja object bindings, without a new option or a generic exception for the output directory.

`GeneratedTestDependencies` recognizes only the exact object, configuration and generated directory for each of the three known test targets. An unselected role admits nothing. A selected role requires its complete known generated set; unknown names, duplicate names, wrong object/directory, missing names, STALE bindings and pre-Build pins claiming to be these generated outputs fail closed. All existing compile-database, source/object, header identity, MD/Doctor, Ninja raw-query and natural-closure checks continue through their original paths.

Every writer, script, map, payload and whole source used by the derivation must occur in the original pre-Build pins and still match its physical bytes and SHA256. Known normalized writer fingerprints bind the complete version of the endpoint CMake writer, worker CMake writer plus `source-bytes.cmake` and `source-map.json`, and request-close CMake writer. Only checkout CRLF is normalized for this writer-version comparison. No fragment or generated payload is normalized. An updated frozen pin cannot authorize an unknown writer body or altered worker map.

The endpoint and request-close writers select raw byte intervals using two unique ASCII source markers. Their `file(GENERATE)` contracts require LF-only, NUL-free fragments with the final LF present, protect each dollar through the literal `$<1:$>` expression, and use UNIX newlines. The reconstructed output is the original byte interval including its final LF. Request-close's thirteen declarations are read from its locked complete CMake text, with source/header and output names derived from those declarations.

The worker writer uses the frozen map's thirteen whole-source pins, twenty-two payload pins and twelve copy declarations. Each mapped interval, size, SHA256 and whole-file flag is checked. The map's payload pins also cover its CMake writer and byte script; their raw-byte requirements remain authoritative even if the normalized writer fingerprint matches. Six whole-file copies preserve all raw bytes, including any CRLF or dollars. Six partial copies require the terminal LF and exclude NUL/CR; the locked CONFIGURE writer removes that validated final LF and writes it back once with UNIX newlines. Reconstructed output is the exact mapped original bytes. Portable relative map paths cannot escape the source or generated role. No absolute SDK root or observed output digest is embedded as an expected generated value.

The physical generated file passes `ObsPin` and `GeneratedTestActual`: exact derived path, size, SHA256 and the complete byte array must agree. Its source and writer pins are rechecked before admission to the actual dependency lookup. The separate `derivedDependencies` row records the original source pin, writer/support pins, raw interval, whole-file flag, selected object, expected generated pin, derivation schema and `preBuildFrozen: false`. The original `frozenDependencyPins` collection is unchanged; generated files are never described as pre-Build frozen.

Pure regression extracts only reviewed function declarations from the candidate and original reader, then replays the actual serialized failed input, all three configurations' recorded database (selecting its 128 Release rows) and the complete original Ninja dependency query. The original `DependencyPin` rejects all 26 real outputs. The candidate derives all 26 and compares each complete existing public byte array. These checks are evidence of byte derivation on failed historical data, not a new accepted SDK build. Fault cases cover writer/map/script and source-set tampering, unknown paths, missing or duplicate dependencies, false frozen outputs, physical body/pin mismatch, malformed Ninja counts, invalid fragments and portable paths. A relocated in-memory root/build uses the same frozen bytes without reading or writing that location. Checkout CRLF coverage preserves derived raw bytes.

Scope is the three known selected test writers. New generated test roles or changed writers require a reviewed source contract. Root must independently review and integrate this Source3 candidate, create/verify the new source manifest, and run a fresh complete SDK producer and semantic reader. Native tests, installed consumer execution, guest compatibility, performance, licensing and release qualification remain unproven here.
