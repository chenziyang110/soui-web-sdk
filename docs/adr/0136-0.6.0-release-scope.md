# ADR 0136：0.6.0 普通 Release 分类与限定交付范围

状态：采用用户 2026-10-28 的本次发布决定；源码集成、实际构建与资产收口进行中。

## 背景

用户要求发布普通 GitHub Release `v0.6.0`，大幅更新公开文档，并明确纳入原工作区尚未进入 main 的原生受控 DevTools。用户同时要求将低收益长测试和重复演练后置。本地候选和已合入 PR 的历史结果绑定各自版本与载荷，不能自动成为新发布证明。

GitHub 上的 `v0.5.0` 实际为 `prerelease=true`；它以未签名、限定验证范围交付并保留 `releaseReady=false`。该历史不被改写为普通 Release 先例。本次分类来自新的明确用户决定。

## 决定

根版本为 `0.6.0`，tag 为 `v0.6.0`，GitHub 最终 Release 分类为普通（`prerelease=false`）。版本的 stable 语法和 GitHub 分类是发布身份，不是生产资格。完整生产状态保持 `releaseReady=false`、`productionQualificationComplete=false`，未执行或失败项目继续如实保留。

采用独立集成 worktree，保护原 dirty 工作区和全部旧产物。发布源码包含本轮实际选择的 DevTools、AutoHost、输入/调度/帧/资源与交付工具源码。受影响内核、SDK 与应用按最终源码和版本重新绑定；最终 DLL 的对应源码、构建输入和产物 hash 由真实材料证明，不能只复用旧 stock 或某个局部候选的通过标记。

优先完成受影响双架构依赖、SDK/应用的必要构建、共同工具回归、Release 原生代表检查、安装/生成与公开消费者、权限/资源边界、包解压启动与真实结束。相同实际输入已覆盖的用例不换入口重复全量执行；改变了身份、源或行为的范围须补本轮证明。原断言、资源 fence、默认拒绝和总期限保持不变。

D13 千次、D14 八小时、完整性能对比、全部 OS/PE/IME/DPI/多屏资格以及低收益重复搬移/升级演练后置，并保留为未完成。D01–D12 的缺项不因“低优先级”或普通 Release 分类被删除。未完成完整 Collector 或完整 Verify-Release 的情况下，只记录本轮真实限定结果并使用现有 `--record-unverified` 入口，不伪造完整验收通过。

## 权限、依赖与分发

DevTools 默认 disabled；原生配置、材料选择、grant 与实际结束分别处理。普通网页/CLI/环境变量不能启用或发许可；结束策略和 Console 业务能力须明确告知。默认 No、文档/进程/目标绑定、离线资源闭集和实际退休门不能后置。

WebView2 Runtime 由系统或部署者准备，不把 Loader 当作 Runtime。发行材料不因此自动包含 Fixed Runtime 或 Windows 字体文件。第三方许可与对应源码见[再分发说明](../licenses/v0.6.0-redistribution.md)，首方 MIT 保留；技术组合工具不生成外部批准或替代授权审查。

工具链生成的 unsigned 文件不被描述为已签名。最终新文件的签名状态、各资产的 bytes/SHA-256 和上传后身份由实际原件记录；不伪造签名、安装器或更新服务。

## 验证与完成记录

发布说明将分别记录最终 commit/source manifest、内核/前端/批准材料 pin、SDK manifest、工具链、实际命令、退出码、跳过与失败、解压后启动及自然清理。未得到的结果写为进行中或未执行。源码清单最后从 Root 审查过的 index 生成，保留历史 raw、旧清单和旧包原字节。

本 ADR 不授权把所有 Issue 或完整生产门槛标为通过，不改变实际权限、超时和清理合同，也不把旧实验的数字迁移为 0.6.0 性能承诺。
