# ADR 0106：安装后构建的输入闭包与字节身份

状态：实施中；最终固定包的独立运行仍须验收。

## 背景

实际生成项目试编发现三个接入缺陷。发布工具从开发包目录调用构建控制器，却请求编译另一个项目，触发控制器所属目录拒绝。安装包包含 LLVM 读取器，但遗漏其无条件绑定的两份 Host64 观察器源码。补足输入后，生成项目与开发包验证工具的档位仍不匹配；逐字段比较确认差异仅来自两份 PowerShell 身份脚本和 CMake 工具链文件的 CRLF/LF 字节差异。

## 决定

- 发布入口调用生成项目自身的 `tools/internal/standard-build.cjs`，保持控制器与请求工作区一致，不放宽控制器的归属检查。
- 每个独立发布阶段复制并绑定应用的 `docs/generated` 动作文档，防止阶段副本缺失实际生成器校验所需的业务输入；文档变化属于业务身份变化。
- 将 Host64 观察器的 C++ 文件及其独立 CMakeLists 纳入 SDK 的显式管理文件，安装和升级由既有事务机制处理；不引入整个基准工程。
- 为 LLVM 工具链文件及两份身份脚本明确设置 Git `eol=lf`，工作树使用与 SDK/源码归档相同的原始字节。其逻辑内容不变。
- 独立档位比较继续核验各自实际文件和原始散列，不忽略换行差异或篡改证据。受影响的验证工具和构建记录必须重新生成。

## 验证与兼容性

新增回归检查 SDK 覆盖全部 LLVM 构建前置输入、三份共享文件与交付规范的字节一致性，并沿用实际包安装、升级、回退及源文件核对。旧版本固定包保持原字节；历史失败与额外输入实验另行标注，不能代表最终交付已通过。
