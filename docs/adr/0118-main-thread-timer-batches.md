# ADR-0118：主线程定时任务批次让出输入处理

- 状态：proposed；限定调度回归、两架构重编和真实输入对照后评审。
- 日期：2026-10-21。

## 背景

隔离消费者中，鼠标已提交到 SDK 后仍有超过 100 ms 的排队，等待窗口与引擎线程约 50 ms 的 Windows 定时消息回调重叠。`WebThreadImpl::schedulerTasks()` 在每个任务后接受新任务并刷新到期时间，持续补充的就绪任务可以耗尽原有 50 ms 批次。SDK 外层原生消息与输入 FIFO 的 2 ms 预算只能在回调返回后检查，不能抢占这个内部批次。

清空绘制间隔仍复现排队，因此取消帧率限制不足以解决。鼠标调用本身的长执行也可能独立存在，本决定不将其视为已解决。

## 决定

仅对正常主线程调度增加每批至多 32 个已完成任务和 2 ms 的协作时间预算，达到任一预算就返回消息泵。保留尚未执行任务、原优先级和等待补偿、未来任务的到期时间。预算在任务及观察器返回后检查，不是单个回调或输入延迟的硬上界；任务接纳本身仍有开销。

工作线程沿用原 50 ms 时间预算，不增加任务数限制。平台关闭在设置 `willExit` 前还有三次调度，分别与页面、加载器、图形和 GC 清理交错；它们明确改走内部 `fireForShutdown()`，沿用原 50 ms 预算及到期规则。该入口不临时修改退出标志，清理期间仍可接纳任务。设置退出标志后的调度及独立 `fireOnExit()` 排空也保持原样，重入保护不变。

本次先保留现有 16 ms 周期定时器，不新增高优先级 posted-message continuation，避免持续积压重新抢占原生输入。剩余就绪任务会在下一次定时调度继续；持续积压时的加载与动画吞吐需实际检查，不能只报告鼠标队列数字。

## 备选与兼容

- 仅缩短 SDK 外层消息泵预算：无法中断一次内核回调。
- 取消绘制限速：不能阻止因未完成场景或积压而产生的重试。
- 立即自我投递 continuation：可能长期优先于原生输入，需要单独验证消息优先级和关闭生命周期。
- 修改所有线程或退出时的预算：扩大本次范围，可能影响工作线程吞吐或清理，不采用。

没有公共 API、Bridge、权限或资源所有权变化；这是未发布的源码候选，不替换固定 0.5.0 DLL，也不重新打包同版本 SDK。任务跨批次的执行时机改变，持续任务链可能增加定时等待，必须如实记录。

## 验证

直接编译生产 `WebThreadImpl`/`WebTimerBase` 的严格字节绑定夹具，覆盖持续自我投递后的消息泵让出、任务数及时间预算、原生 sentinel 执行、未来任务不提前、最终逐一执行、工作线程原行为及退出清理。关闭前调度另从真实 `BlinkPlatformImpl::shutdown()` 的字节绑定证明中核对三处路由，覆盖退出标志设置前超过 32 个就绪任务的排空与后续任务接纳；它不执行完整平台销毁。使用旧实现取得真实失败，再验证修复版本。

适用原生执行在隔离来宾中完成；宿主只构建与检查。两架构实际内核重编后，在相同资源和输入下对照队列等待、页面加载/刷新及关闭。编译、夹具通过或局部输入改善均不批准完整性能、兼容性或生产发布，既有未验收状态保持。
