# ADR-0121：事件唤醒与有界任务接纳

- 状态：源码候选，最终编译和运行交由 PR 验证人员执行。
- 日期：2026-10-26。
- 基线：PR109（`3293bebe27ba8508bbd9dfe8b6e0d445e7879f3f`），包含 PR104 的正常主线程 32 项 / 2 ms 预算。

## 背景

输入处理、DOM 更新及页面提交会产生主线程任务。已有短批次让出消息泵，但首次任务和剩余就绪任务仍可能等待原有 16 ms timer。跨线程队列的接纳在批次预算外无界执行，生产者持续补充时也可能延长消息泵停顿。PR104 短测同时出现输入排队下降和突发完成时间上升；尚不能将全部代价归因于 timer。

即时续调度会放大原有资源未就绪时的立即 CommitTask 重试。后续沿 startFromOtherThread → start 核查确认：同线程没有跨线程 insertion-order 指针，原本已使用 currentTime() + interval；先前关于该路径借用批次开始时间的判断不成立，不能计为新增收益。必须处理实际重试路径，不能只提高轮询频率。

## 决定

1. 同线程提交后已有到期任务、跨线程成功入队、正常主线程批次结束后仍有到期任务或未接纳工作时，请求合并的窗口消息。执行仍发生在原主线程，没有同步跨线程调用或任务指针随消息传递。
2. 发布 HWND、投递和关闭由短 SRW 锁串行化。每次成功请求带递增票号；旧消息、错误窗口及关闭后消息不能消费新请求。投递失败解除 pending，继续使用原 timer 兜底。票号耗尽后也退回 timer，不回绕重用。
3. 消费消息先验证、清除 pending 并暂停新唤醒，再检查重入和 `HIWORD(GetQueueStatus(QS_INPUT | QS_PAINT | QS_TIMER | QS_HOTKEY))`。存在当前原生工作或重入时交还消息泵，生产者也不能补投；原 timer 下一次实际进入调度时解除暂停。没有原生压力则立即解除暂停并执行一批。锁不覆盖回调、调度或窗口销毁。
4. 主线程跨线程接纳改为 owner 保留批次和游标，每轮最多接纳 32 项，与执行共享 2 ms 协作截止时间；完成任务仍最多 32 项。接纳中不反复搬移剩余元素，保留任务的创建时间、优先级和 insertion order。优先级/老化策略仍作用于已经进入 timer heap 的任务；尚未接纳的后续批次不能越过前批次，不能宣称全队列优先级调度等价。
5. 同线程仍由 start() 在实际 post 时采样 currentTime()，无行为作用的 createTime 局部计算在后续 W00 删除；跨线程保留实际创建时间。资源不可记录时保留一个最少延后 1 ms 的 commit 重试，与已有主帧间隔取较大值，避免就绪链反复执行失败提交。
6. worker 和显式关闭继续使用原接纳/排空方式与 50 ms 批次；最终关闭包含未接纳的保留批次。任务所有权仍只转移一次。

## 边界和取舍

原 16 ms timer 保留，未来任务到期、原生输入压力、重入或投递失败仍可能等待它。1 ms 是重试最小延迟，不是 1 ms 周期 timer，也不保证 1 ms 后呈现。单个回调、观察器、析构、分配或优先级选择不能被协作预算抢占。资源持续不可用时仍按 timer 重试，未改为完整的资源就绪通知。

不启用旧的禁用高精度分支：它使用 LOWORD 变化标志，且未覆盖 mousemove。不使用无限 PostMessage 链压过输入。不修改 CPU 17 ms draw interval、滚动阻尼、raster fence 或 WebView2。这些剩余成本及端到端改善必须用实际载荷测量，不能由本源码改动推算性能倍数。

## 兼容和回退

公共 WKE ABI、SDK 协议、固定 DLL/LIB 和版本不变；内部 `WebThreadImpl` 布局改变，相关内核对象必须完整重编。同线程正延时语义未因 createTime 局部变量改变，计时依赖仍需回归。保持 Windows 7 可用的 SRW API，不提高最低工具链。

按 `0014-ready-task-wake-and-admission.patch` 和对应来源清单回退五个 vendor 文件，同时恢复测试来源映射和注册清单；不单独混用旧内核对象与新头文件。
