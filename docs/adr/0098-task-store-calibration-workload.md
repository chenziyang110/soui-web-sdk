# ADR 0098：公开 Bridge 配额的可重复校准负载

状态：两架构显式 128 MiB 最大负载已自然完成；默认额度决策见 ADR-0101，资源门槛仍独立验收。

## 背景与决定

ADR 0089 的边界用例仅能证明额度执行，不能用夹具中的小输入推导生产
默认值。新增独立安装消费者，通过真实 `json_bridge` 执行最大合法的
请求参数、128 字节 kind/operationId、512 字节 origin、4,096 字节
进度与终态消息，以及最大合法结果。先填满 1,024 个终态历史，再保留
32 个在途请求，验证第 33 个拒绝；释放后继续替换历史，覆盖候选复制
与退役存储的峰值。只链接安装后的 `Soui::Sdk`，不复制 Store 实现。

每阶段读取同一 Bridge 的原生额度与服务快照，记录真实进程 PID、创建
FILETIME、单调采样范围、进程 Private Bytes 和句柄数。额度计数保持
十进制字符串；忙状态有限重试，不将不完整值当成零。基线显式传入
nullopt，后续可传固定额度重复整套负载。失败保留阶段与错误并返回非零。

## 范围、兼容与替代方案

该入口是 Native 公开调用校准，不伪装为真实页面、GUI typed endpoint、
100 次重载、8 小时或全缓存预算。实际安装/工具/EXE 身份由运行控制器
另行绑定。不得读取销毁后的对象来生成虚假归零记录；只确认正常析构
返回，并由外部监督器验证进程闭合。现有构造语义、额度与 P0 门槛不变。

不选用合成分配器大小、SSO 推测或历史测试峰值代替实际请求字节峰值。
两个架构的当前 SDK 消费结果及真实宿主负载齐备后，再冻结余量和默认
策略，必要时修复历史回收与背压行为；本阶段不预定一个有利于通过的数值。

## 验证

在当前安装前缀下独立编译并执行，确认 32 在途、1,024 历史、所有请求
的边界尺寸及正常返回。显式不足额度必须导致原生失败而非削减负载。
保留实际报告及参数，生产默认值仍须单独复验。
