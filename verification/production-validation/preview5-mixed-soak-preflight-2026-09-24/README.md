# preview.5 同进程混合生命周期预检

日期：2026-09-24。独立公共 SDK 消费者新增 `mixed` 模式，在**同一个进程**反复运行真实页面 Bridge 探针、重载、最小化/恢复、三窗口创建与中间窗口重建、关闭和空闲阶段。每次挂载的页面执行 32 并发关联、200 ms 原生异步等待、原生容量边界及错误恢复；测试程序只使用安装后的公开 SDK。此模式没有调用通用原生任务服务，也没有外部真实键鼠输入，因此是生命周期/Bridge 浸泡预检，**不是**完整 8 小时业务负载或 Electron 性能比较。

独立监督器要求单一 PID、完整且有序的每轮步骤、空闲时长、逐轮资源样本、正常退出，以及最终原生单调用时不短于请求时长。缺一步、失败事件、进程异常、超时或提前退出均失败。超时仍保留[原生观察与可选抓栈](../preview5-timeout-diagnostics-2026-09-24/README.md)。即使操作通过，结果继续标记 `resourceGate: not-evaluated`、`longRunGate: not-evaluated`、`releaseReady: false`，长期趋势和完整业务须另判。

本次从隔离 Git 工作树冻结源码、SDK 构建、消费者源码、安装内容和运行载荷；源码指纹 `b8355092795ee5bb08f36dc4c677c6259f5eb857032fc5cd8d3fdd9859a6d392`。它与前一轮失败的 x86 Bridge 固定载荷不同；以下短测不能消除那两次失败。三个运行目录的请求、结果、事件、stdout/stderr（及启用时的阶段日志）从原运行目录复制后逐文件 SHA-256 相同。

| 运行 | 配置 | 操作结果 | 构建身份 |
|---|---|---|---|

x86/x64 运行载荷分别绑定各自的消费者 build-id 和 SHA-256，完整值见原始结果；x86 60 秒与 x86 20 秒虽是同源，也因独立编译而不混用二进制载荷身份。三组结果仅证明当前范围的短时混合操作及监督器核对可运行。8 小时持续运行、资源趋势、通用任务的进度/取消/队列上限、真实输入到呈现、目标系统和完整 Demo 场景仍待独立证据。

[x86 60 秒分时分析](x86-60s/analysis.json)已从结果绑定的原始事件重新核对散列和完整步骤，记录每类操作时长与逐轮资源；仅有 4 轮、未跨小时，不据此作资源趋势判断。分析器在 8 小时运行完成后复用同一格式，仍由人工审查长期趋势和业务覆盖。
