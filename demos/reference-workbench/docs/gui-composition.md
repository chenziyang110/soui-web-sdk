# Reference GUI composition, first slice

This implementation composes the existing shared Workbench controller and native business with ADR0054's optional SDK GUI command service. It changes application code only and uses the separately reviewed GUI SDK implementation. Frontend and native protocol checks have run; installed consumers and actual application workflows still require validation.

The same `reference.agent-task` element is actually rendered by `common/react-view.tsx` (Modern React19 and Compat React18) and `web-compat/src/view.vue` (Compat Vue3). It is a group with a read-only task-status display. Its explicit structured actions are `start`, `query`, and `cancel`; read-only display does not mean an implicit permission to perform them. Each action is exposed only by an exact registered native GUI family and the authenticated endpoint policy. There is no manual Agent button or page-owned Agent client. The public node lists its actions and bounded state; it contains no credential or raw draft. Ordinary manual task controls retain their existing per-page task ownership and enabled/busy states.

The first nine native rows cover four workflows:

| Workflow | Registered GUI families | Native effect |
| --- | --- | --- |
| Filter and inspect | `reference.gui.filter`, `reference.gui.status` | None; fixed projection of visible counts/state |
| Dialog | `reference.gui.dialog_open`, `reference.gui.dialog_close` | None; actual common controller action |
| Form | `reference.gui.form_set`, `reference.gui.form_submit` | Submit only: existing `reference.form.submit` |
| Summary task | `reference.gui.summary_start`, `reference.gui.summary_query`, `reference.gui.summary_cancel` | Existing `reference.summary.local.start/query/cancel` |

All rows are registered after `register_local_business` and before `create_local_endpoint`. A failed registration returns through configuration failure before the factory is called. The old two-argument Agent constructor remains the default/headless path, with no GUI rows or endpoint activation when disabled. The GUI overload can register the optional GUI composition while the listener stays disabled. Page grants explicitly include only `gui.bind`, `gui.effect`, and `gui.ack` in addition to existing page controls. GUI families and native local business capabilities never enter page grants.

The endpoint continues to authorize one actual held selected peer and one actual native scope. Its exact method/capability list includes the nine families' start/query/cancel plus the already registered typed effects. A GUI parent task keeps its original authenticated Agent scope; the page gets only one command-specific, one-use effect closure. The native SDK rechecks both scopes and the actual owner proof. A lost/rejected effect is not retried, and no raw token, session credential, exception text or arbitrary business object is projected.

The form GUI effect must use the same approved full input currently displayed in the shared form/category state. The manual branch still calls the generated typed `reference.form.submit` helper. Both principals reach that same domain handler. Summary tasks from both principals also reach the same `reference.summary` handler and the Bridge's only task service. The existing manual view retains one observed page task; the new display retains one observed Agent child. These are per-view ownership limits, not an additional global business concurrency rule or task store. They may run concurrently subject to the actual SDK capacity.

An Agent start response means actual child admission only. The display uses the local phases `admitting` and `admitted`, with no invented native progress or terminal. A new authenticated GUI query effect obtains the actual local-family child state and decimal-string sequence. Cancel records only actual request acknowledgement; a subsequent query supplies any terminal. Task IDs are never sent to the page `ReferenceTask`, subscribed through a page grant, persisted in preferences, or used by an automatic polling/replay loop. Agent operations use the separate visible group so manual buttons do not acquire another principal's hidden behavior.

Client initialization creates exactly one `bindGui(gui)` route. It awaits route readiness before reporting `bridge.probe.report`, checks document shutdown after the wait, and disposes the route during shutdown. Native owner binding uses actual Host ready/document state, exact captured session ID, own HWND owner thread/process, and the accepted Compat execution-context receipt or Modern session digest/status. The callback repeats that actual proof around `application_ready`; the native generation string is a correlation label rather than authority. The Agent endpoint starts with the same actual callback only after GUI native binding succeeds.

Navigation/reload revokes the old GUI route and native Agent scope. The application does not reopen or replay them: after owner polling observes closed GUI admission it closes normally. Preferences may survive, but a new explicit application activation is needed for a new native scope. Close first stops GUI admission and polls until actual owner callback/effect borrows are released; pending retains Host/Bridge/HWND. It then waits for actual endpoint stop, destroys the actual Host/window, destroys Bridge (real task-service join), and only then releases the application proof/Agent/business storage and shuts down Compat runtime. Worker-only GUI projections do not access Host/window. Closing GUI admission is not itself a worker-join receipt.

Thirteen new pure tests exercise the actual view/effect helper; all 51 reference frontend tests (38 existing and 13 new) passed with no skips. Both typechecks, action generation and its verification, three genuine Vite builds, two classic-entry conversions, three distribution audits and both fixed-lock dependency audits passed with natural process closure. This frontend-only run is separate from the native run.

The two native GUI registration tests use the real Bridge to check registration before/after factory freeze. Together with the unchanged 4 business and 8 Agent tests, all 14 cases passed by direct execution and serial CTest on both x64 and Win32 using freshly compiled normal SDK25. Configure/build root processes returned 0, but their compiler helpers required bounded cleanup and the supervisors returned 124. Those stages remain partial failures; the overall native run is not reported as fully passed.
