# ADR-0007：预览包改用已重编译的 Miniblink 内核

- 状态：proposed，第三方二进制替换及发布须维护者评审
- 日期：2026-09-23
- 范围：`0.3.0-preview.4` 的 x86/x64 固定运行依赖

## 背景

`0.3.0-preview.3` 固定的两个 `node.dll` 与当前补丁源码不一致。本地 HTTPS 对照已确认它们接受未受信证书及错误主机，因此不能以源码候选的正负向结果批准实际交付包联网。该固定包还不含已重编译的生命周期修补。源码候选的 x64 SHA-256 为 `0801aa929336168c851df4a3f245f5984a88bd01af585aea752404fa07774816`，x86 为 `3b9071413f704958fb5708b8bb065785a6c3ed03b7fd0fb04f5952201e5fe4f7`。

候选在两架构的回环 HTTPS 六项正负向测试、模板与 Workbench 的短启动/关闭、独立公共 SDK 消费者四模式各三轮中通过；具体证据在[内核验证归档](../../verification/production-validation/tls-kernel-2026-09-23/README.md)。这些结果不足以放行生产。

## 决定

1. 将两个明确散列的重编译 DLL 纳入下一预览包的固定 `third_party/prebuilt/<arch>/miniblink/node.dll`，并更新依赖清单、二进制授权审阅对象、版本与变更记录。x64 构建输出名称为 `miniblink.dll`，安装时只改交付文件名；复制后逐字节校验 SHA-256。
2. 任何构建、测试和源包均以新的固定 DLL 为同一版本输入。历史 `0.3.0-preview.3` 的结果保留原候选身份，不改写为新版本通过。
3. `releaseReady` 保持 false。TLS 正负向通过只证明已测试行为；系统信任根、代理、动态子资源、旧 TLS 组件维护、授权、GPU 资源与长稳仍是独立阻塞项。GPU 默认仍使用软件路径。
4. 新二进制通过草稿 PR 供维护者审阅；维护者批准、完整来源/链接组成与许可检查、发布验证完成前不创建正式发行版。

## 备选方案

- 保留旧固定 DLL，只在测试中指定新候选：正式包仍有已验证的网络身份校验缺陷，不采用。
- 只在宿主层禁用联网：受控页面和动态子资源仍可触发底层网络路径，也不能修复其他使用内核的消费者，不作为替代。
- 立即宣布生产可用：缺少长稳、平台、信任根与安全维护证据，不采用。

## 兼容、迁移与回退

公共 C++/TypeScript API 不变；网络请求现在拒绝未受信链或错误主机，既往依赖错误配置成功的页面必须修正服务器证书和信任配置。升级须以新版本号安装，不能把不同 DLL 继续标成 preview.3。回退应恢复完整旧版本包和项目锁；旧包的联网风险必须在回退决策中明示，不用旧 DLL 局部覆盖新包。

## 验证要求

两架构均检查实际固定 DLL 散列、源码清单与依赖清单；运行单元/原生契约、完整 SDK/模板/Demo Release 构建、三个实际入口 smoke、独立公共消费者四模式和仓库外项目编译运行。再分别执行固定 DLL 的 HTTPS 正负向测试、100 次资源趋势、每种支持模式 1,000 次、8 小时混合负载以及目标系统与升级/回退。任一未执行项在结论中保持未验收；短回归不能代替这些门槛。
