# 0104 — 分别验证依赖构建来源与交付源码

状态：采用；选择器与完整树匹配回归 10/10 通过，实际新内核配对待完整构建后验证。

## 背景

原依赖验证假设编译与 SDK 交付位于同一目录。隔离内核构建具有真实的独立来源目录，
即使交付文件完全相同，也不能改写原命令或来源记录使其看似在交付目录编译。

## 决定

保留 v1 选择器；v2 显式提供 kernel 和 SOUI 的 producerRoot。
首先在各自原始目录验证原公共入口、实际命令、工具输入、完整构建前后源码、库、DLL 和进程自然退出。
随后独立计算交付组件完整目录树，要求每个文件的原始字节与目录项身份均与构建来源一致。
不规范化行尾、不排除文件、不允许漂移，也不以 DLL 名称替代源码验证。
原目录与记录必须可读。v2 结果保留 producerRoot 和交付树匹配元数据。

## 兼容性、迁移与备选方案

SDK ABI、原始编译报告和已有 v1 记录不变。Test-Dependencies.ps1 增加可选
KernelProducerRoot 与 SouiProducerRoot，LLVM 路径在显式指定时构造 v2；省略时沿用 v1。
应用工具输入、六个 DLL 的实际载荷匹配和真实桌面验证全部保留。
不修改原始证明，也不为改变目录名字而重复编译同一份源码。

## 验证

实际回归包括 v1、v2 字段与路径拒绝、相同树搬移、修改/删除/增加文件、空目录变化和大文件流式散列。
新内核仍须以原来源记录通过实际 v2 配对，再完成应用编译和桌面启动。
本规则提供可追溯搬移，不豁免源码不变性或编译证据。
