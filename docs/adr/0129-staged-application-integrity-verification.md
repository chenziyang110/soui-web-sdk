# ADR-0129：已 staging 应用目录完整性校验

状态：开发工具，不提供真实性或运行认证。

## 决定

复用 `soui.desktop.application-stage/1` manifest，不改变既有 staging 格式，新增
只读 Node verifier。校验完整目录清单、大小/SHA-256、必要布局、二进制平台/
架构/最低系统与元数据一致性，可额外指定预期平台/架构。生成包和 SDK 安装
入口复用现有 staging 能力，不增加归档、安装器、签名或运行目标程序的步骤。

拒绝缺失/修改文件、未声明文件及多余目录、非法相对路径、大小写冲突、重复项、
symlink/特殊文件、不一致或越界 manifest。清单本身不列入自身摘要，不允许其
冒充签名验证；攻击者同时替换清单和文件仍可能通过。成功只代表此快照与声明
内部一致，不证明来源可信、系统依赖完整、GUI可运行或没有恶意内容。

校验只读取，失败不修复、不删除、不启动应用或 doctor；stdout 输出结构化结果，
不含绝对用户路径。限制清单大小、文件/目录数量、单文件和总读取量，分块哈希。
目录须可信且校验期间静止，有限一致性检查不消除恶意并发替换 TOCTOU。

## 集成与兼容性

保留 create-only staging。CMake 的现有 app_stage 目标在创建目录后校验；新增
独立 app_verify_stage 目标只校验现有目录，不依赖构建或重新 staging。生成
项目自动继承已安装 SDK 的入口，工具与依赖模块一起安装。不修改许可/版本。

## 验证

少量损坏/缺失/额外/非法输入重点检查，加一次真实 Linux 已 staging 目录和安装
工具检查；完整矩阵、平台执行权限差异、签名/发布和目标运行继续留待统一验收。
