# ADR-0160：默认关闭的原生渲染阶段成本诊断

状态：诊断实现、双架构 CPU/冷 ABI、增量内核及消费者编译通过；一轮私有桌面成本采集完成。默认 SDK 不采用该诊断载荷，物理性能及新 GPU/相位策略未认证。

## 背景

当前帧策略候选保留已有分数计时、绝对截止、双槽租约与 GDI 完成屏障。已有 scalar 记录没有逐事件时间戳；大 `task_queue` 桶还包含合法的计划等待。原 Canvas 记录不能据此判断晚唤醒、raster、同步复制或原生提交是否主导成本。不能凭缺少数据直接更换相位源或默认启用 GPU。

现有 trace v1 的 stage、duration 和事件布局是已交付契约。将新含义塞入旧桶，或把窗口观察、SwapBuffers 返回解释为物理呈现，会破坏原读者与事实边界。

## 决定

增加独立、私有、进程内且默认关闭的有界直方图诊断，不修改 trace v1 enum、struct、provider 函数表或必需导出。仅用于回答当前默认 CPU 路径是否值得进一步研究相位或 transfer 优化，不替代完整逐帧因果链。

- 使用既有 trace 的冷配置、固定 32 个 producer 槽、线程注册和 stop/quiescent 生命周期。禁止热路径注册、分配、锁、磁盘或 Bridge 调用。
- 在开关、录制状态和当前线程注册均有效后才读取新增 QPC；关闭或不录制时只检查状态，不额外读时钟。指标及每指标 64 桶均固定，溢出和坏时钟显式失效。
- QPC 范围只记录 raster、spare buffer copy、UI mirror copy 和原生提交调用的 inclusive wall duration。嵌套、抢占及调用内等待仍包含在内，不称线程 CPU，不相加计算成本占比，也不相减分位数构造阶段。
- 唤醒迟到使用 producer 当处的原 WTF monotonic due 与实际 dispatch 时间，在同一时域内计算微秒；提前、无有效 due、非有限值或溢出分别处理。不得把 owner 服务预算截止当作 timer due，不与 raw QPC、DOM 时钟相减。
- stop 后不再接纳新 scope；已经开始的 scope 可完成记账，槽和模块仍须存活。最终静止快照才提供精确累计值；运行中读数保留捕获括号、busy/fault，不伪装原子快照。

冷开关及只读有界快照沿精确私有 `wkeSetDebugConfig` / `wkeGetDebugConfig` key 接入。该分支独立于 WebView，不触碰已关闭 view 或 WTF 对象；默认分支继续原 owner 检查。配置必须在任何 producer 注册前固定，重复或迟到配置不能清空已采证据。控制数据不来自网页，JSON 只含固定指标、非敏感身份、状态和数值。

消费者仅增加显式诊断入口及独立结果，不改变普通 SDK 默认值、工作量、画质或页面调度。生产者接线先作为诊断 overlay 保存：私有 helper、原始七 TU 身份、可审补丁及生成规则由 benchmark 所有，在仓库外的新副本编译独立诊断内核；不修改默认 vendor 物理树，不替换已验证的 SDK2 库、K1 或安装前缀。诊断消费者显式选择该独立载荷，其来源、开关和结果另行绑定，不能把新诊断挂到旧 DLL，也不能将诊断 DLL 冒充默认交付。最终交付包在源码稳定后才冻结；条件成立后的实际优化与默认采用另行记录。

## 备选方案

扩写公开 trace ABI 会增加当前不需要的迁移与跨版本范围；复用旧桶会改变旧含义，均不采用。新增 clock、GPU runtime、相位锁定、线程或无界逐帧日志也不属于本次诊断。只打开 detailed 能补已有事件，却仍没有缺少的 copy/raster/wake producer，不能回答当前成本问题。

完整 due/post/fire、frame/scene/span 关联和同一帧的重复等待次数仍是独立缺口；聚合直方图不能证明它们。若这轮发现相应主要成本，再按原方案设计后续关联与优化。

## 兼容与回退

消费者先核对显式诊断构建及实际 DLL 身份，不匹配或旧 DLL 记录 unsupported，不解释为零，也不在旧 DLL 冷态探测未知 debug key。旧配置与 trace 输出原样，关闭开关即可回退；本次不改线程、优先级、调度、同步、租约或 GDI 屏障，也不改变 GPU 失效后的完整 CPU 重绘规则。供应源码使用现有编译语言能力，不提高 Windows、编译器或 SDK 最低要求。

## 验证

先以有代表性的 CPU 合同验证关闭时零新增时钟读取、边界分桶、溢出、线程/槽绑定、重复配置、stop 与在途完成、静止/忙快照及坏 due。再按原增量链接来源分别重编两架构受影响 TU，保留原其他对象身份与链接命令，验证 v1 布局不变。

运行前冻结当前默认 CPU Canvas 负载、源码与实际 DLL/SDK/页面身份、诊断开关和期限。执行一轮有界诊断并自然关闭；先检查生产者注册、累计守恒和故障，再解释各自直方图。工作量与时间窗不一致、缺槽、溢出或坏时钟保留失败。该结果不认证物理输入延迟、scanout、完整 GPU 成本或 Electron 对齐。

## 已执行范围

2026-11-03，固定 bank 的 14 组合同及实际 hooks 的普通 6 组、独立缺映射 1 组合同，均已用 LLVM22/MSVC142/19041 在 x64/x86 自然执行通过。独立审查发现的普通未注册线程误报已先修正；未注册线程现在不读新增时钟，原 trace 已注册而私有映射缺失仍明确故障。

首轮内核构建中两个 x64 编译器自然成功，随后严格 include 守卫发现旧 40TU 清单未覆盖 InputFrameTrace 原有的三个 STL 头，整轮失败保留。新的有限 MSVC142 include roster 逐文件冻结，原重叠文件必须同散列；实际 include 仍逐文件核对。仅复用原轮完整通过守卫的 WebThread 对象，另外 13 次 fresh compile 与两次 link 实际自然成功、Job 排空，无强清，约 25.55 秒完成。完整 vendor 默认物理树、K1 双架构 DLL、SDK2 库和 Git index 未改；这是独立增量诊断内核，不是 fresh whole-kernel、v143、应用运行或性能资格。

随后双架构各一份真实冷探针验证 v1 函数表、producer 注册/释放/stop/quiescent、最终快照及迟到配置拒绝；另各一进程证明旧 K1 在加载前因 SHA 不符被拒绝。探针不初始化 WKE、COM 或窗口，零 render 样本只表示未运行渲染。首次探针缺少标准头、首次消费者配置漏传旧 profile 的失败均保留；最小修正后的两个诊断消费者各编译一个 TU，生产工具显式部署 K2，各 270 文件闭集核对通过，默认库及安装前缀不改。

一轮 x64、默认预算 0、请求 60Hz 的原 Canvas240 负载，在任务私有非输入桌面完成约 10 秒预热、完整 30 秒记录、Begin/End 和页面报告落盘及应用自行关闭。Host/controller/broker 自然退出，Job 清空，无强清、系统输入或窗口消息，343 份冻结文件前后相同。SDK/kernel/private 绑定同一 run、PID/incarnation 与 10MHz QPC；六个 producer 的最终七指标守恒、无故障。原生 Begin/End 捕获点相距 30.0025378 秒，但私有成本覆盖配置后约 41.3466 秒，包含启动、预热和关闭，不能按 30 秒 CPU 份额解释。

本轮 raster 的 P95/P99 桶为 0.8192–1.6383ms，context-submit P95 同桶、P99 为 1.6384–3.2767ms；shared-wake-lateness P95 为 1.024–2.047ms、P99 为 2.048–4.095ms。少量更长尾部仍保留，不能凭聚合数据归因某帧、启动或具体等待。spare/mirror/layered 三项没有样本，成本为 unknown。原页面完成 1,799 模拟步和 1,800 绘制，rAF 回调 60Hz 仅与请求配置相符，不认证实际呈现。该有限结果不足以证明新 GPU 或显示相位源有收益，本次继续保留默认策略及原屏障；其他负载、透明/DC/readback、逐帧重复等待与物理性能仍未知。
