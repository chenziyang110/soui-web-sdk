# 原生位图提交完成边界：限定验证

2026-10-31。修复前 BitmapPlatformDevice::DrawToNativeContext 在缓存 DC 情况下没有显式完成发起线程 GDI 批次便返回；调用者可能随后释放像素租约，直接 raster 的 accessPixels 不保证触发 onAccessBitmap 的延迟刷新。本次在变换恢复后、EndPlatformPaint 和 DC 释放前刷新，绘制失败也执行刷新及清理，设备返回值组合绘制与刷新结果。上层 void wrapper 仍忽略该返回值。

设计、权衡、回退见 [ADR-0149](../adr/0149-complete-native-bitmap-submission.md)。这是提交完成契约的局部修复；基线也有该路径，历史 CRC 根因未被证实，不标记为已复现并修复的 CRC 回归。

## 源码契约回归

`tests/native/native_submission_completion/run.py` 提取真实生产方法编译，未复制方法逻辑。x64/x86分别执行相同测试源码与32种组合共272项检查：旧方法各152项失败、原生退出1；修复方法各0失败、退出0；x86两个测试EXE均核对PE machine为0x014c。覆盖不透明/Alpha、缓存/新DC、默认/显式区域、绘制失败、刷新失败、无条件刷新、清理顺序与返回后的像素复用。延迟GDI队列是确定性模型，不证明真实驱动曾延迟某次BitBlt或造成旧CRC。

## 隔离桌面短测

旧候选与新内核使用相同Starter和外部DOM/计算/Bridge页面，默认共享预算0；预热1秒、工作4秒。旧/新分别完成218/217批次、同数量C++往返，错误0、校验值均843029256；两个进程正常退出0，自有Job关闭，静态二进制前后不变。加载路径绑定各自node.dll，最终真实窗口PNG可读。

这是短程功能与绘制冒烟，不是同逻辑总量的正式性能对照。批次数和原始间隔记录不授予性能改善、P95/P99输入延迟或物理显示结论。

原VM使用权已转交其他任务，领取被拒，未换盘、抢用或操作该VM。故新内核尚未执行VM真实SendInput/DXGI CRC复测；隔离桌面不替代它。x86实际启动、透明layered路径、长稳、完整公开构建、最终整包尺寸与发布资格本轮未验证。
